## 2. 包职责及允许依赖

| 位置 | 允许依赖 | 职责 | 禁止内容 |
| --- | --- | --- | --- |
| kernel | 审查过的纯计算库 | 基础 ID/值/时间/错误 | 框架、业务服务、网络、Node/DOM |
| contracts | kernel | 注册登录、AI、同步批次/回执/快照、错误和版本 | 计划/训练/复盘处理器、页面模型、业务仓储 |
| client-business-core/domain | kernel、本域及其他域公开纯类型 | 业务模型、不变量和状态转换 | 云端模块、具体数据库、HTTP 和组件 |
| client-business-core/application | 本地域、公开端口、本地命令 Schema | 单用例、跨域事务、业务来源核验 | 原始表操作、界面状态及服务器请求对象 |
| client-business-core/queries | 公开查询仓储 | 本地业务查询/统计、workspace 组合 | 第二套事实或 UI 布局规则 |
| data-schema | kernel、受控 Schema 工具 | 本地结构、行类型、复制范围及迁移登记 | 业务用例、连接和界面 |
| local-runtime | client-business-core、kernel、contracts、data-schema 的公开入口 | 本地命令执行、数据批次、基线/投影、客户端冲突和升级 | 云端业务执行、Taro/Expo/Node API |
| storage-* | 客户端仓储/事务端口、data-schema、local-runtime/ports | 本地物理存储、映射、索引和恢复 | 规则副本、apps 或云端依赖 |
| client-model | 客户端公开业务类型、kernel、必要协议类型 | reducer、输入格式、命令转换和 ViewModel | SQL、HTTP、JSX及领域规则副本 |
| cloud | contracts、kernel、data-schema/replication、Node/服务框架 | 账号、AI、同步存储及必需设施 | client-business-core、local-runtime、client-model、任何本地业务仓储 |
| mobile/miniapp | 客户端共享包、所属平台框架及端口 | 页面、功能交互、平台装配 | cloud 内部实现、绕过核心写业务数据 |
| testing | 公开类型/端口及测试驱动 | 合成场景和客户端持久化等价契约 | 生产包反向依赖 testing |

`data-schema/replication` 只导出逻辑表/字段、主键、精度及载荷版本等结构信息，不能经间接依赖导入业务核心。服务器用它检查输入形状和所有者，不执行引用图的业务核验、指标重算、确认资格或规则批准。

CI 同时检查直接/传递依赖和云端构建产物。云端不能通过 testing、client-model、data-schema 的 barrel 绕过限制。业务包 exports 按领域开放，禁止根 index 将全仓导出。存储实现依赖端口，本地运行时不反向依赖具体存储包。

`storage-indexeddb` 按 connections/transactions/repositories/queries/upgrades 拆分。SQLCipher 和 Keychain 的真实平台接入由 mobile/platform 提供，本地仓储包不导入 Expo。云端自己的账号/同步表定义及 MySQL migrations 留在 cloud 内，不生成客户端领域仓储。

packages/contracts 存受控运行时 Schema 和派生类型，根 contracts 存生成 OpenAPI/已发布样本。不得在两处手写同一协议。备份容器及本地命令 Schema 分别属于 local-runtime/backup 与 client-business-core/local-commands，服务器不需要解释或执行它们。

本地映射使用 `TableName` 和 `TableRowMap[K]` 关联强类型，拼错字段应编译失败；导入数据仍需运行时校验。生成文件注明来源，CI 临时生成比较。数据结构变更同步更新本地迁移、载荷兼容和导入测试；业务规则改变而传输不变时，不要求给云端增加业务实现。

本地业务行、操作意图、待同步批次和可见投影在一个可靠提交边界内更新。云端则把收到的载荷、回执和账户 headVersion 原子保存；这两种事务分别服务于本地业务正确性和远端数据保存，不共享领域 UnitOfWork。

业务命令执行只发生在 local-command-bus；上传内容是数据变化，不让 sync-engine 承担业务规则。冲突处理在客户端拿到最新数据后重新调用本地用例，并生成新的同步批次；云端只比较账户版本。

本地 commandId 与网络 batchId 分开，原意图和原分支可恢复。不能使用动态方法反射重放，必须按本地命令版本显式注册。同步引擎只做阶段协调，上传/拉取/对账/重试/冲突各自拆分；平台前后台、网络和文件交互通过应用适配器注入。

服务端没有 business、planning、execution、review、nutrition、业务 backups 或 privacy 编排模块，没有 compose-business、业务 command-executor，也不注册客户端领域命令。Node.js 在此仅作为轻量账号/AI/同步服务运行技术，不表示迁移 Java 业务到 Node。

同步流程：认证 → 传输校验 → 同 batchId 幂等 → 账户 expectedHeadVersion 比较 → 载荷/回执/headVersion 原子存储。MySQL 只保存这些容器，不查询客户端业务聚合、不调用本地规则、不做领域合并。批次包含表名也不能拼接为任意 SQL。

AI 流程：接收客户端冻结输入 → 检查会话/授权/格式/额度 → 调用供应商 → 返回结构化结果及输入摘要。候选是否接纳、是否过期、是否发布/确认均在客户端。注册只创建账号和会话相关数据，不初始化任何计划/事实表。

快照下载、增量读取与同步存储维护属于 sync 内部能力；AI 临时图片只服务调用。首期不扩展独立对象业务、营养来源、自动复盘、业务定时备份或整套隐私工作流。账号访问控制、日志脱敏和基础恢复作为必要设施保留，不借此增加领域用例。

## 7. 客户端共同分层及整页拆分要求

两个客户端都遵守以下分工，UI 组件按平台分别实现：

| 层 | 做什么 | 不做什么 |
| --- | --- | --- |
| 路由入口 | 解析路由参数、进入 Screen | 查询、表单、业务判断、数据库连接 |
| Screen/Page | 页面布局、区块组合、页面级导航/可见性协调 | 全部业务动作、复杂表单、直接发请求或写库 |
| 页面区块 | 显示一个区域，接收数据与回调 | 创建业务事务、操作同步引擎 |
| Feature 交互 | 单一用户动作，例如记录训练、确认结论 | 包揽整个页面、跨域临时业务规则 |
| Hook | 订阅一个查询、封装一个表单或一个交互生命周期 | 集中整页所有状态、巨型 effect、业务计算副本 |
| Model | 纯 reducer、ViewModel、格式校验、命令转换 | 平台 API、SQL、HTTP、业务批准规则 |
| Gateway | 调用本地 CommandBus/QueryBus，或身份/AI 远端端口 | 直接绕开共享用例写业务数据 |
| Platform | 文件、SQLite、网络、密钥、生命周期适配 | 页面业务规则与确认逻辑 |

普通业务入口默认进入本地 Gateway；注册登录、AI 请求等云端动作有显式 OnlineGateway。页面不能根据网络错误自动切换数据源或回退 mock。依赖由 app/bootstrap 注入，功能模块不 import 平台具体实现。

## 8. 文件规模与职责的强制检查

行数按实际非空非注释代码行统计，不计生成文件；行数是上限，职责混杂即使未超限也不允许。禁止把多条语句挤到一行规避检查。

| 文件类别 | 强制上限 | 内容限制 |
| --- | --- | --- |
| App、路由入口、main | 80 行 | 仅启动/Providers/导航，不包含业务页面主体 |
| Screen/Page 装配 | 200 行 | 布局、区块和小范围页面状态，不含表单全实现或规则 |
| 功能 Hook | 150 行 | 一个查询/表单/提交生命周期；不能包揽全页 |
| 展示组件、字段、区块 | 200 行 | 一个视觉或交互职责，复杂列表项单独拆分 |
| 单用例、纯策略、查询处理器 | 200 行 | 一个主要行为，跨域编排与纯规则分开 |
| 其他手写生产文件 | 350 行；超过 250 行报告提醒 | 仍需单一职责，禁止万能 service/utils/runtime |
| 单个函数 | 80 行 | 大 JSX 也按函数处理，拆成有名称的区块 |
| 测试文件 | 500 行 | 按场景拆分；大 fixture 单独文件，不能将整套验收写成一例 |

字段定义、常量清单和类型文件按领域/协议拆分；生成内容、纯 Schema 快照及大合成 fixture 可在明确路径免行数检查，但仍检查格式、来源及生成一致性，不能给手写页面加 generated 注释逃避约束。

CI 的 `check:ui` 至少检查：路由/屏幕禁止导入数据库、存储、fetch 和云端 SDK；Screen 不能 import 业务域内部；Hook 的大小与禁止依赖；函数/文件规模；每个页面的实际模块清单。静态检查不能证明所有职责正确，代码审查继续核对是否把全页逻辑搬入一个巨型依赖文件。

`docs/engineering/page-map.md` 为每页记录路由、Screen、区块、交互 Feature、查询/命令 Gateway、共享用例和关键测试。今日页需显式列出训练、学习、睡眠、饮食与复盘的不同入口；该映射存在性由脚本核对。新增页面提交同时更新映射，不能仅新增一个大 index 文件。

确有例外时先拆分或调整设计；无法拆分的第三方适配/生成场景在 ADR 和检查白名单中记录精确路径、原因及退出条件，不给整个目录关闭检查。页面逻辑集中不作为可豁免项。

## 9. 命名、状态与错误约定

- 页面/组件使用 PascalCase，Hook 使用 `use-xxx.ts`，纯规则/用例使用表达动作的 kebab-case；命令名明确稳定，不能把 JS 函数名当持久协议。
- `index.ts` 仅作为受控导出入口，不放实现；`public.ts` 只导出本领域允许外部访问的能力，不使用 `export *` 暴露内部实现。
- 类型避免 `any`、双重断言及大量非空断言；边界使用 unknown + Schema 校验，明确 null/未知/未配置状态。
- 输入中的数值先保留可编辑文本，提交前做格式转换；精确业务值由共享 Decimal/Quantity 表示，领域不依赖界面本地化文本。
- 表单、持久业务、同步、AI 状态分别建模。保存按钮的忙碌状态不复用 AI 运行标记；同步失败不将已保存表单恢复成未保存。
- errors 定义稳定错误码和结构，界面按功能映射可操作提示；日志保留 requestId/commandId，不记录密码、会话、照片正文和完整健康资料。
- mock 只在显式开发/测试入口装配；生产构建和真实入口禁用，运行失败不自动切换 mock。

## 10. 测试分工与脚本契约

生产代码单元测试可就近放 `*.test.ts(x)`；测试适配器与跨存储契约放 testing，跨工程闭环放根 tests。不得把“目录存在”作为架构测试的全部内容。

| 测试位置 | 内容 | 负责人角色 |
| --- | --- | --- |
| client-business-core 各域测试 | 纯规则、状态转换、历史基准、确认、未知值 | 领域实现者 |
| testing/storage-contracts | 同一本地用例跨内存/真实 SQLite/日志/IndexedDB 的语义 | 存储适配实现者 |
| local-runtime 测试 | 本地意图、批次队列、回执、冲突、崩溃和客户端版本重放 | 本地运行时实现者 |
| cloud 集成测试 | 注册登录、跨账号隔离、批次幂等/版本/存储事务、AI 调用 | 云端模块实现者 |
| client-model 测试 | reducer、命令转换、字段错误与显示语义 | 功能实现者 |
| apps 界面测试 | 弹层、输入、保存失败、确认范围及导航 | 对应客户端实现者 |
| tests/architecture | 包/域边界、循环、生产依赖及页面规则 | 工程维护者 |
| tests/compatibility、migration | 旧库、旧队列/备份、Java 基线、切换与回退 | 迁移实现者 |
| tests/e2e、acceptance | UC/AC 闭环、真机、真实微信环境及部署 | 验收执行者 |

以上是工作职责，不表示必须多人或多智能体执行。一个实现者也要按职责提供不同层次证据。

新工程必须实现下列根级命令；当前文档不表示这些命令已经存在：

| 命令 | 作用 |
| --- | --- |
| `pnpm install --frozen-lockfile` | 按锁文件安装 |
| `pnpm typecheck` / `pnpm lint` | 严格类型和语法/风格 |
| `pnpm check:deps` | exports、领域依赖、循环和平台隔离 |
| `pnpm check:ui` | 页面职责导入、映射、文件/函数上限 |
| `pnpm check:generated` | 结构、行类型、Schema/OpenAPI 输出一致 |
| `pnpm test:unit` / `pnpm test:integration` | 规则与真实数据库/HTTP/存储契约 |
| `pnpm test:compatibility` / `pnpm test:migration` | 版本、队列、备份、切换与恢复 |
| `pnpm build:cloud` / `pnpm build:miniapp` / `pnpm build:h5` | 各独立部署目标 |
| `pnpm build:mobile-bundle` / `pnpm build:ios` | Hermes 与 Xcode 原生产物分别记录 |
| `pnpm verify` | 规定的本机可执行检查汇总，不隐藏真机/外部未覆盖层 |

数据库测试启动独立实例并验证目标库标识；无数据库不能悄悄跳过后仍让完整集成任务显示通过。iOS 原生构建在 Mac runner 执行，签名密钥仅在受限环境提供。浏览器构建成功不替代小程序/原生构建；类型检查也不替代持久化及离线验收。

## 11. 模块交付清单与文档同步

每个本地业务功能交付至少包含：对应 UC/BR/AC、客户端共享命令/查询、规则、本地仓储映射、两端交互、错误状态、版本影响和必要测试。注册登录、AI 代理与同步存储另外按自身接口/状态测试，不要求为它们建立客户端领域用例。可以分阶段提交，但没有完成的目标端和能力必须明确列出，不能因接口存在宣称完成。

每个页面 PR 必须列出：Screen、区块、Feature、Hook/Model、Gateway、共享用例及交互验证。每个协议/结构 PR 必须列出：旧客户端、旧队列、旧备份影响，生成差异、升级/失败恢复场景和灰度回退条件。

文档同步顺序为：需求/领域依据 → ADR/契约 → 结构及版本矩阵 → 实现和测试 → 页面/模块地图 → 验证记录。架构决定同步到 AGENTS、CI 与检查脚本；只写“注意拆分”而没有可执行约束不算完成工程初始化。

新工程初始化时将本规范的不可违反项写入根 `AGENTS.md`：禁止整页集中、禁止云端加载客户端业务核心或重复实现领域逻辑、禁止生产 mock 回退、禁止静默删队列/删库、禁止跨包内部引用、禁止跳过真实数据库冒充回归、禁止未经迁移核对切换业务库。已有项目保留当前工程规范作为基线，不能用目标目录冒充已经落地的工程状态。
