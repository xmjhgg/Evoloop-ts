## 1. 物理约定与仓储边界

下表公共列 **C** 在每张表真实展开，不是父表隐式继承：user_id UUID NOT NULL、created_at DATETIME(6) NOT NULL。UUID 表示 CHAR(36) CHARACTER SET ascii COLLATE ascii_bin；HASH 表示 CHAR(64) ascii_bin；所有代码、键、摘要用 ASCII 二进制比较，人工正文用 utf8mb4。UTC 时间点用 DATETIME(6)，上海归属日/周一用 DATE；DECIMAL 的单位明确，未知值 NULL，不能补 0。

键记法 U(a,b) 表示 UNIQUE(user_id,a,b)，F(a,b→parent.x,y) 表示 FOREIGN KEY(user_id,a,b) REFERENCES parent(user_id,x,y)。所有内部父表提供相应同用户唯一键；删除采用 RESTRICT 和显式清理。跨域事实、目标、任务、身份请求仅存公开 ID/修订与来源快照，不建跨域 FK 或 JPA 导航。

DailyConclusionRepository / GoalWeeklyReviewRepository 分别加载一个文档根及当前 manifest；组件按权限/所选范围加载，不在学习操作中 JOIN 健康正文。AdjustmentSuggestionRepository 只管理建议及提交记录。SourceQuery 查询来源引用和范围版本，不改事实；DataHandlingRepository 管理本域固定导出与恢复账本。rev_document 是两个根的共享物理头，不形成一个全用户/全周大聚合。

本域使用公共 sys_command_receipt、sys_event_consumption 与单一持久事件登记，不另建 outbox 或授权表。公共幂等键 requestId 为 VARCHAR(128)，不能假定客户端幂等键是 UUID。所有数字/时间默认由服务端显式提供；只有表中特别标注的默认值生效。

## 9. 事务、写入/删除顺序与实施验证

| 操作 | 同短事务内容与顺序 |
| --- | --- |
| 日/周建立、输入采集 | BEGIN→identity栅栏→公共幂等/消费去重→来源公开API/适用规则共享锁→日或周根→source/组件/manifest→生成关联→ai受理→tokens/事件→COMMIT |
| AI业务接纳 | 栅栏→去重→重核全部来源/人工及必要规则→本域根→新组件/manifest或建议修订→ai.recordAcceptance→本域tokens/事件，失败一起回滚 |
| 人工补充/判断 | 栅栏→幂等→必要来源/规则→文档根→人工修订/新组件→清所选确认头→token/事件；未涉及健康只复用元数据引用 |
| 范围确认 | 必须ActorContext；栅栏→幂等→全部所选来源/覆盖最终核验→文档根→confirmation/link/head→token/事件；不调用计划发布 |
