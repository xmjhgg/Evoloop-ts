## 1. HTTP 输入、输出与错误

前缀 `/api/v1/review`。写操作带 Idempotency-Key，修改根带 expectedVersion；后台上下文不能执行人工确认。日期为上海 DATE、weekStartDate 必须周一、cutoffAt 为不晚于当前时间的 UTC ISO 8601。实际发生截至与采集保存时间分开。对他人或不可访问对象统一 404；日期/单位/组件类型错误为 422。当前准确最新性查询也开启短事务并锁用户栅栏；查询不创建日/周对象，不自动确认。

| 方法 / 路径 | 输入 | 输出 / 核心失败 |
| --- | --- | --- |
| GET `/daily/{businessDate}` | goalIds?、includeOverview、mode=CURRENT/HISTORICAL、revisionId? | 200 DailyConclusionView；无根为 NOT_GENERATED、conclusionId=null 和 DAILY token=0；受限段 REDACTED_SCOPE |

## 2. ReviewApi 公开查询 DTO

| 方法 | 输入 | 不可变输出 / 事务属性 |
| --- | --- | --- |
| getDailyConclusion | AccessContext、businessDate、DailyQuery{goalIds?,includeOverview,mode,revisionId?,freshnessMode} | DailyConclusionView{conclusionId?,version?,revisionId?,businessDate,segments,overviews,confirmationSummary,restrictedScopes,sourceTokens} |
| getWeeklyReview | AccessContext、goalId、weekStartDate、WeeklyQuery{mode,revisionId?,freshnessMode} | WeeklyReviewView{reviewId?,version?,revisionId?,goalRevisionRef,weekStartDate,components,dayStates[7],coverage,cutoffAt,confirmations,sourceTokens} |
| getSourceTokens | AccessContext、ReviewScopeQuery{dailyDates[],goalWeeks[],manualDocumentIds[]} | TokenSnapshot{readAt,tokens[]}，每个请求范围都有项，不存在返回逻辑0 |

AccessContext 仅由服务器 ActorContext/限定 ProcessingContext 构造。freshnessMode=AUTHORITATIVE 开启或加入已持用户栅栏的 READ COMMITTED 短事务，逐组件核验真实来源；CURRENT 查询默认此模式。仅允许列表的 CACHED 提示 `freshness=NOT_VERIFIED`，不能用于“最新已确认”、输入、确认或调整。HISTORICAL 返回明确原修订、当时确认与当前可用性，不宣称其为最新。

ComponentView 包含 `slotKey,componentId,goalId?,purposeScope,origin,cutoffAt,coverage,metrics,statements,manualContributions,sourceFingerprint,sourceRefs,scopeTokens,contentStatus,sourceFreshness,confirmation`。返回的 sourceRefs/token 按资格删节；删节后 `completeSourceSet=false`，不能用作 adjustment basis。人工内容来自已绑定 entryNo；不把最新未纳入人工说明混进旧历史组件。

dayStates 固定周一至周日，包含 `businessDate,conclusionId?,revisionId?,componentId?,status=CONFIRMED/UNCONFIRMED/NEEDS_UPDATE/NOT_GENERATED/NOT_APPLICABLE/REDACTED_SCOPE,confirmationId?,coverage,cutoffAt?`；未来标 FUTURE_EXCLUDED，暂停按规划范围 NOT_APPLICABLE。缺日结论也读取当天底层事实。周确认仅记录周范围，日状态不改变。

review 范围类型为 `DAILY(scopeKey=YYYY-MM-DD)`、`GOAL_WEEK(scopeKey=goalId:YYYY-MM-DD)`、`MANUAL(scopeKey=documentId)`。token 是本人范围版本；不包含正文；资格仍按用途/范围核验，不允许拿版本读取被限健康数据。

## 3. AdjustmentBasisVerifier 实现契约

实现接口：`planning.api.AdjustmentBasisVerifier.verify(actor,basisRefs,cutoff,affectedScope) → BasisVerification{latest,invalidReasons,verifiedSourceSet,verifiedConfirmations}`。输入/输出沿用 planning 的 [03](../planning/03_命令查询与领域事件.md)，不另创不兼容契约。实现类位于 review.application，bootstrap 将其注入 planning；只读来源，业务写锁之前收集，加入调用方事务，不使用 REQUIRES_NEW。

调用方必须已 BEGIN → identity.lockProcessingFence；verify 校验 FencePermit/同本人事务后：

1. 验证结论类型、本人/日或目标周身份和 affectedScope 的 goal/date。basisRef.revisionId 必须为当前组合修订；不存在、删节或受限来源返回 invalidReasons，不从历史拼造依据。
2. 根据 affectedScope.goalId 选择当前目标组件；confirmationId/version 必须为该 slot 最新确认头、本人明确人工确认，确认 scope 覆盖目标和所用判断/截至。确认绑定 componentId 必须等于当前 manifest 中组件；原组合修订可不同但组件必须一致。
3. 比较提交完整来源集合与存储确认集合，防客户端遗漏 refs/tokens；核验人工 entryNo 仍当前、coverage/cutoff/组件 sourceFingerprint 未变化。cutoff 必须是该依据确认的截至，不允许客户端扩大到未确认时段。
4. 通过 planning.getSourceTokens/getBaselines、execution.getFacts/getSourceTokens、profile.getSourceTokens/getBodyFacts 读取原本所用范围；学习依据仅读学习条件/事实，未引用身体范围时不能调用健康事实查询。已有 refs 被删、修订变更或任何 scope token 不同均拒绝，包括先前空范围新增事实、缺失日新增结论、原/新日变更。
5. 周依据额外核验所引用七日日状态和对应 review DAILY tokens，底层事实与日确认状态均比较；不强求七日都已确认。确认中明确未确认/未生成范围仍可为有限判断，但来源变化必须重核。
6. 输出规范 verifiedSourceSet 和逐确认 `{confirmationId,confirmationVersion,componentIds,goalIds,cutoffAt,coverageDigest}`，供 planning 存 basis。任何差异 latest=false，不调用 mergeAdjustment/publication，不更改源域，不递归评估需再次 verify 的用例。

当前 scope 尚未建立为0；未来新增使0→1即可拒绝，不能只检查已有对象。facts 读取仅核验所用 refs/范围和保存语义，不重新写 facts。planning 的最终未来范围/限制/冲突审查由调用方负责；全局健身规则选择行共享锁由需要规则评估的调用者在 review 写锁之前按共同顺序取得。

## 4. 日周核心 API 工作流程

### 4.1 事实成功后日生成与业务接纳

```mermaid
sequenceDiagram
    actor U as 本人
    participant E as execution/profile
    participant R as review
    participant I as identity
    participant S as planning/execution/profile
    participant A as ai
    U->>E: 保存真实反馈
    E-->>U: 事实已保存
    E-->>R: 事实变更事件
    R->>R: BEGIN
    R->>I: lockProcessingFence
    R->>R: 消费去重/命令幂等
    R->>S: 选定范围事实、原基准、覆盖、refs/tokens
    R->>R: 建唯一日根/选定组件摘要，保存生成输入来源
    R->>I: 预分配taskId后签AI_CANDIDATE_PROCESSING
    R->>A: createTask(ownerModule=review, DAILY_CONCLUSION)
    R->>R: 生成请求/公共回执/事件，COMMIT
    A->>A: 事务外执行模型
    A-->>R: AiTaskCompleted(taskId)
    R->>R: 新BEGIN
    R->>I: lockProcessingFence(原双版本与scope)
    R->>R: 回调去重
    R->>S: 重读完整refs/tokens、必要规则
    R->>A: READ_OWN_CANDIDATE(只读，不持任务写锁)
    R->>R: 锁日根，校验根/人工/来源/schema/风险，写新组件与manifest
    R->>A: recordAcceptance(ACCEPTED或拒绝)
    R->>R: 单事务保存业务结果和接纳回执，COMMIT
    U->>R: getDailyConclusion
    R-->>U: 今日/复盘同ID与当前组件；仍待人工确认
```

AI 输入只包括所选权限范围；自动事件在资格允许时发起持久生成，没有授权则保存受限事实摘要/待生成提示，允许人工判断。外部模型调用无数据库锁。接纳阶段顺序为栅栏→去重/幂等→源/必要规则锁→review根→ai写锁→事件；ai 候选读取不先持任务写锁再回头锁根。AiTaskApi.recordAcceptance 与组件写入共享调用方短事务，单独提前 ACCEPTED 禁止。

task kind 精确为 DAILY_CONCLUSION/GOAL_WEEKLY_REVIEW/ADJUSTMENT_SUGGESTION，ownerModule=review。原任务保存 authorizationVersion/deletionEpoch、选定范围和输入 schema；worker/租约续期不能更新旧 epoch。上下文失效时只能按 identity 维护权限终结/清理任务，不能复活旧输入。AI失败/旧结果拒绝保留事实和人工内容，重试创建最新快照的新业务请求。

```mermaid
    R-->>U: 仅周判断确认，每日状态保持
```

三天记录/周中起步/未确认日均可形成有限周结论，coverage/dayStates 必须可见。日 AI 推测保留其 kind 和状态，不升级为周事实。日确认改变，即使底层事实未变，也使所依赖周 token 失配；周确认不补造日确认。

### 4.4 最新已确认依据 → 同周草案 → 独立发布

```mermaid
sequenceDiagram
    actor U as 本人
    participant R as review
    participant I as identity
    participant P as planning
    participant V as review实现的Verifier
    U->>R: 建议原值/新值/理由/未来日期
    R->>I: BEGIN后栅栏、幂等
    R->>V: 核验当前组合/组件确认/底层refs和tokens
    R->>P: 读取当前安排/保护、必要健身限制
    R->>R: 锁建议根，保存候选，COMMIT
    U->>R: 明确选中patch及归属周提交
    R->>I: 新BEGIN后栅栏、公共幂等
    R->>P: mergeAdjustment(basisRefs,old/new/reason/date)
    P->>V: 只读verify，不回调合并
    P->>P: 锁目标/周/项目，三方合并，逐项冲突，保留其他安排
    P-->>R: 唯一weekPlanId/draftRevisionId/conflicts
    R->>R: 最后锁建议根登记提交引用，COMMIT
    R-->>U: 草案已保存 published=false
```

submission 不先持 review 写锁再进入 planning 写锁；建议与 planning 合并加入同一事务，最外层维护一份公共幂等回执，不创建嵌套第二份。跨周按 affectedDate 的上海周一分组，单次提交一组；周日“明日”即2026-10-12周一，进入 weekStartDate=2026-10-12 的既有工作草案。若周一睡眠在周日已开始，planning 拒绝该时段，用户重新明确选择剩余范围，不静默扩大或修改。

## 5. 事件、消费及计划失效通知

共同信封含 eventId/eventType/schemaVersion/occurredAt/ownerModule/userId/aggregateId/aggregateVersion/requestId/affectedScopes/payload；schemaVersion=1。只传最小必要 ID/版本/范围和状态，不传完整健康/人工正文或图片。业务变更与单一持久事件登记同事务；不建 review outbox。消费变化与 sys_event_consumption `(consumer,eventId)` 去重同事务，乱序不能回退已见版本。

| 发出事件 | 时点 / 最小 payload | 消费者与效果 |
| --- | --- | --- |
| DailyConclusionUpdated | 选定组件/人工或摘要更新；conclusionId/revisionId/componentIds/changedSlots/DAILY token | review 周依赖投影；workspace刷新；不算事实新增 |
| DailyConclusionConfirmed | 范围确认；conclusionId/confirmationId/version/slotKeys/componentIds/token | review 周状态依赖；workspace显示范围确认 |
| WeeklyReviewUpdated | 周组件/人工变化；reviewId/goalId/weekStartDate/revisionId/token | workspace；review 建议投影 |
| WeeklyReviewConfirmed | 周确认；reviewId/confirmationId/version/goalId/weekStartDate/token | workspace；不修改每日确认 |
| ConclusionSourceChanged | 来源实际失配或所选组件替换；documentId/changedSlots/affectedGoalWeeks/reasonCodes/tokens | review 自身异步调用 planning.markAdjustmentBasisChanged；workspace显示需更新 |
| AdjustmentSuggestionChanged | 保存/拒绝/提交/失效；suggestionId/version/status/affectedScopes/planDraftRef? | workspace；不被当计划发布 |

| 订阅事件 | 行为 |
| --- | --- |
| ExecutionFactChanged/Corrected/Removed、FoodIntakeConfirmed | 按 affectedScopes 精确找源依赖；标需更新，资格允许才发新生成；一事实事件重叠按 eventId+来源当前版本去重，不重复累计 |
| BodyObservationChanged/ProfileConditionsChanged | 标用到相应来源的健身/条件判断；不让无关健康正文进入学习 |
| GoalChanged/PlanConfirmed/PlanItemLocked | 重核适用计划/目标范围；历史基准仍按原引用，PlanDraftChanged仅影响用到该草案的建议输入，不改执行基准 |
| DailyConclusionUpdated/Confirmed、ConclusionSourceChanged | 更新依赖周与建议提示；仅有真失配才写，防自身事件循环 |
| AiTaskCompleted/Failed/Cancelled | 核验ownerModule/taskKind/taskId、来源、双版本；接纳或保存安全失败元数据 |
| AuthorizationChanged/AccountStatusChanged/DataRequestCreated | 拒绝旧生成/接纳，处理本域数据请求；不自行维护当前授权副本 |

review 收到源变更先在短栅栏事务记录自己投影与必要 ConclusionSourceChanged 并提交。其后独立 handler 消费自身失效事件，在**新 BEGIN → 用户栅栏 → 公共消费去重 → planning 锁**调用 `markAdjustmentBasisChanged(trustedReviewContext,basisRefs,affectedScope,eventId)`，不持 review 写锁。planning 不能 typed 订阅本域/执行事件；通知只使未发布候选需复核，已发布计划不自动变化。即使通知失败、乱序、事件未消费，最终 verifier 仍读当前来源拒绝。

## 6. 重试和数据请求

返回未知时先查当前根、taskId 或公共请求回执，再用相同 Idempotency-Key 重试。相同键不同摘要409；瞬态数据库失败有限同键重试；真实版本/来源冲突刷新后由用户重新决定。异步受理回放返回原 taskId；当前权限/epoch 先核验，不无条件重放敏感旧响应。

导出/删除/注销使用 identity 创建的 DATA_REQUEST_WORKER/STAGE_REPORTER。各批 BEGIN→栅栏→范围核验→本域清单/正文处理→进度提交；对象存储/外部请求在事务外。正式阶段名、ArtifactDescriptor 和真实回执遵 identity 03；详细清理与固定导出清单见 [04](04_仓储与数据映射.md)。健康用途撤回不阻止本人已受理的数据权利操作，旧普通 AI 任务不因此获新权限。
