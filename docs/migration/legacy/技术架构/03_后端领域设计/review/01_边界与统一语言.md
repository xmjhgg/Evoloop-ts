## 1. 职责与一致性边界

review 回答“实际与执行时目标有什么差异、用户认可了哪些判断、这些判断能支持哪些未来变化”。拥有 DailyConclusion、GoalWeeklyReview 及其不可变内容、人工判断、覆盖/截至、确认和调整建议。日结论自然键为 `(userId,businessDate)`；周复盘自然键为 `(userId,goalId,weekStartDate)`。类别筛选、今日卡片和复盘详情都不能改变身份。

| 能力 | 本域拥有 | 协作边界 |
| --- | --- | --- |
| 日结论 | 目标分段、分用途日总览、来源、截至、缺失、人工补充、范围确认 | planning 提供适用基准；execution/profile 提供唯一事实 |
| 目标周复盘 | 大目标/周计划对照、逐日结论状态、底层事实分析、周反馈和周确认 | 不复制七个日结论；不将日推测当事实；不代确认每日 |
| 未来调整 | 最新已确认依据、候选原值/新值/理由/影响日、必要性和限制提示 | planning 拥有唯一周工作草案、逐项冲突、审查和发布 |
| 来源有效性 | 所用 refs、范围 tokens、人工版本和确认范围核验；待更新投影 | 数据所有者维护自己的版本；事件延迟仍须拒绝过期来源 |
| 人工闭环 | 保存人工说明、明确来源的人工判断、独立确认 | 手工学习不要求健康字段或 AI 授权；备注不修改实际 |
| 数据请求 | 本域正文/历史/人工/来源快照/建议及导出片段的处理 | identity 统一范围、阶段、授权、账户和正式回执 |

不拥有身体测量、日级身体状态、训练感受事实、食物分析草案、摄入份量换算、AI 任务租约或健康发布策略。也不维护总健康分、学习掌握率或第二份健身报告。页面组合由 workspace 通过公开 API 完成，不允许其直接 JOIN 本域内部表。

## 2. 统一语言

| 术语 | 明确含义 | 区分 |
| --- | --- | --- |
| 归属日 businessDate | Asia/Shanghai 的业务 DATE，睡眠按实际起床日 | UTC 保存时间、前夜睡眠开始日 |
| 归属周 weekStartDate | 按业务 DATE 推导的周一，周一至周日 | 从入口文字“本周/下周”推导对象 |
| 组合修订 ConclusionRevision | 一个结论在某时刻采用的不可变组件清单 | 根 version 是并发版本，不等于 revisionNo |
| 目标分段 GoalSegment | 对指定 goalId 的计划/实际、差异及判断组件 | 不是另一个计划或日结论根 |
| 日总览 DailyOverview | 对个人日事实去重后的维度摘要；健康与学习用途组件分开 | 把多个目标的同一餐/睡眠重复累加 |
| 覆盖 Coverage | 已到时段、有效计划项、登记/缺失/部分/休息/暂停/未发生范围 | 未登记不等于未执行；未来不在分母 |
| 截止 cutoffAt | 当前判断实际观察截至的 UTC 时间点 | generatedAt、confirmedAt、后来补记的 savedAt |
| 来源 SourceReferenceSet | 已有对象 refs + 可检测新增/删除的 scopeTokens | 单纯已有 ID 清单、仅靠事件失效标记 |
| 人工补充 ManualContribution | 用户原因、感受、限制、纠正判断或下周偏好，独立不可变修订 | 改实际数量须去事实所有者，不用备注覆盖统计 |
| 人工结论 MANUAL | 用户基于明确来源/截至/覆盖填写的最终判断 | 伪装 AI 生成、将推测升级为事实 |
| 判断类别 | FACT_SUMMARY、ESTIMATE、UNKNOWN、HYPOTHESIS、USER_JUDGMENT、ADVICE | 确认推测不把推测变真实事实 |
| 范围确认 ConfirmationScope | 明确认可哪些组件、goalId、日期/维度、覆盖及缺失 | “今日全完成”或计划发布 |
| 最新已确认 | 对应组件仍是当前组合采用版本、人工与底层来源仍最新、所需范围有当前确认 | 历史确认记录存在、状态缓存显示 CONFIRMED |
| 调整依据 basisRef | 当前结论修订、对应确认、cutoff、底层完整 refs/tokens | 没确认的 AI 初稿、过期人工理由 |
| 调整建议 AdjustmentSuggestion | typed 白名单字段差异和理由的候选集合 | planning 工作草案；建议接纳与草案发布不同 |
| 基准日期不匹配 | 纠正移日后事实仍保留原保护基准，baselineDateMismatch=true | 用原日目标虚构新日达标率 |

## 3. 来源所有权与 ACL

| 上游公开能力 | 本域如何使用 | 保留的来源 |
| --- | --- | --- |
| PlanningApi.getBaselines/getSourceTokens | 当前日待执行对照及事实历史执行基准；目标状态和范围 | goalRevisionId、itemRevisionId、publicationId、GOAL_SET/GOAL_STATE/PLAN_DAY/PLAN_GOAL_WEEK tokens |
| ExecutionApi.getFacts/getCoverage/getSourceTokens | factId 去重、仅有效已保存事实、已确认摄入小计、未知/覆盖 | factId/revisionId、actual occurrence、原基准、事实日/维度范围 tokens |
| ProfileApi.getBodyFacts/getConditions/getSourceTokens | 健身观测/长期限制及必要条件，学习只读取学习条件 | BODY_DAY、CONDITIONS 对应范围和不可变 refs |
| IdentityApi | 本人、场景用途、授权版本、deletionEpoch、栅栏、任务资格、数据请求 | 不另存一套当前授权；快照保存发起双版本 |
| AiTaskApi | 持久生成候选；本域再做结构/规则/来源接纳 | taskId、输入 schema、模型/提示来源引用、接纳回执 |

ACL 在 infrastructure/integration 把公开 DTO 转为本域 SourceFact/Baseline/Coverage 值对象；domain 不依赖外域实体。公开 api 只返回不可变 ID/修订/单位/状态快照。允许编译依赖 `identity::api, profile::api, planning::api, execution::api, ai::api, shared`。

`AdjustmentBasisVerifier` 接口在 planning.api，review 实现、bootstrap 装配。review 消费来源事件或自身 ConclusionSourceChanged 后，在**新的短事务**先锁用户栅栏，再调用 planning.markAdjustmentBasisChanged；不持 review 写锁，不让 planning typed 订阅 review/execution 事件，不出现合并/发布递归。

## 4. 用途、范围和跨模块可用性

人工学习为 ACCOUNT_ACCESS；学习 AI 增加 AI_PROCESSING；健身正文/事实摘要增加 HEALTH_DATA。本域分析不需要食物图片正文，仅使用 execution 已确认摄入及来源标识，因此不默认请求 FOOD_IMAGE。任何场景只发送本次所选范围的最小输入。

同一日根可同时含健康与学习。其目标分段和健康/学习总览保存为不可变组件，组合修订通过引用复用未涉及组件。学习生成/补充只读取学习组件与学习上游；不会加载、复制或 AI 重写健康组件。无健康权限时查询返回同一 conclusionId/currentRevisionId、允许的学习组件及 restrictedScopes，不返回健康正文、来源明细、覆盖数值或敏感原因。不能将限权总览声称为完整全日总览。

确认可选目标分段和授权可读的总览组件。仅学习确认不表示所有目标已确认；调整确认必须覆盖要调整的 goalId。未涉及组件更新后，原范围确认仅在当前组合仍引用同一组件且其底层来源最新时继续有效，其他范围不受该确认扩张。根编辑 expectedVersion 仍检测所有并发变化。
