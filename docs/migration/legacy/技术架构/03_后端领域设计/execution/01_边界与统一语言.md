## 1. 职责与范围

本域回答“实际发生了什么、由本人保存或确认的是哪一版”。拥有训练反馈和单次训练感受、学习执行及文字成果、睡眠实际区间、已确认个人摄入、事实修订和误记删除；拥有食物图片的受控业务关联、分析输入和草案、个人份量确认、营养来源适配及单位换算。真实事实成功即成立，后续结论更新或 AI 失败不回滚。

| 能力 / 数据 | 本域责任 | 协作边界 |
| --- | --- | --- |
| 训练 / 学习反馈 | 保存状态、实际量、感受/成果、片段；原计划量不预填成实际 | planning 拥有动作处方与任务；review 解释计划实际差异 |
| 睡眠 | 保存真实入睡/起床，按起床日；多目标引用一次事实 | 常规作息、日级疲劳/精神/不适属于 profile，不能从其习惯生成事实 |
| 身体测量 / 日状态 | 不创建或复制 | 由 workspace 调用 profile API；单次训练不适仍是本域事实 |
| 食物草案 / 图片 | 选择、上传关联、版本、同餐多图合并核对、来源未知 | ai 只执行 FOOD_ANALYSIS 图片理解；不确认实际食用 |
| 摄入 | 个人实际部分确认、kcal/g 换算、未删已确认小计 | planning 拥有饮食目标计算、总量、餐次分配、发布和保护 |
| 限制证据 | 提供最小训练不适引用及范围版本，通知证据变化 | planning 判 ALLOWED/WARN/BLOCKED；限制不拒绝如实记录已发生事实 |
| 日周结论 | 发事实变更事件、供事实与覆盖 | review 唯一维护日结论、周复盘、确认和调整依据 |
| 账户 / 授权 / 清理请求 | 每次遵守本人资格、用途、epoch；清理本域全部持有内容并回执 | identity 定义用途/处理上下文/阶段；不复制账户或授权模型 |

额外训练、自主学习和无饮食目标的摄入可保存；没有基准返回 `baselineRefs=[]`，不反向建立目标。不提供统一健康分、学习掌握率、课程接入、自动评卷或极端补偿规则。

## 2. 统一语言

| 术语 / 类型 | 定义 | 容易混淆的边界 |
| --- | --- | --- |
| ExecutionFact / 事实身份 | 单次训练、一个学习任务反馈、一个睡眠区间或一笔个人摄入的稳定 factId | 页面、目标和图片不是事实身份 |
| FactRevision / 事实修订 | 本人保存的不可变完整内容，含 revisionId/revisionNo、归属与保存时间 | 可变根 version 是并发控制；修订号不是 expectedVersion |
| BusinessDate / 归属日 | Asia/Shanghai 的实际日；睡眠是 endAt 起床日 | UTC 时间点保留；周按周一至周日 |
| AppliedPlanBaseline / 执行基准 | planning 在保存时保护的不可变 protectionId、目标/项目修订与处方引用 | 纠正不换成当前计划；无计划是显式自主 |
| ExecutionStatus / 反馈状态 | COMPLETED、PARTIAL、NOT_PERFORMED；睡眠另有 IN_PROGRESS | UNREGISTERED 是没有有效反馈的查询状态，不能自动新建未执行事实 |
| ActualAction / 实际动作 | 用户自填的动作、逐组量/负重 | 计划7组不等于实际7组；动作明细可缺失 |
| LearningFragment / 学习片段 | 同一反馈内一次真实投入及成果的稳定片段身份 | 同任务多次学习汇总不重复，同一片段修改不是追加一遍 |
| FoodAnalysisDraft / 食物草案 | 图片或手工输入、识别候选、来源、未知、核对状态 | 草案和 AI 成功不计摄入、不使日结论确认失效 |
| FoodLine / 食物明细 | 合并同餐图片后的一项食物候选或已确认个人食物 | 多图支持同一 line，不能每张图新增同份菜 |
| PersonalPortion / 个人份量 | 克、份数、可核对比例或明确未知；含测量/估算依据 | 共享整盘、剩余和未吃部分不能默认全部入账 |
| NutritionValue / 营养值 | ENERGY、PROTEIN、FAT、CARBOHYDRATE 的点值/范围/未知及来源 | 来源数据库值、标签、AI 估算、人工输入分别表达 |
| ConfirmIntake / 摄入确认 | 本人确认最新明细代表实际已经食用 | 不能由 worker、AI 或计划审查代确认 |
| Coverage / 覆盖 | 按维度返回应登记、已登记、部分/未执行/缺失及截止 | 未知不是0，未来/休息/暂停不加入普通分母；无计划无达标率 |
| SourceReferenceSet | 已有 refs + 用户/日/维度 scopeTokens | 新事实或删除也可使来源失效，不只比较已有 ID |

## 3. 用途与公开协作

纯学习人工记录仅 `ACCOUNT_ACCESS`；训练/睡眠/摄入另需 `HEALTH_DATA`。保存/读取用户选定图片加 `FOOD_IMAGE`，图片 AI 再加 `AI_PROCESSING`；手工饮食不要求图片或 AI 同意。用途枚举、authorizationVersion、deletionEpoch 和 ProcessingContext 直接采用 identity 公共契约，不自建同义枚举。普通事实由 ActorContext 保存；后台只能接纳草案候选或处理获分配数据请求，不能作本人确认。

所有短写 `BEGIN → identity.lockProcessingFence → 公共幂等 → planning（如适用）→ execution 根/修订 → ai 接纳回执（如适用）→ 持久事件 → COMMIT`。公开 API 与 HTTP 分开；`FitnessEvidenceReader` 接口属于 planning.api，execution 实现、bootstrap 装配；实现只读，不能回调 planning。

## 4. 营养来源与图片端口

| 本域端口 | 输入 | 输出 / 限制 |
| --- | --- | --- |
| NutritionSourcePort.lookup | 规范食物关键词/标签标识、地区语言、需要的营养项、服务器受限处理资格 | 候选条目、供应商条目标识/版本、单位、每100g/每份基准、缺失、依据获取时间；不猜测不存在值 |
| PortionConversionPolicy.convert | 原值/单位、参考基准、参考份量、个人实际量及来源 | 统一 kcal/g 的点值或范围、conversionVersion、原始依据、未知原因；纯本地规则 |
| FoodImageStoragePort | 本人 uploadIntentId、允许 MIME/大小策略、摘要、受控键 | 存储元数据及可用性；网络操作在事务外，只登记用户选定图片 |
| FoodCandidateNormalizer | ai 的 food-analysis 输出 schema、全部选定图片上下文 | 食物候选、证据图集合、待合并/需补充项；输出不代表个人吃过 |

营养供应商返回经防腐层转换后进入本域候选；数据库来源不能以 AI 数值冒充。包装标签 `kJ ÷ 4.184 = kcal`，每100g按已核对克数/100缩放；每份只有参考份数/重量可核对才缩放，质量与体积之间没有密度依据不能猜转换。宏量仍以 g；不从热量反推未知宏量。该单位恒等式不是个人健康目标公式。供应商、图片数量/大小/格式配置、误差评价、保留期限在 TBD-002/003 评审后落配置；未配置能力返回明确不可用/信息不足。
