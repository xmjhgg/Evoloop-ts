## 1. 独立设计分工与共同责任

| 领域 | 独立子智能体 | 本域重点 | 主设计联审责任 |
| --- | --- | --- | --- |
| identity | identity_design | 登录会话、用途授权、处理上下文、数据请求及阶段回执 | 六方调用资格、后台子操作权限、七方清理闭包 |
| profile | profile_design | 分区条件、身体观测、日状态及修订 | 学习/健康读取隔离、条件变化及身体事实来源 |
| planning | planning_design | 分类目标、周日处方、审查、发布、保护和限制 | 事实原子保护、适用基准、部分发布、依据倒置端口 |
| execution | execution_design | 真实训练/学习/睡眠/个人摄入、食物候选及营养换算 | 多目标事实去重、未完睡眠、移日保护、摄入确认 |
| review | review_design | 共享日结论、目标周复盘、人工判断、范围确认和调整依据 | 单一日身份、组件最新性、确认与未来调整分开 |
| ai | ai_design | 持久任务、固定输入、租约尝试、候选结果和接纳回执 | 任务类型/所有者、调用与接纳分开、撤回和恢复 |

每个领域由独立子智能体编写本域文档，主设计维护公开协作协议并处理冲突；不新增重复领域所有者。设计入口见 [README](README.md)，共同协议见 [协作契约](01_领域协作契约与设计约定.md)。

三个收尾子智能体遇到服务额度限制：ai 的01～05已落盘，execution 的01～04及review的01～03已落盘。主设计接续完成execution的05、review的04/05，并对全部文件统一联审。六个领域的独立设计任务均已分别启动，不将额度中断或未返回最终消息当作文档验收通过。
