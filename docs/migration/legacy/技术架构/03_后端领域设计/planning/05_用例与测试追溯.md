## 3. 规则与并发验证

额外回环断言：已确认日/周依据→同周未来草案合并→审查→发布；草案编辑和需复核投影只变技术版本，不改变已发布适用 PLAN_DAY/PLAN_GOAL_WEEK，结论来源不绑定可变 WeekPlan.version，避免合并自身使依据失效。真实发布/事实保护/目标状态变化仍正确改变来源范围。

| BR | 所属设计 | 额外断言 |
| --- | --- | --- |
| BR-COM-001/002/018 | 本人/用途/删除栅栏（01/03/04） | 换userId无权；撤回/删除不接纳旧AI；维护context不能恢复正文 |
| BR-COM-003/004 | 版本/公共幂等（03/04） | 同键异输入409；响应丢失查回执；AI失败保留旧计划；重复事件不重复写 |
| BR-COM-005/006/007/008 | 目标/周/日与条件引用（01/02/04） | 真MySQL唯一周、跨用户复合FK、current pointer、局部读回 |
| BR-COM-009、BR-FIT-002/015 | 最新审查（02/03） | 每个动作字段改变失效；阻断不可KEEP；RULES覆盖不足不READY |
| BR-COM-010、BR-FIT-003/010 | 基准/日期（02/03） | 无时段今日effectiveNotBefore；周日晚开始周一睡眠次周但保护；不补过去分母 |
| BR-COM-014/017、BR-FIT-011 | 来源/合并/独立发布（02/03） | refs不变但新增事实/计划scope变仍拒绝；结论确认不发布 |
| BR-COM-015 | 共享/重叠（02/04） | 主/引用/排除明确；事实去重；不发布矛盾适用基准；另一目标不暗改 |
| BR-COM-016、BR-FIT-012 | 暂停恢复（02/03） | 保护历史保持；PENDING_REPLAN；归档非删除 |
| BR-FIT-001/008/013/014 | 健身/总量槽（02/04） | 无目标摄入也建槽；之后不能今日加总量；未开始餐次守总量；BLOCKED仍保存真实反馈 |
| BR-LRN-001/002/003 | 学习专属（01/02） | 分钟/页/题各自含义，无数值可文字；不推掌握率、不强制健康 |

1. **事实/发布竞争**：事实先提交→发布ITEM_PROTECTED；发布先提交→旧候选BASELINE_STALE。注入事实写失败须同时回滚保护、总量槽、scope和事件，不能留下“记录失败但锁计划”。
2. **来源事件延迟**：新增观测/不适/人工判断/目标/计划后暂停消费者，旧review发布和basis合并仍按当前范围拒绝；已有refs相同不得通过。
3. **规则切换竞争**：发布FOR SHARE持到提交，切换只独占选择行等待、不申请用户栅栏；切换先提交则旧token失效。旧策略内容不得原地改。
4. **渠道**：拒绝AI的学习草案RULES覆盖充分可发布；健身缺方法/参数/覆盖INFORMATION_REQUIRED；AI失败不自动降级，显式重审新review。RULES不得抹除已识别禁止项。
5. **调整冲突**：原45、当前40、候选30→CONFLICT_PENDING；KEEP/USE/CUSTOM逐项选择；未涉及项保持。合并后源变→发布verify拒绝。独立手工规划不要求结论。
6. **共享摄入**：自主摄入refs=[]仍建槽，另目标当天后加总量也拒绝；主基准成员同修订，摄入正文一次。未开始餐次调整守旧总量和已保护餐次。
7. **删除恢复**：清理历史/计算/来源/保护后，旧AI、重试和幂等正文不得重建；deletionEpoch优先于scope清空逻辑0；回执准确显示未完成外部阶段。
8. **架构**：planning仅依赖identity/profile/ai::api/shared；两个倒置端口属于planning.api，实现无planning递归；外域公开通知需新短事务，不能源域持写锁回调。
