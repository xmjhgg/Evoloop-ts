## 1. 仓储和物理约定

GoalRepository、WeekPlanRepository、PlanReviewRepository 是纯 Java 聚合仓储；基础设施映射至以下 `pln_` 表。历史、列表、基准批量查询采用本域专用投影，不加载完整历史聚合，不访问别域表。

以下每张表**逐表包含公共列 C**；C 是字段定义缩写而不是继承表或省略字段：`user_id CHAR(36) NOT NULL`（本人所有者，无跨域FK）、`created_at DATETIME(6) NOT NULL`（UTC，应用赋值，无隐式服务器时间默认）。所有 UUID 列 `CHAR(36) CHARACTER SET ascii COLLATE ascii_bin`；下表 `CHAR(36)` 均采用该定义。表内未特别注明的字段无默认值；NULL 表示未知/不适用，不能自动0。根的 `version BIGINT NOT NULL DEFAULT 1`；不可变序号 BIGINT 从1递增。关系表也有 C，确保用户可过滤/清理。

所有主键和唯一键注明字段；为简洁 `U(x...)` 表示 `UNIQUE(user_id,x...)`，`F(a...→表.b...)` 表示显式复合FK **`(user_id,a...) REFERENCES 表(user_id,b...)`**。每个被引用键均有对应 U；不以含NULL唯一键保证当前身份。各表 C + 下列字段构成完整物理列清单。索引也隐含以 user_id 为首列，注明全局索引除外。所有同域FK RESTRICT，不用级联删除绕过业务；隐私删除按依赖反序小批次处理。

## 9. 事务、版本和删除落点

所有短写遵循账户栅栏 → sys_command_receipt → 必需的全局规则选择共享锁（rule_scope排序）→ Goal → WeekPlan/稳定项目（ID排序）→ 本域审查/保护/共享槽 → 事件登记。跨域事实事务由 execution 开启，planning protectBaseline MANDATORY；整个事实保存结束前不释放栅栏/项目锁。对同用户多个目标/日期按稳定ID顺序；无槽时账户栅栏保护首次建立。规则切换只拿选择行独占锁，不再拿账户栅栏。长网络调用全部在事务外。

创建循环当前指针时：根以NULL插入 → 子修订/manifest插入 → 同事务更新指针；提交前断言非空，不需要延迟FK。修订号由已锁根分配，当前指针不依赖MAX查询；同请求幂等不会再分配序号。UPDATE根用version条件，受影响行不为1则409。字段CHECK只做行内格式，不代替跨行日分配、未来保护、本人父子和source最新性。

导出覆盖上述每表用户行及计算/规则/来源快照。普通误记由事实所有者新删除修订处理，本域历史保护不自动解锁；隐私删除则清所有适用正文、历史、参数快照、来源、候选、保护和选择，先断开根当前指针，再依FK反序删除。外域事实ID不构成阻止删除的FK。删除scopeTokens也须通过deletionEpoch让旧输入失效，不能将清理后逻辑0当旧授权可恢复。公共幂等/事件消费表由基础设施按请求范围一起清理，不在planning重复建outbox。

索引为设计候选，后续必须用真实MySQL迁移、查询计划、锁竞争与数据量验证；本文未宣称DDL已实施或性能/事务已验收。
