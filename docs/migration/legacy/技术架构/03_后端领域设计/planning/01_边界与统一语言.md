## 1. 职责与业务范围

本域回答“目标是什么、准备做什么、哪个计划修订在该时点适用”。拥有分类目标及状态历史、同目标同周工作草案、每日稳定项目与动作明细、学习内容、饮食目标及餐次分配、睡眠安排、发布前审查、发布组合、执行保护与健身适用性规则。保存目标不要求已有周计划；保存草案、处理审查意见、确认计划是不同命令。

Goal、WeekPlan、PlanReview 分别为聚合。目标按健身/学习分类，健身使用增肌/减脂方向；学习不要求身体、营养或睡眠字段。健身与学习都使用同一草案、审查、未来发布和状态协议，不能另建学习专用确认闭环。

| 本域拥有 | 原始事实/判断所有者 | 协作方式 |
| --- | --- | --- |
| 目标体重等期望衡量值 | 实际体重为 profile | 期望值保存于 Goal；观测只保留引用 |
| 每日训练处方与动作列表 | 真实训练/单次感受为 execution | 提供历史基准，锁定与保存事实同事务 |
| 每日营养总目标、餐次分配及计算策略 | 摄入、图片、营养来源换算为 execution | 保护总量与已开始餐次；不接入营养数据库 |
| 睡眠目标 | 真实睡眠为 execution | 以起床日定位，使用跨日开始时间保护 |
| 学习任务、预期成果 | 实际学习文字成果为 execution | 不由计划填充真实成果 |
| 调整候选合并、冲突选择与草案修订 | 已确认判断和调整理由为 review | 通过 AdjustmentBasisVerifier 核验来源 |
| 健身发布/调整限制 | 长期条件和日级身体事实为 profile，训练不适为 execution | 当前公开证据 + 版本化规则；不依赖 AI 成功 |

workspace 只能组合本域公开查询；AI 只返回候选内容。目标归档保留历史，隐私删除按 identity 的请求清理历史、引用和派生产物。

## 2. 统一语言

| 术语 / 类型 | 精确定义 |
| --- | --- |
| Goal / GoalRevision | 稳定目标身份与不可变内容修订。描述、周期、衡量、专属设置形成新修订；状态变更留历史。执行引用当时修订。 |
| GoalStatus | ACTIVE、PAUSED、PENDING_REPLAN、ARCHIVED。ACTIVE 可暂时没有计划；恢复先进入 PENDING_REPLAN。 |
| WeekPlan | 用户、目标、周一归属周唯一的稳定根；当前草案指针和最新发布指针各自独立。 |
| DraftRevision | 周草案不可变完整快照：周重点、目标依据、逐项修订清单、调整来源。编辑形成新修订并切当前指针。 |
| PlanItem / ItemRevision | itemId 是目标/日期/项目的稳定身份；itemRevisionId 是不可变完整内容。动作编辑保留 itemId。复制到别日/别周新建 itemId。 |
| ItemKind | TRAINING、REST、LEARNING、NUTRITION_TOTAL、MEAL、SLEEP。类型切换在未开始项目的新修订完成，稳定项目不换日期。 |
| PublishedPointer | 每个稳定项目唯一 currentPublishedRevisionId；不可用“周版本最大”推定某日的适用内容。 |
| Publication | 一次明确确认及所选范围，保存变化清单和确认后的完整周组合；可能只变一项而非整周替换。 |
| PlanReview | 对一个确切 DraftRevision 和 sourceRefs/scopeTokens 的发布前检查，不是执行后的 review 日/周结论。 |
| ReviewIssue | BLOCKING、INFORMATION_REQUIRED、ADVISORY；前两类须解决。保留普通建议可记录用户理由。改内容后所有旧意见处理失去发布资格。 |
| SourceReferenceSet | 已有对象修订 refs + 范围版本 scopeTokens；前者用于追溯，后者发现新增计划/事实/目标状态变化。 |
| PlanBaselineSnapshot | execution 保存的不可变对照，含执行时目标、稳定项目和修订、归属日、数量单位和发布引用。 |
| BaselineProtection | 首次开始/实际使修订受保护。允许纠正真实事实，不能解锁来美化过去目标；删除误记也不自动解锁。 |
| DailyIntakeGuard | 用户/日的总量保护槽：首次确认摄入后当日既有总量冻结；原来无目标仍保持无目标，不事后补造。 |
| AdjustmentBasis | 最新已确认日/周判断、确认版本、截止和底层来源集合。是草案依据，不是发布许可。 |
| AdjustmentPatch | 稳定项目、字段、原值、新值、理由和影响日期；冲突逐项选择，未涉及内容保持。 |
| FitnessRestrictionAssessment | 对目标/项目/日期的 ALLOWED/WARN/BLOCKED 当前评估及规则、证据版本；用于引导、发布和调整，不拒绝已发生事实。 |

## 3. 协作与依赖边界

编译依赖只允许 `identity::api`、`profile::api`、`ai::api`、shared。planning 在自己的 `api` 定义 `AdjustmentBasisVerifier` 和 `FitnessEvidenceReader`；前者由 review 实现，后者由 execution 实现，bootstrap 装配。两个回调仅只读源域公开快照，不再次调用 planning 的发布/合并/限制评估，避免递归；planning 不导入 review/execution 实现。

| 端口 | 输入 / 输出最小约定 | 调用时点 |
| --- | --- | --- |
| IdentityApi | ActorContext、用途、范围、授权版本；global authorizationVersion/deletionEpoch | 所有短写先 lockProcessingFence；读取本人资格；AI 入/出及接纳再次检查 |
| ProfileApi | 类别、时间/身体日期；条件修订、长期限制、最小身体证据、范围 tokens | 生成、审查、限制评估、最终发布 |
| FitnessEvidenceReader.readEvidence | actor、goalId、dateRange、cutoff、kinds；最小训练不适证据、refs/tokens | 健身限制最终评估，读取当前已提交事实；无证据不伪造零风险 |
| AdjustmentBasisVerifier | actor、basisRefs、cutoff、affectedScope；latest/invalidReasons、verifiedSourceSet | 调整合并、AI接纳、审查和最终发布 |
| AiTaskApi | PLANNING_GENERATE / PLANNING_REVIEW、输入快照、schema/rule/source版本 | 短事务创建任务；外部调用不占用事务；候选由 planning 接纳 |
| PlanningApi | getBaselines、protectBaseline、evaluateFitnessRestrictions、mergeAdjustment、getSourceTokens | 公开返回不可变快照，完整契约见 03 |

手工学习需要 ACCOUNT_ACCESS；学习 AI 再加 AI_PROCESSING；健身业务追加 HEALTH_DATA。FOOD_IMAGE 属于 execution 图片处理，不用于普通计划。拒绝 AI 后可显式选择 RULES 渠道：由版本化确定性策略完成当前适用审查，覆盖充分才可发布；不是用户自行宣告通过。AI 渠道失败不能自动降级，显式切换 RULES 必须对最新输入重审。此处为详细设计建议，需求尚未正式冻结；健康计算参数仍待批准。

## 4. 时间、范围与事实原则

UTC `DATETIME(6)` 存时间点，API 使用带 Z 时间；归属日/周按 Asia/Shanghai、周一计算。睡眠 D 日目标是 D−1 夜至 D 晨，周日开始的周一睡眠归下周 WeekPlan。发布检查真实已开始状态以及计划时段已经到达的历史边界；不能仅因 businessDate=明日将已开始睡眠认作未来。

同人饮食/睡眠事实正文只存一次。多个目标同时关联时，冲突必须选择主比较基准和各目标引用关系；不能将一份事实复制累计，也不能静默发布互相矛盾的个人日总量/睡眠基准。没有计划仍可登记事实，基准列表为空，不虚构目标。

限制状态与原生效修订分别展示。明显不适的限制和暂停建议无需等待 AI；BLOCKED 能阻止发布增加强度、极端补偿等受限安排，不能阻止如实保存已经发生的训练/摄入/睡眠。过往事实修正不会自动修改未来已确认安排。
