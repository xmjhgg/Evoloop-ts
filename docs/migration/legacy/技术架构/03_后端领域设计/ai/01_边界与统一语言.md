## 1. 职责与数据所有权

本域回答：某次 AI 请求是否已持久受理、由哪个有效租约执行、是否需要重试、返回是否可供业务所有者核验、最终被业务接纳到哪个候选版本。AiTask 是一致性根；输入、来源引用、调用尝试、租约、结果和接纳记录归该任务，不是另一套目标、实际或结论。

| 本域拥有 | 业务所有者拥有 | 协作方式 |
| --- | --- | --- |
| 任务身份、幂等、重试和取消状态 | planning 的目标/草案/审查/发布与健身限制 | planning 固定输入和 schema，接纳候选并执行自己的规则；AI 不判最终可发布 |
| 输入快照和调用所必需来源引用 | execution 的照片业务关联、食物草案、个人份量、摄入事实与营养换算 | execution 选择受控图片引用，维护 FOOD_ANALYSIS schema；AI 不查询营养数据库或换算入账 |
| 规范化模型返回、模型/提示版本 | review 的共享日结论、目标周复盘、人工补充、确认与调整依据 | review 固定来源与覆盖，维护分析 schema；AI 不保存第二份可编辑结论 |
| 调用成功与业务接纳分别记录 | identity 的本人资格、用途、账户/删除 epoch 与数据请求 | ai 只调用 identity::api，不自建另一授权枚举 |
| 任务持有的受控资源引用、供应商调用标识 | 图片原始正文/业务关联由 execution 及文件端口维护 | ai 不永久复制原图；若调用适配产生临时材料，本域负责清理其副本并回执 |

AI 模块不得导入 planning/execution/review 的聚合、仓储、事件实现或私有 API。结果事件属于 `ai.api`，业务模块依赖并订阅它；本域不回调业务实现。场景 schema 为独立版本化协议制品，由所有者维护、bootstrap 登记，AI 仅按该制品检验结构和转换供应商响应。schema 版本不以 Java 跨域实现类表示。

## 2. TaskKind 与场景契约

| 精确枚举 | origin ownerModule | 输入快照由所有者准备 | 输出候选及唯一接纳者 | 需求入口 |
| --- | --- | --- | --- | --- |
| `PLAN_GENERATION` | `planning` | 目标/条件/规则版本、目标周、可安排范围、已有草案及有限依据 | 逐日候选安排；planning 接纳为同周工作草案，不发布 | UC-FIT-003；UC-COM-009；学习复用 |
| `PLAN_REVIEW` | `planning` | 最新完整草案、确定性规则检查、条件/来源和审查渠道 | 带定位、严重性、替代与未知的语义审查候选；planning 判定适用审查状态 | UC-FIT-005；UC-COM-010 |
| `FOOD_ANALYSIS` | `execution` | 同餐草案/图片版本、用户选择证据、说明与已知单位/来源 | 可核对食物/份量/营养估算、假设/未知/需补充；execution 合并核对，不计摄入 | UC-FIT-012 |
| `DAILY_CONCLUSION` | `review` | 同一归属日的计划/事实/身体/人工信息、覆盖、截至时间与来源集合 | 日总览与目标分段候选；review 写入同一日结论的新修订，不确认 | UC-COM-012；UC-FIT-017 |
| `GOAL_WEEKLY_REVIEW` | `review` | 单目标归属周、日结论状态、底层事实/基准、覆盖/截止 | 单目标周分析候选；review 接纳到目标周复盘，不代确认每日 | UC-COM-014；UC-FIT-020 |
| `ADJUSTMENT_SUGGESTION` | `review` | 最新已确认依据、影响目标/未来日期、原值、保护范围与规则版本 | 原/新/理由/日期候选；review 核验后提交 planning 合并，不发布 | UC-COM-015；UC-FIT-019 |

映射是服务端白名单，客户端不能传 ownerModule 切换数据所有者。输入与输出分别带 `schemaId/schemaVersion`，schemaId 命名空间为 origin 所有者；同一 TaskKind 可以支持健身/学习 schema，但不能缺省为健身。结果若只有未知或需补充而结构有效，可调用成功；业务判定“可核对/需补充”属于所有者。

## 3. 统一语言

| 术语 / 类型 | 定义 | 必须区分 |
| --- | --- | --- |
| AiTask / AI 任务 | 一个固定业务输入的持久处理意图 | 不是一次 HTTP 连接，也不是供应商的一次调用 |
| BusinessRequestId | origin 域给出的同一业务生成意图的幂等键 | 与命令 requestId、taskId、供应商 requestId 分开 |
| InputSnapshot | 规范化最小输入及 schema、来源和资格版本的不可变快照 | 修改业务输入须新任务，不更新旧快照 |
| SourceReferenceSet | refs 引用已有对象修订；scopeTokens 检测新增/纠正/删除范围变化 | AI 保存它，不反向读取源域核验最新性 |
| InputFingerprint | 规范化输入/schema/来源/用途/双版本/模型策略的 SHA-256 | 不含临时签名 URL；同业务键不同 fingerprint 为冲突 |
| ProcessingContext | identity 签发的封閉用途/操作/范围上下文 | 无用户确认权，不是可任意续期的同意 |
| TaskAttempt | 同一个任务的一次领取/调用尝试 | 网络超时后可能已经送达供应商，不承诺恰好调用一次 |
| ExecutionLease | 当前 worker 的限期执行资格：leaseToken、到期、attemptNo | leaseToken 每次领取更新；workerId 不能代替 token |
| ModelBinding / PromptBinding | 本任务固定的供应商策略、模型配置及提示版本 | 供应商秘密在部署凭据系统；任务不保存密钥 |
| ExecutionStatus | QUEUED/RUNNING/RETRY_WAIT/SUCCEEDED/FAILED_FINAL/CANCELLED | SUCCEEDED 仅为规范化候选产出 |
| AcceptanceStatus | NOT_READY/PENDING/ACCEPTED/REJECTED_STALE/REJECTED_POLICY | ACCEPTED 表示业务候选保存，绝不表示人工确认 |
| AcceptanceReceipt | origin 所有者对一个结果的接纳/拒绝、理由和业务结果修订 | worker 不能自己声明 ACCEPTED |
| MaintenanceContext | 当前 epoch 下限任务元数据终结/清理的后台资格 | 不能为旧正文恢复可用权限 |
| ControlledResourceRef | 本人选定图片/临时材料的受控引用、摘要与选择证据 | 不是永久下载 URL，也不携带图片正文 |

输入正文和结果候选使用 schema 约束的 JSON 文档，是模型调用协议快照；它不能替代业务所有者的类型化事实表。缺失、估算和范围由业务 schema 明确表示，适配器不以 0 填充未知、不编造来源或置信度。

## 4. 用途与任务处理资格

用途直接引用 `identity.api.ProcessingPurpose`：学习 AI 为 ACCOUNT_ACCESS + AI_PROCESSING；健身文本 AI 再加 HEALTH_DATA；FOOD_ANALYSIS 再加 FOOD_IMAGE。混合日结论按真实输入并集核验，不能将健康正文伪装为学习输入。上传仅包括用户拍摄/选定图片，选择证据由 execution 保存并引用。无图片/健康/AI 授权仍可按对应业务域规定使用手工能力。

创建由 origin 所有者在持账户栅栏的短事务采集快照，预分配 taskId 后取得受限上下文。`ownerModule` 表示 origin 所有者；executor 固定为受信 ai worker，不能据此写 origin 域正文。调用前、返回落库前、origin 业务接纳前分别核验账户、用途、authorizationVersion、deletionEpoch、删除范围和上下文有效期；重新同意不能恢复旧 epoch。

旧普通上下文遭拒绝后，ai 以自己拥有的 taskId 请求新的 BACKGROUND_MAINTENANCE，ownerModule=ai、当前 epoch，仅执行 CANCEL_TASK/REJECT_RESULT/RELEASE_LEASE/RECORD_FAILURE_METADATA/PURGE_HELD_CONTENT。不读取输入/返回正文，不发新模型请求，不接纳结果。调用成功已经提交后再撤回，可保留“调用曾成功”的无正文状态并拒绝未接纳候选；撤回本身不等于已完成全部数据删除。

## 5. 出站端口及最小化

| 端口（本域 application 定义） | 输出与限制 |
| --- | --- |
| IdentityProcessingPort | 包装 identity 公开栅栏/资格/上下文/阶段回执；不复制授权实现 |
| ModelInvocationPort | 固定模型/提示、受控 schema 输入 → 规范化候选或分类失败；网络调用无数据库事务 |
| ControlledResourcePort | 按用户/任务/epoch 读本次受控图片流、清理本域临时副本；不直接从客户端 URL 下载 |
| TaskPolicyRegistry | 版本化 retry/timeout/token/图片限制配置和可用 schema；未批准配置返回未就绪，不编造生产阈值 |
| DataRequestArtifactPort | 按冻结清单生成受控导出片段/证据；网络工作事务外，最终关联前重核 epoch |

供应商响应原文只在适配层短暂处理，不写日志/事件/公共响应；必要诊断只保留白名单错误码、供应商受控 requestRef 和用量。若供应商会保留输入或图片，该范围、期限、删除能力必须纳入用途说明与 PROCESSOR 阶段。提示与模型配置切换不悄悄改已创建任务，重试沿用原绑定；新 schema/策略需要新任务。
