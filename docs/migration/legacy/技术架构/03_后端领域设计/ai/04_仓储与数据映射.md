## 1. 映射约定与仓储

表中的 `UUID` 均展开为 `CHAR(36) CHARACTER SET ascii COLLATE ascii_bin`；`HASH` 为 `CHAR(64) CHARACTER SET ascii COLLATE ascii_bin`；代码/版本/幂等键使用显式 ascii_bin VARCHAR，私人文本使用 utf8mb4。每张表均有非空 user_id。UTC 时间点为 DATETIME(6)，上海业务日/周为 DATE；JSON 数字/数量遵业务 schema，不把未知填零。所有默认值在表中标注，`无`表示插入方必须赋值，`NULL`表示可缺失；时间不依赖服务器本地时区。

AiTaskRepository 只操作本域表，按 `(userId,taskId)` 加载当前任务/输入引用，尝试和修订分页。专用 TaskProgressQuery 不读输入/结果正文；CandidateQuery 只在完整 origin 资格后返回固定结果。来源对象、账户、公共命令 receipt 和 Modulith 登记没有跨域 FK/JPA 导航。公共表由 V001 基础设施提供，不再造 ai_command_receipt/ai_outbox。

每个内部父表有 `UQ(user_id,<id>)`，内部 FK 包括 user_id，不仅对单列 ID 建 FK。FK 采用 RESTRICT，隐私清理按子表先、父表后显式批处理，避免未核范围的级联删除。根当前 revision/result 指针不反向建 FK，避免 MySQL 非延迟外键根/子循环；同事务插根/子后校验本人指针存在。组合 FK 和所引用唯一索引按 [MySQL 8.4 外键规则](https://dev.mysql.com/doc/refman/8.4/en/create-table-foreign-keys.html) 设计，真实迁移测试尚待执行。

## 14. 事务、索引与竞争处理

| 操作 | 短事务锁顺序 / 提交内容 |
| --- | --- |
| 创建任务 | origin 已先账户栅栏；公共receipt→origin业务根→ai新根/输入/来源/初始revision；业务关联+任务同提交 |
| 领取 | 无锁候选读取 taskId/userId；账户栅栏→ai_task FOR UPDATE；重新核可领取状态/nextAttemptAt/原资格/deadline，新增attempt+lease+revision，共同提交 |
| 续租 / 调用开始 | 账户栅栏→任务→当前attempt；token/未到期/双版本核验，更新root与attempt镜像，提交 |
| 完成/失败 | 当前处理或新维护context账户栅栏→任务→attempt；有效token才保存结果或分类失败、root/revision和单一事件登记；释放锁后进行网络清理 |
| origin接纳 | 账户栅栏→公共receipt/消费去重→origin相关根→ai任务；origin候选+接受/拒绝回执+root/revision同提交 |
| 取消/恢复 | 账户栅栏→公共receipt→任务→attempt；失效租约/受限排队或同结果重投通知；无用户确认 |
| 固定导出 | 请求导出资格+账户栅栏→本域manifest/稳定清单；读取根当前revision/输入/结果指针并固定；提交后按清单分批只读不可变版本 |
| 清理小批次 | DATA_REQUEST_WORKER账户栅栏→本域工作行→按ID排序任务→相关子表；先保存外部清理键再删正文/引用，真实证据到达后另短事务回执 |

数据库隔离为 READ COMMITTED；所有锁定读在显式短事务保持到提交，外部网络不在其中等待，依据 [MySQL 锁定读](https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html)。领取不得先对队列表使用 `FOR UPDATE SKIP LOCKED` 抢任务再申请账户锁；那会违反共同栅栏顺序。扫描可按索引无锁取少量候选、按用户公平限额处理，竞争者在栅栏后重新读状态，已领取则跳过。

root更新 `WHERE user_id=? AND task_id=? AND version=?` 防乐观冲突；worker状态更新另匹配当前token摘要/attemptNo/到期。MySQL死锁/瞬态失败按固定有限策略使用同requestId重试；业务版本冲突返回调用方，不自动覆盖新业务。数据库now为租约时钟，实例钟仅用于观测；具体续租安全边距需压测。

## 15. 导出、删除与备份

导出在一个短栅栏事务固定匹配范围任务清单及每任务 current_revision_id/taskVersion/inputId/resultId/acceptanceId，snapshotAt 是本域采集时刻。后续不得分页读当前根或持续变化attempt；从不可变 revision.attempt_summaries 导出当时状态。输入/结果/回执不可变，资源选择冻结。不同批之间写入可继续；新task不混入原清单，已删源使导出epoch失效并清理临时片段，不能用最新源填缺口。

DELETE/CLOSE_ACCOUNT 按 identity 已受理范围解析源对象关联的 ai_input_snapshot/source_ref/resource_ref/result/attempt/acceptance/revision/export副本闭包。userId+对象/日期+衍生条件匹配，不能未经确认删除独立事实；ai不存独立业务事实。清理顺序：失效租约/取消待接纳→建外部待删目标→删除导出manifest_item/受控产物引用→acceptance→result→resource_ref→attempt→source/purpose→input→revision→task。最小无正文终结墓碑仅在批准策略允许时保留，不以保留历史为借口留下输入/结果正文。

根FK RESTRICT 的子表必须先清理；删除旧结果相关接纳不能丢失仍需第三方清理的工作键。公共sys_command_receipt/sys_event_consumption/持久事件载荷由 infrastructure处理其阶段，本域仍处理自己持有副本；控制事件仅含引用以减少正文扩散。备份恢复后在开放业务前重放删除/epoch拒绝及清理证明，具体备份政策尚待TBD-003决定。供应商不可验证删除时PROCESSOR保持PENDING_EXTERNAL/PENDING_POLICY并记录原因，不将数据库删除等同全部完成。
