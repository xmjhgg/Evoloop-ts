## 1. 处理上下文与事务属性

普通 HTTP 从本人会话恢复 ActorContext，不接受客户端 userId/ownerModule/ProcessingContext。跨域创建使用 `operation=AI_CANDIDATE_PROCESSING` 的封闭上下文，context.ownerModule 固定为 origin（planning/execution/review），task 资源所有者仍 ai。TrustedModuleContext 由 bootstrap 绑定真实调用方，identity 核验上下文及本次子操作：

| 受信调用方 | 允许子操作 | 禁止 |
| --- | --- | --- |
| origin owner | CREATE_TASK、READ_OWN_CANDIDATE、SAVE_OWNER_CANDIDATE、RECORD_ACCEPTANCE；取消按本人/受信 origin 范围 | 使用其他 origin 的 task、替用户确认/发布 |
| 固定 ai executor | CLAIM、EXECUTE、STORE_CANDIDATE、COMPLETE、FAIL；受限续租、恢复执行状态 | SAVE_OWNER_CANDIDATE、RECORD_ACCEPTANCE、跨域写正文、用户确认 |
| ai 维护 worker | 新签 BACKGROUND_MAINTENANCE 的 CANCEL_TASK、REJECT_RESULT、RELEASE_LEASE、RECORD_FAILURE_METADATA、PURGE_HELD_CONTENT | 读/生成正文、执行供应商调用、ACCEPTED、用户确认 |

worker 不改变原 context.ownerModule/双版本/范围，不在续租时刷新 epoch。context 到期不能自行扩权续办；origin 重取当前来源及资格后创建新任务。任务普通恢复仅在原上下文仍有效、双版本未变时继续原快照。业务接纳由 origin 持自己的业务处理资格及原任务同双版本条件，最终校验来源，不由 ai executor 代行。

`createTask`、`recordAcceptance` 为 REQUIRED，加入调用方同一 READ COMMITTED 短事务；调用者先持用户栅栏。业务根先于 ai 任务锁，禁止 REQUIRES_NEW 使候选保存与接纳分离。ai 自己的领取/续租/完成/失败/取消/恢复为短事务，先定位 userId，再请求 identity 栅栏，再锁任务；网络端口始终事务外。

## 2. 公共 DTO

以下是不含 JPA/聚合/供应商秘密的不可变 `ai.api` 协议。公开包直接放类型；scenarioPayload 是 schema 制品定义的调用文档，origin 不需导入 AI 内部模型。

| DTO / 字段 | 必填、类型与含义 |
| --- | --- |
| CreateAiTaskCommand.context / trustedCaller | 必填，服务端 ProcessingContext / TrustedModuleContext，不能由 HTTP 字符串构造 |
| taskId / ownerModule / taskKind | 必填，预分配 UUID、origin 白名单、六种 TaskKind；context 绑定同一 taskId |
| requestId / businessRequestId | 必填，命令幂等键 / 业务任务幂等键；两者不得混称 |
| inputSchema / outputSchema | 必填，`{schemaId,schemaVersion}`；都来自 origin 登记的受支持版本 |
| inputSnapshot | 必填，规范化的最小 JSON 文档；未知显式；不能含密钥、微信会话或任意下载 URL |
| sourceRefs | 必填数组，可空，`{ownerModule,objectType,objectId,revisionId?,version?}`；至少 revisionId/version 之一；生成所需范围由 origin 负责完整提供 |
| sourceTokens | 必填数组，`{ownerModule,scopeType,scopeKey,version}`；必要空范围也带逻辑 0，不只检查现有 ID |
| resourceRefs | 必填数组，可空，`{ownerModule,resourceType,resourceId,revisionId?,contentDigest,selectionEvidenceRef}`；图片必须来自本人已选引用 |
| purposes / authorizationVersion / deletionEpoch | 必填，identity 用途集合、原上下文双版本；不能用 sourceTokens 替代 |
| businessDate / weekStartDate / cutoffAt | 按 schema 适用可空；DATE 为上海日期、weekStartDate 为周一，cutoffAt 为 UTC 时间点，不由 AI 改归属 |
| modelPolicyVersion / promptVersion / executionPolicyVersion | 必填，服务端批准并固定的版本；尚未选型不接收客户端随意模型名 |
| TaskHandle | `taskId,taskVersion,ownerModule,taskKind,executionStatus,acceptanceStatus,createdAt`；相同业务键重放同 taskId |
| TaskProgress | TaskHandle + `attemptCount,nextAttemptAt?,lastFailureCode?,retryable,recoverable,cancelable,resultAvailable,acceptanceReasonCode?,businessResultRef?,recoveryAction?`；无正文/模型秘密 |
| OwnerCandidateView | TaskProgress + `resultId,resultDigest,outputSchema,normalizedOutput,sourceRefs,sourceTokens,authorizationVersion,deletionEpoch,producedAt`；仅受信 origin 且完整用途/双版本通过时可读 |
| RecordAcceptanceCommand | `context,trustedCaller,taskId,ownerModule,expectedVersion,requestId,resultId,resultDigest,outcome,reasonCode?,businessResultRef?` |
| businessResultRef | `{ownerModule,objectType,objectId,revisionId,version}`；ACCEPTED 必填，拒绝不伪造业务结果；不保存私人正文 |
| AcceptanceOutcome | ACCEPTED / REJECTED_STALE / REJECTED_POLICY；拒绝 reasonCode 必填 |
| AcceptanceResult | `taskId,taskVersion,executionStatus,acceptanceStatus,receiptId,businessResultRef?,duplicate` |

`inputFingerprint` 由服务端 canonical JSON 计算，包含 schema/refs/tokens/资源摘要/用途/双版本/模型提示执行策略及业务范围，排除 requestId、taskId、临时签名票据。排序规则对无序引用按稳定键排序、有序动作等 scenario 数组维持顺序；具体 canonicalization 实现锁定后写入契约测试。taskId 不同但同业务键+摘要仍返回原任务。

## 3. AiTaskApi 完整契约

| 方法 | 输入 / 成功输出 | 核验、事务及错误 |
| --- | --- | --- |
| `createTask(CreateAiTaskCommand)` | 上表全部创建字段 → TaskHandle；仅持久受理，不调用外部模型 | origin 身份/TaskKind/schema/最小输入/双版本/范围；加入 origin 输入采集事务。IDEMPOTENCY_CONFLICT、TASK_KIND_OWNER_MISMATCH、UNSUPPORTED_SCHEMA、INPUT_SCHEMA_INVALID、TASK_POLICY_UNAVAILABLE、PURPOSE_NOT_GRANTED、AUTHORIZATION_STALE、PROCESSING_EPOCH_STALE |
| `getTask(TaskQuery)` | actor 或受限上下文、trustedCaller?、taskId、mode=PROGRESS/OWNER_CANDIDATE → TaskProgress 或 OwnerCandidateView | PROGRESS 只本人安全元数据；OWNER_CANDIDATE 需 origin 与完整处理资格，在 origin 接纳栅栏内读取。TASK_NOT_FOUND、CANDIDATE_NOT_READY、CONTEXT_OPERATION_DENIED、RESOURCE_DELETING、授权/epoch 拒绝 |
| `cancelTask(CancelAiTaskCommand)` | actor/受信 origin 或 ai 维护 context、taskId、expectedVersion、requestId、reasonCode → TaskProgress | 短写栅栏→公共 receipt→任务；未成功任务 CANCELLED，成功待接纳拒绝候选，已接纳 TASK_ALREADY_ACCEPTED；重复同键同请求返回已提交结果。VERSION_CONFLICT、TASK_NOT_FOUND、TASK_ALREADY_ACCEPTED |
| `recordAcceptance(RecordAcceptanceCommand)` | origin 资格、精确结果/摘要、预期版本、outcome/理由/业务结果引用 → AcceptanceResult | 只有 origin 正常资格能 ACCEPTED/REJECTED_STALE；必须与 origin 保存候选共用事务；重复一致回执返回 duplicate，不同 terminal outcome 返回 ACCEPTANCE_CONFLICT。RESULT_MISMATCH、TASK_NOT_SUCCEEDED、VERSION_CONFLICT、TASK_NOT_FOUND、来源/资格拒绝 |

维护 worker 的 REJECT_RESULT 是本域内部命令；它可写明 `reportedBy=AI_MAINTENANCE, outcome=REJECTED_POLICY`，不能伪装 origin 的 ACCEPTED。公开 `recordAcceptance` 的调用权限不因存在维护能力而扩大。来源差异由 origin 返回 REJECTED_STALE(reason=SOURCE_STALE/BUSINESS_VERSION_STALE)，业务 schema/限制拒绝为 REJECTED_POLICY(reason=OWNER_RULE_REJECTED)；AI 不自行评估这些规则。

所有跨域错误使用共同 `{code,message,requestId,details}`，HTTP 对应 401/403/404/409/422。AI 完成事件中的 taskVersion 是该事件发生版本；origin 在持栅栏事务重新 `getTask` 获取当前可接纳状态，不能盲用事件版本写入。结果已拒绝/取消时只完成消费去重，不再次保存业务候选。

## 4. HTTP：本人任务进度、取消与恢复

前缀 `/api/v1/ai/tasks`。任务创建从 planning/execution/review 用例入口受理；HTTP 不提供任意 prompt/ownerModule 创建接口，不开放领取/心跳/完成/供应商管理端点。写请求必须 Idempotency-Key；时间点带 Z，安全错误不含 input/result/provider 原文。

| 方法 / 路径 | 输入 | 输出 | 主要失败 |
| --- | --- | --- | --- |
| GET `/` | taskKind?、executionStatus?、cursor?、limit（受配置上限） | 200 本人 TaskProgress[]、nextCursor；按 createdAt+taskId 稳定分页 | 401 SESSION_EXPIRED；403 ACCOUNT_RESTRICTED；422 INVALID_FILTER |
| GET `/{taskId}` | 本人会话 | 200 TaskProgress；resultAvailable 仅提示 origin 有候选，私密结果仍由 origin 页面读取 | 404 TASK_NOT_FOUND（含非本人） |
| POST `/{taskId}/cancel` | expectedVersion、reasonCode=USER_CANCELLED | 200 TaskProgress；立即失效本地租约，外部取消尽力进行 | 409 VERSION_CONFLICT/TASK_ALREADY_ACCEPTED；403 账户受限 |
| POST `/{taskId}/recover` | expectedVersion、mode=RESUME_EXECUTION/RESUME_DELIVERY | 202 TaskProgress；同输入有限重新排队或重投已有结果事件 | 409 TASK_NOT_RECOVERABLE/PROCESSING_EPOCH_STALE/AUTHORIZATION_STALE；403 PURPOSE_NOT_GRANTED/PROCESSING_CONTEXT_EXPIRED |

PROGRESS 和安全取消仅需本人基础 ACCOUNT_ACCESS，scope 限任务状态，不读取撤回用途的正文；CLOSING/CLOSED 无普通业务访问，注销进度仍走 identity 专用端点。RESUME_EXECUTION 需原完整用途、原双版本、原上下文有效、可重试失败和固定人工恢复预算；不重新签发旧 context。RESUME_DELIVERY 只对 SUCCEEDED+PENDING，完整用途/双版本通过后重新登记同一结果的通知，origin 再按来源核验；未接纳结果不能凭“恢复”强制接纳。

若输入/授权/删除状态改变、上下文到期、schema 策略不可用，recover 输出 `recoveryAction=RECREATE_VIA_OWNER`，origin 重新采集当前输入并创建新 businessRequestId，不在此接口编辑输入。QUEUED/RUNNING/RETRY_WAIT 的恢复先查询原任务，不重复调用；相同写幂等键不同 mode/版本返回 IDEMPOTENCY_CONFLICT。

## 5. 创建、租约执行与业务接纳

```mermaid
sequenceDiagram
    actor U as 用户
    participant O as origin 应用服务
    participant I as IdentityApi
    participant A as AiTaskApi
    participant D as MySQL及单一事件登记
    participant W as 受信 ai worker
    participant P as 模型端口
    U->>O: 业务生成/分析 + 幂等键
    O->>I: 短事务 lockProcessingFence
    O->>O: 获取当前来源/范围token，固定输入，预分配taskId
    O->>I: createProcessingContext(AI_CANDIDATE_PROCESSING)
    O->>A: createTask(固定schema/输入/双版本)
    A->>D: 栅栏已持有；幂等→任务/输入/初始修订
    O->>D: 保存 origin 任务关联，同事务提交
    O-->>U: 202 taskId + 当前业务版本
    W->>D: 无锁扫描候选 taskId/userId
    W->>I: 短事务 栅栏 + CLAIM 子操作
    W->>D: 锁任务，重核状态，attemptNo++ / 新leaseToken
    W->>D: 提交释放锁
    W->>I: 调用前 EXECUTE 资格/双版本核验
    W->>P: 固定输入/模型/提示调用（无数据库事务）
    P-->>W: 候选或分类失败
    W->>I: 新短事务 栅栏 + STORE_CANDIDATE/COMPLETE
    W->>D: 锁任务，核leaseToken/到期/attemptNo
    W->>D: 保存规范化结果，SUCCEEDED+PENDING，同事务登记 AiTaskCompleted
    D-->>O: 至少一次交付完成事件
    O->>I: 新短事务 栅栏，origin资格/原双版本
    O->>A: getTask(OWNER_CANDIDATE)
    O->>O: 核当前业务根/来源refs+tokens/schema/规则
    alt 仍适用
        O->>D: 锁origin根，保存候选与消费去重
        O->>A: recordAcceptance(ACCEPTED,业务结果修订)
        A->>D: origin锁后ai任务锁，回执/任务修订，共同提交
    else 来源或业务规则不适用
        O->>A: recordAcceptance(REJECTED_STALE/POLICY,理由)
        O->>D: 拒绝回执+消费去重提交，不改新业务内容
    end
```

创建时同业务键唯一冲突先回滚新行尝试，再在同用户新短事务取已有任务并比 fingerprint；不能把失败插入 taskId 当作成功返回。调用前 EXECUTE 核验通过后记录 invocation_started 的短写也遵守栅栏；发送与记录之间不能实现外部 exactly-once，attempt.deliveryState 真实标识 NOT_SENT/SENT/UNKNOWN/RESPONSE_RECEIVED。

## 6. 过期租约、重试与取消

```mermaid
sequenceDiagram
    participant W1 as 旧worker
    participant W2 as 恢复worker
    participant I as IdentityApi
    participant D as MySQL
    participant P as 供应商
    actor U as 用户
    W1->>P: attempt 1 已发出
    W2->>D: 无锁定位过期 taskId/userId
    W2->>I: 账户栅栏（原资格有效或维护资格）
    W2->>D: 锁任务，租约已过期，尝试1 EXPIRED，失效token1
    W2->>D: 根据预算进入 RETRY_WAIT，提交
    W2->>I: 到期后栅栏，资格核验
    W2->>D: 领取尝试2，新token2，提交
    P-->>W1: 迟到结果
    W1->>I: 完成短事务 栅栏
    W1->>D: 锁任务，token1不是当前token2
    D-->>W1: LEASE_LOST，丢弃返回，不记录结果
    U->>I: 本人取消资格
    U->>D: 栅栏→幂等→任务 CANCELLED，token2失效，登记事件
    W2->>P: 事务外尽力取消供应商请求
    P-->>W2: 仅受理或取消失败
    W2->>D: 元数据记录真实结果；不能完成 CANCELLED 任务
```

leaseToken 是随机服务器凭据，HTTP 不暴露；库仅存摘要。完成/失败均同时要求 task RUNNING、token 摘要匹配、attemptNo 相等、到期未过。续期后仍用该次 token；重新领取必须换 token。LEASE_LOST 后旧 worker 不允许把错误写成当前任务失败。旧 attempt 的私密临时材料由清理扫描单独处理，不在失效完成路径读取业务正文。

## 7. 授权撤回与返回拒绝

```mermaid
sequenceDiagram
    participant W as ai worker
    participant I as IdentityApi
    participant P as 供应商
    participant D as MySQL
    actor U as 用户
    W->>I: 原context 调用前核验
    W->>P: 外部请求已发出
    U->>I: 撤回/删除/注销
    I->>D: 栅栏内双版本变化与事件提交
    P-->>W: 原请求返回
    W->>I: 原context 完成前 lockProcessingFence
    I-->>W: AUTHORIZATION_STALE / PROCESSING_EPOCH_STALE
    W->>I: createMaintenanceContext(ai拥有的taskId,当前epoch)
    W->>I: 新维护context 栅栏
    W->>D: 仅锁任务元数据；取消/拒绝/释放租约，记录脱敏原因
    W->>W: 不持久化返回正文；清理本地内存/临时材料
    W->>P: 事务外尽力取消/处理方清理请求
    W->>I: 适用数据请求PROCESSOR阶段，报告真实未完成项
```

执行结果已提交后才发生撤回时，未接纳候选可由维护路径标 REJECTED_POLICY；原 SUCCEEDED 历史不假写 FAILED。已接纳业务对象由 origin 自行处理数据请求，AI 不反向删业务表。授权事件延迟时，直接调用前/完成前/接纳前核验仍阻止旧返回。

## 8. 集成事件与恢复

共用信封 `eventId,eventType,schemaVersion,occurredAt,ownerModule,userId,aggregateId,aggregateVersion,requestId,affectedScopes,payload`，schemaVersion=1，event.ownerModule=ai（不等于 payload.originOwnerModule）。仅用 ADR-002 的单一 Modulith JDBC 持久登记；不建 ai_outbox。业务变更及发布登记同事务，公共 sys_event_consumption 与业务消费变化同事务。

| 事件 / 订阅者 | 最小 payload | 行为 |
| --- | --- | --- |
| `AiTaskCompleted` / 相应 origin | taskId、originOwnerModule、taskKind、businessRequestId、resultId、resultDigest、outputSchema、sourceFingerprint、authorizationVersion、deletionEpoch | origin 按本人和 taskId 读候选，再核完整来源；payload 无正文/图片/秘密 |
| `AiTaskFailed` / origin、安全进度投影 | taskId、originOwnerModule、taskKind、failureCode、retryable、nextAttemptAt?、attemptNo | 显示等待/失败，保留原事实/草案；不可假设任务永远失败 |
| `AiTaskCancelled` / origin、进度投影 | taskId、originOwnerModule、taskKind、reasonCode、executionStatus、acceptanceStatus | origin 停止等待，不撤销已确认事实/发布 |

任务排队由数据库扫描恢复，不必须另造 TaskQueued 事件。重复结果通知可新 eventId，但固定同 resultId/digest；origin 对 `(taskId,resultId)` 接纳业务结果防重，再以公共消费表对 eventId 去重，避免重新保存候选。失败/取消旧事件仅在版本不回退前提更新显示。供应商 callback 若选型需要，是 infrastructure 的认证回调入口，先验证供应商签名、task/attempt 关联，再使用同一有效租约完成协议；不是公开 worker 接口。

| 本域订阅 identity 事件 | 处理 |
| --- | --- |
| AuthorizationChanged / AccountStatusChanged | 无锁定位本域受影响任务；各自新维护context短事务终结/清理，不等待事件才做资格拒绝 |
| DataRequestCreated | 扩展本域所持输入/结果/尝试/图片/导出闭包，持请求资格分批处理，回执正式阶段 |
| ExportArtifactInvalidated | 按 epoch 清理本域导出片段/临时材料，不能恢复为可下载 |

## 9. 数据请求与正式阶段回执

DELETE/CLOSE_ACCOUNT 由 ai 对 MODULE_DATABASE、OBJECT_STORAGE、PROCESSOR、BACKUP 各报告；EXPORT 对 EXPORT_SNAPSHOT、EXPORT_OBJECTS 报告。状态仅为 PENDING/RUNNING/SUCCEEDED/SKIPPED/FAILED_RETRYABLE/FAILED_FINAL/PENDING_EXTERNAL/PENDING_POLICY，SKIPPED 必须有无持有/无处理方理由与核实证据，不能代表未实现。

| 阶段 | 本域内容 / 完成证据 |
| --- | --- |
| MODULE_DATABASE | 固定闭包后分批删输入/结果/来源引用/尝试私人诊断/任务修订/接纳引用/导出副本；统计目标和已删数量、复核无正文残留；必要最小无正文进度按已批准策略处理 |
| OBJECT_STORAGE | 本域持有临时图片/结果材料/导出片段的删除与实际不存在验证；原图由 execution 对自己的阶段负责 |
| PROCESSOR | 模型处理方已送达请求的输入/图片/结果副本清理；仅供应商“受理” → PENDING_EXTERNAL，确认清理证据才 SUCCEEDED |
| BACKUP | 本域数据在基础设施备份的处理证明；无已批准处理/保留政策为 PENDING_POLICY，不能用主库删除代替 |
| EXPORT_SNAPSHOT | 短栅栏建立固定 taskVersion/输入/结果/回执选择清单与 snapshotAt，分批读不可变记录，产物包含版本、时间/未知和缺失清单 |
| EXPORT_OBJECTS | 仅冻结范围选择的本域持有资源/导出片段，事务外取文件，关联/回执前重核 acceptedEpoch；无图片且确无对象可 SKIPPED |

回执用 IdentityApi.reportDataRequestStage：`dataRequestId,module=ai,stage,receiptVersion,attemptNo,status,artifactDescriptors,snapshotAt?,sourceManifestRef?,residualItems,evidenceRef?,contentDigest`。本域每请求每阶段单调 receiptVersion；同版本同摘要可安全重投。删除重试由 identity 重新签当前 epoch 的 DATA_REQUEST_WORKER，不给旧模型任务新权利；未完成项示例为 PROVIDER_ERASURE_NOT_CONFIRMED/BACKUP_POLICY_PENDING/OWNED_OBJECT_DELETE_FAILED。

导出不锁住用户全部业务直到文件完成。固定选择清单后只读该 taskVersion 的不可变状态及所引用输入/结果/回执；正在运行尝试的状态以 snapshotAt 已冻结的修订镜像表示，不继续读取最新可变 attempt。任何 epoch 改变取消旧导出并清理临时产物。多个域 snapshotAt 不同，组合包如实记录各域采集区间。
