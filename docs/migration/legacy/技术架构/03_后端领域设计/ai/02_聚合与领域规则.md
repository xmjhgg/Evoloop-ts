## 1. 聚合和内部对象

AiTask 为唯一业务聚合根，拥有固定的 InputSnapshot、SourceReferenceSet、ModelBinding/PromptBinding、TaskPolicySnapshot、TaskAttempt 集合、当前 ExecutionLease、最多一个 TaskResult 和接纳回执。加载命令所需当前状态即可，历史尝试通过分页专用查询读取，不在每次续租中装载完整历史。AiTaskRevision 是不可变状态审计快照，不是独立编辑聚合；导出与清理工作记录属于本域运行支撑。

领域模型使用纯 Java；ActorContext/ProcessingContext 在应用层核验后转换为限行为许可，供应商 SDK、HTTP 与 JPA 类型不进入领域。聚合行为要求 expectedVersion 或有效 leaseToken；取消/接纳不会直接改其他领域。

## 3. 执行状态

```mermaid
stateDiagram-v2
    [*] --> QUEUED: 输入快照与任务提交
    QUEUED --> RUNNING: 领取并创建尝试/新租约
    RETRY_WAIT --> RUNNING: 到达 nextAttemptAt 后领取
    RUNNING --> SUCCEEDED: 有效租约与资格下保存规范化结果
    RUNNING --> RETRY_WAIT: 可重试失败或租约超时且预算剩余
    RUNNING --> FAILED_FINAL: 不可重试或预算耗尽
    QUEUED --> CANCELLED: 本人或维护取消
    RETRY_WAIT --> CANCELLED: 本人或维护取消
    RUNNING --> CANCELLED: 取消使租约失效
    FAILED_FINAL --> QUEUED: 有限人工恢复且原资格仍有效
    SUCCEEDED --> [*]
    CANCELLED --> [*]
```

FAILED_FINAL 的 `lastFailureClass=TRANSIENT` 可按固定恢复策略、原快照及原上下文恢复；POLICY/INVALID_INPUT/UNSUPPORTED_SCHEMA 等最终失败不可恢复。手动修改输入或新授权必须走 origin 的新任务流程。恢复不替换原 epoch、不重新获得旧任务被撤回的权限、不执行确认。

重试退避、总任务截止、单次 timeout、租约期限/续期、安全边距及人工恢复次数来自固定 TaskPolicySnapshot。参数尚待接入压测与评审；文档不规定未经确认的生产秒数/次数。worker 可续租但必须 token 当前且尚未到期，上下文当前有效，总截止未过；不能靠持续心跳无限延长总任务截止。

## 4. 调用成功与接纳状态

```mermaid
stateDiagram-v2
    [*] --> NOT_READY
    NOT_READY --> PENDING: 规范化调用结果提交
    PENDING --> ACCEPTED: origin 保存候选+同事务接纳回执
    PENDING --> REJECTED_STALE: 来源或目标业务版本失效
    PENDING --> REJECTED_POLICY: 授权/删除/业务规则/取消拒绝
    ACCEPTED --> [*]
    REJECTED_STALE --> [*]
    REJECTED_POLICY --> [*]
```

`SUCCEEDED + REJECTED_STALE` 是有效组合，表示执行完成但未进入当前业务候选。ACCEPTED 的业务候选之后仍可过期、撤回或删除，后续状态由 origin 管理；AiTask 的历史接纳回执不宣称该对象至今最新或已确认。未产生规范化结果时 acceptanceStatus 保持 NOT_READY，资格拒绝/取消理由记录在执行终结修订。已经 SUCCEEDED 但尚 PENDING 的取消不回退成功状态：拒绝候选为 REJECTED_POLICY(reason=USER_CANCELLED)，登记 AiTaskCancelled 通知；ACCEPTED 后取消返回 TASK_ALREADY_ACCEPTED，由 origin 提供候选处理能力。

## 5. 不变量和规则

| 设计规则 | 行为与失败保护 | 原需求规则 |
| --- | --- | --- |
| AI-R01 本人和固定 origin | 按 userId+taskId 查询；ownerModule/TaskKind 白名单；非本人统一不存在 | BR-COM-001/002 |
| AI-R02 业务幂等 | `(userId,originOwner,taskKind,businessRequestId)` 非空唯一；同 fingerprint 返回原任务，不同拒绝；HTTP 幂等另走公共 receipt | BR-COM-003 |
| AI-R03 固定输入 | input/schema/sourceRefs/tokens/双版本/模型策略不可改；新输入新业务请求，不用“重试”覆盖旧快照 | BR-COM-003/009/012/013 |
| AI-R04 栅栏先于任务 | 所有领取/续租/完成/失败/取消/接纳/清理短写先账户栅栏；扫候选仅无锁定位 userId | BR-COM-018；ADR-003 |
| AI-R05 有效租约 | 当前 token、attemptNo、RUNNING、数据库 now 小于 expiresAt；过期旧 worker 的续期/成功/失败全部拒绝 | BR-COM-003/004 |
| AI-R06 无长事务调用 | 领取提交后发请求；调用前核资格；完成开启新短事务；事件失败不回滚原事实 | BR-COM-004/018 |
| AI-R07 三处门禁 | 创建/调用/完成及 origin 接纳均校验当前用途/双版本/删除范围；事件及时性不能代替最终核验 | BR-COM-002/018 |
| AI-R08 安全终结 | 普通上下文拒绝后新维护资格只终结/清理，不读取/持久恢复私人正文 | BR-COM-018 |
| AI-R09 候选结构 | schema 不支持拒绝调用，输出不合法失败；保留来源、估算、范围和未知，不填零或伪造精度 | BR-FIT-006/009；BR-LRN-002 |
| AI-R10 origin 最终接纳 | origin 核来源/结构/业务规则并同事务保存业务结果与回执；ai 不判计划、营养或事实规则 | BR-COM-003/009/012/013/014；BR-FIT-013 |
| AI-R11 无隐含确认 | retry、ACCEPTED、事件处理、模型成功不能确认摄入/结论或发布计划 | BR-COM-001/017；BR-FIT-004 |
| AI-R12 可恢复状态真实 | 请求超时标未知送达/失败，按策略重试；调用可能重复且不保证供应商 exactly-once | BR-COM-003/004 |
| AI-R13 隐私闭包 | 处理输入/输出/尝试诊断/模型私人材料/受控资源及导出副本；第三方/备份独立真实回执 | BR-COM-018 |

## 6. 失败、取消与恢复的边界

| 情况 | 执行处理 | 可保留与不可发生 |
| --- | --- | --- |
| 供应商限流/网络超时/暂不可用 | 分类 TRANSIENT；记录 sent/unknownDelivery，按退避与预算进入 RETRY_WAIT 或 FAILED_FINAL | 原业务事实、人工输入和生效计划保持；不生成伪结论 |
| 非食物/图片模糊/未知份量 | 若 schema 表达需补充，保存有效候选为 SUCCEEDED | 不自动把未知值补齐，不计摄入 |
| 输出不符合固定 schema | MALFORMED_OUTPUT；策略允许时有限重试，否则最终失败 | 不将供应商原文直接写业务对象 |
| worker 崩溃/租约到期 | 无锁扫描 taskId/userId；栅栏→任务锁后使旧 token 失效，原尝试 EXPIRED，再重新排队 | 旧 worker 即使收到结果也不能完成；可能需要供应商去重/取消 |
| 本人取消 RUNNING | 栅栏内 CANCELLED、清租约；事务外尽力取消供应商 | 供应商只受理取消不等于已清除输入；数据请求另行处理 |
| 授权/epoch 改变或注销 | 普通处理停止；新维护上下文终结元数据、拒绝未接纳结果及按策略清理 | 不刷新旧任务 epoch，不恢复私人输入或结果 |
| 来源改变而资格仍有效 | origin 拒绝为 REJECTED_STALE，保持 SUCCEEDED 历史 | 新输入由 origin 固定，旧结果不覆盖 |
| 持久结果事件消费失败 | 留在单一事件登记中待重投；origin 可受限查询恢复 PENDING | 不重复生成候选、不重新调用供应商、不自动确认 |

调用前检查与外部发出之间存在不可完全消除的撤回竞争窗口；V1 不跨网络持锁。当前资格拒绝时不再发出新请求；已经发出的请求尽力取消，并拒绝其返回写入。此限制在用途说明/第三方进度中如实表达。
