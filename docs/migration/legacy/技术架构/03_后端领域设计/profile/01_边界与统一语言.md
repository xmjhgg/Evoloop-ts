## 1. 职责概述

本域回答“此人目前有哪些规划条件，哪些身体观测是真实保存的”。保存常规作息、可用时间、健身基础与器材、学习基础与资源、长期限制的版本；唯一保存身体测量及日级疲劳、精神、不适事实。支持分步补充、补记、纠正、普通误记删除，以及 identity 发起的隐私导出/删除处理。

条件是用户自述的规划依据，不是目标或具体安排。身体观测是带实际观测时间的事实，不是医学诊断。保存条件/事实独立成功，后续结论分析失败不回滚。资料变化通过版本和事件告知使用者，不能在本域生成或发布计划。

| 内容 | 唯一所有者 | profile 的行为 |
| --- | --- | --- |
| 常规入睡/起床、班次、每周可用时间、器材、基础、资源、长期限制 | profile | 保存条件分区修订，提供相关投影 |
| 体重、身高、围度的实际测量及日级身体状态 | profile | 保存事实身份、时间、单位及纠正历史 |
| 最新体重摘要 | profile 查询投影 | 返回原测量 ID/修订及时间；条件表不另存体重值 |
| 某次训练后的感受 | execution | 不提供同名保存入口，不复制训练正文 |
| 实际睡眠起止、质量、时长 | execution | 常规作息不生成实际睡眠 |
| 目标体重、健身方向、未来训练/饮食/睡眠目标 | planning | 仅提供相关条件与身体事实引用 |
| 健身适用性、明显不适对应的任务限制及计算策略 | planning | 提供用户报告证据；规则不在 profile 复制 |
| 日结论、周复盘、确认与调整依据 | review | 提供事实及范围 token，不建身体专用复盘 |
| 账户、用途授权、导出/删除总进度 | identity | 执行本域阶段并返回真实回执 |
| AI 调用、供应商任务 | ai | 本域 V1 无 AI 任务；其他业务域自行组织合法输入 |

## 2. 上下游与依赖

允许编译依赖 `identity::api`、最小 `shared`。`ProfileApi` 和两个集成事件置于本域 `api` 命名接口；domain 仅使用纯 Java 类型。公开结果是不可变快照，禁止返回聚合/JPA 实体。profile 不导入 planning、execution、review 或 ai 实现；这些模块通过本域公开查询读取证据。

| 协作者 | 读取或交互 | 一致性责任 |
| --- | --- | --- |
| identity | `checkProcessing`、`lockProcessingFence`、`DataRequestCreated`、阶段回执 | 身份/用途/删除状态由 identity 核验；本域所有短写先取得用户栅栏 |
| planning | `getConditions`、`getBodyFacts`、`getSourceTokens`；订阅 `ProfileConditionsChanged` / `BodyObservationChanged` | 草案相关依据变化需复核；已生效安排保持；限制评估直接查当前证据，不等待事件或 AI |
| review | 同上查询；订阅身体/条件事件 | 新事实、补记、纠正、删除使相关日周来源失效；既有确认最新性不能仅依赖事件 |
| workspace | 本人条件、最新测量、指定日状态批量查询 | 我的与今日复用同一事实；页面不能补建第二份体重或身体状态 |
| 数据请求执行装配 | 服务器受限 ProcessingContext 调用本域处理器 | 每域处理自身正文、历史和持有快照；总状态仍由 identity 聚合 |

```mermaid
flowchart LR
    I[identity 资格与栅栏] --> P[profile 条件与身体事实]
    P -->|公开快照 / refs / scopeTokens| L[planning 规划与限制]
    P -->|公开身体事实 / scopeTokens| R[review 共享结论]
    P -->|同一事实查询| W[workspace 今日 / 我的]
    P -->|本域阶段回执| I
```

箭头表示运行时协作，不表示 profile 编译依赖下游模块。风险反馈的成功响应只说明身体事实已保存并提供证据引用；关联任务限制由 planning 的查询/评估负责。异步通知可加速刷新，不能成为限制是否生效的唯一依据。

## 3. 统一语言

| 术语 | 定义 / 类型 | 易混淆概念 / 来源 |
| --- | --- | --- |
| PersonalProfile（个人条件根） | 每个用户一个稳定根，协调 COMMON、FITNESS、LEARNING 三个分区的当前修订 | 不是账户、目标或健康档案的第二份事实；BR-COM-008 |
| ConditionSection（条件分区） | COMMON 通用条件、FITNESS 健身条件、LEARNING 学习条件，各有独立版本与当前修订 | 不按目标复制条件；多个健身目标引用同一分区 |
| ConditionRevision（条件修订） | 保存时成立的不可变分区内容，包含完整分区快照、修订号及保存时间 | 不是“某日已经生效的计划”；不允许回填保存时间 |
| RoutineSleepWindow（常规作息） | 用户常规睡眠窗口，上海本地时间与跨午夜偏移、班次说明 | 实际睡眠归 execution；BR-COM-008 |
| AvailabilityWindow（可用时间窗） | 周几、起止本地分钟及跨日偏移；窗口代表可以安排的条件 | 与 planning 的具体计划时段不同；V1 不自动跨目标排程 |
| ModuleResource（模块资源） | 用户自述可用器材/场地或书籍/课程/其他学习资源 | 是资料，不是器材库存或课程平台接入 |
| LongTermRestriction（长期限制） | 用户报告的长期训练/饮食/资源/时间限制及说明 | 与每日不适、临床诊断、planning 的阻断规则分开 |
| BodyMeasurement（身体测量） | 一次实际观测的稳定 factId，可含多项 kg/cm 测量值 | 同一次观测多目标按引用复用；另一日期的测量是另一个事实 |
| MeasurementValue（测量值） | 指标、围度部位、数值、单位 | 无数值不能伪造测量；目标值属于 planning |
| DailyBodyState（日级身体状态） | 一人一归属日一个当前状态事实，包含用户自述疲劳/精神/不适、观测时间和修订 | 某次训练后的感受归 execution；身体状态可以独立于计划存在 |
| 未知 | 未填写/未观测，显式 `UNKNOWN`；无法据此判为无疲劳/无不适 | 数值缺项不填 0；状态 UNKNOWN 不等于 NONE；BR-COM-010、BR-FIT-013 |
| 普通误记删除 | 当前事实转 REMOVED，追加无身体正文的删除修订；不参与当前查询，保留正常纠正追溯 | 不等于隐私物理清理；BR-COM-018 |
| SourceReference（对象引用） | `ownerModule,objectType,objectId,revisionId,version` | 已有对象引用不能检测范围内新增事实 |
| SourceScopeToken（范围版本） | 条件分区或身体归属日的单调版本 | 用于发现新增/纠正/删除，不替代授权版本或 deletionEpoch |

## 4. 分区、用途与最小必要

identity 定义 `ACCOUNT_ACCESS`、`HEALTH_DATA`、`FOOD_IMAGE`、`AI_PROCESSING`；profile 不自建授权枚举。

| 操作 / 投影 | 需要的用途 | 内容限制 |
| --- | --- | --- |
| 学习条件、普通可用时间、资源限制 | ACCOUNT_ACCESS | LEARNING 查询只返回 COMMON 可用时间与学习条件，不返回常规睡眠、身体或健身限制 |
| 常规睡眠作息、健身条件、身体观测 | ACCOUNT_ACCESS + HEALTH_DATA | 仅处理对应本人资源范围；无健康资格时不能用内部查询绕过 |
| planning/review 准备发往 AI 的本域来源 | 上述适用用途 + 由调用方核验 AI_PROCESSING | 本域只返回请求范围，AI 数据选择和调用由所属业务域负责 |
| 隐私导出/删除执行 | identity 发给 profile 的受限数据请求上下文 | 限请求本人、范围、operation、版本与时效；不需要用户重新同意处理已请求删除的数据 |

COMMON 中作息和可用时间采用组件级修改掩码及不可变组件引用：COMMON 修订只保存 RoutineSleepRevision 的 ID；只改可用时间复用既有 ID，不读取、复制或修改作息正文。作息新增、清空或变更需要 HEALTH_DATA，变更时建立新的作息组件修订。学习查询不 JOIN 该组件表，学习写入只接受学习字段；不因健康字段缺失拒绝学习。用途撤回与删除是不同操作；限制生成/展示按 identity 处理资格执行，资料不由 profile 擅自自动删除。

## 5. 视图、历史与设计范围

我的的最新身体指标由身体事实读模型按实际 `observedAt` 降序选取仍有效的测量项，返回 factId/revisionId/单位/时间。补记较早测量不覆盖较晚观测；纠正或删除当前最新项后重新选择。排序相同时间时按 factId 确定显示顺序，不宣称两个同值事实必然重复。重复提交由幂等处理；用户明确两次观测可以具有相同时间和值。

日身体状态以稳定事实 ID 编辑，今日/我的/历史入口必须查询同一身份。归属日由实际观测时间换算上海日期；补记保存时间与观测时间分别记录。更改日期属于事实纠正，需要原事实 expectedVersion，新日期已占槽则返回冲突，不静默覆盖或合并。

条件历史查询以服务器保存时间追溯“当时知道的条件”，不提供回填已生效条件。未来规划取当前条件，不把未来计划日期当作条件生效历史。领域不提供医学阈值、营养计算、诊断、资料保留期限或供应商选择；这些待决事项见 [05](05_用例与测试追溯.md)。
