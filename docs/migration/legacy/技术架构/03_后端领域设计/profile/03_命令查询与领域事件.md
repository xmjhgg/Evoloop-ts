## 1. 共同请求协议

路由 `/api/v1/profile/*`。服务端从会话生成 ActorContext；HTTP 不接受 userId 授权。本人未找到或非本人对象均返回 404，不暴露是否属于他人。所有写操作需 `Idempotency-Key`，服务端取得 requestId；公共 `sys_command_receipt` 的键为 `(user_id,operation,request_id)`，相同键与摘要重放同业务结果，同键不同摘要返回 409 IDEMPOTENCY_CONFLICT。权限/删除状态必须在重放前核验，不能以成功回执绕过撤回或删除。

每个写用例在 READ COMMITTED 短事务中依次：identity 用户栅栏 → 公共幂等记录 → 本域根/分区或事实及槽 → 范围版本 → 持久事件登记。调用 `IdentityApi.lockProcessingFence` 核验 ACCOUNT_ACCESS、适用 HEALTH_DATA、resourceScope、authorizationVersion（提供时）和 deletionEpoch。后台也使用服务器创建、限定 ownerModule/operation/scope/purposes/时效的 ProcessingContext；不能伪装用户保存。无网络调用占用事务。

公共幂等 operation 命名为 `profile.condition.edit`、`profile.measurement.create/correct/remove`、`profile.body-state.create/correct/remove`，后两组斜线分别代表独立操作代码。结果查询只接受本域允许列表及本人requestId，不提供任意公共回执检索。后台数据请求按identity请求ID及本域work唯一约束恢复，不借普通用户写回执恢复被删除事实。

成功创建 201，更新/删除/查询 200。profile 本域无 AI 异步创建；导出/隐私删除 HTTP 入口在 identity，受理为 202 不代表本域清理完成。`expectedVersion` 是可变根版本，不是 revisionNo；PersonalProfile 初次创建 expectedVersion=0，事实创建不接受已有 factId。DECIMAL 数值返回字符串并显式单位，时间带 Z，businessDate 使用上海 DATE。

## 2. HTTP API 清单

| HTTP / 路由 | 输入 | 输出 / 用途 / 用例 |
| --- | --- | --- |
| GET `/conditions?category=FITNESS\|LEARNING&mode=CURRENT_FOR_PLANNING\|HISTORICAL_AT&applicableAt=...` | 类别；历史模式带 UTC 时间，禁止未来历史时间 | `ConditionSnapshot`；200，未填分区 NOT_PROVIDED。学习 ACCOUNT_ACCESS；健身包含作息需 HEALTH_DATA。UC-COM-006 |
| PATCH `/conditions/{section}` | COMMON/FITNESS/LEARNING；expectedVersion、updateMask、匹配组件值、可选 changeReason | `profileId,profileVersion,sectionVersion,revisionId,changed,sourceTokens,impactHint`；初次根创建 201，后续 200。UC-COM-006 |
| GET `/measurements?fromDate=...&toDate=...&metricType=...&cursor=...&limit=...` | 有限日期范围、可选类型；按 observedAt/factId 游标 | 当前有效测量、分页信息、范围 token；HEALTH_DATA。UC-FIT-011 |
| GET `/measurements/latest?metricType=...&site=...&asOf=...` | 指标/围度部位；asOf 实际观测截止可选 | 同一个原测量引用或 `value:null,knowledge:UNKNOWN`；不创建资料测量。UC-COM-006-AC-03 |
| GET `/measurements/{factId}?revisionId=...` | 当前或本人历史修订；历史修订仍提供当前根状态 | 测量快照及 currentVersion/currentStatus；已隐私清理则 404。UC-FIT-011 |
| POST `/measurements` | observedAt、businessDate、values[]、可选 note | 201，稳定 factId/version=1/revisionId、values、tokens。支持补记过去观测。UC-FIT-011 |
| PUT `/measurements/{factId}` | expectedVersion、完整 observedAt/businessDate/values、correctionReason | 200，新修订、旧/新日期及 tokens；不修改历史计划。UC-FIT-011 的纠正技术分支 |
| POST `/measurements/{factId}/remove` | expectedVersion、reason | 200，REMOVED 新修订、影响日 token；普通误记删除，不是隐私清理 |
| GET `/body-states?fromDate=...&toDate=...` | 有限上海日期范围 | 当前状态或逐日 NOT_RECORDED、范围 tokens；HEALTH_DATA。UC-FIT-011 |
| GET `/body-states/{factId}?revisionId=...` | 当前/本人历史修订 | 日状态快照及当前版本/状态 |
| POST `/body-states` | observedAt、businessDate、fatigue、mental、discomfort、可选 note | 201；同日已占槽 409，返回本人现有 factId/version。UC-FIT-011 |
| PUT `/body-states/{factId}` | expectedVersion、完整状态/时间/日期、correctionReason | 200，新修订；日期变更必须取得目标空槽 |
| POST `/body-states/{factId}/remove` | expectedVersion、reason | 200，REMOVED，释放日期槽并递增日 token |
| GET `/write-results/{operation}/{requestId}` | 本人已知 operation/requestId | 公共幂等查询投影；成功结果再次受权限/删除范围过滤；未知返回 404，不能解释为原写一定未提交 |

`limit` 默认 50、最大 200 是查询保护技术约定，不是产品或健康阈值；日期范围最大 366 日，长历史分段查询，确认/来源验证必须完整收集所需范围 token，不能拿分页的部分事实冒充完整覆盖。只查询状态不意味着当日测量已登记。

### 2.1 条件编辑组件

| 分区 | updateMask 可选组件 | 完整组件结构 / 清空语义 |
| --- | --- | --- |
| COMMON | availability、routineSleep | availability 为 `{state,windows[]}`；routineSleep 为 `{state,bedtimeMinute,wakeMinute,wakeDayOffset,shiftNotes}`。选中后 null 表示清为 UNKNOWN；未选中保持，不让学习条件编辑隐式清掉作息 |
| FITNESS | availability、foundation、resources、restrictions | foundation 为 `{trainingFoundation,venueDescription}`；resources 为 `{state,items:[{type,name,description}]}`；restrictions 为 `{state,items:[{kind,description}]}`。仅健身类型资源/限制 |
| LEARNING | availability、foundation、resources、restrictions | foundation 为 `{description}`；resources 同样带 state/items，资源 BOOK/COURSE/OTHER、限制 TIME/RESOURCE/OTHER；不接受健康/饮食/训练字段 |

mask 非空、无重复；载荷未被 mask 选中的字段拒绝为 422 UNSELECTED_COMPONENT，避免忽略输入造成误判。每个组件整体替换，缺失状态必须明确 UNKNOWN；未知不自动等于 NONE。COMMON 修改 routineSleep 需要 HEALTH_DATA，单改 availability 仅需 ACCOUNT_ACCESS。COMMON 修订只引用不可变 RoutineSleepRevision；未选择作息时复用引用，不读取/复制健康正文，学习查询不 JOIN 该组件表。

```json
{
  "expectedVersion": 4,
  "updateMask": ["availability"],
  "availability": {
    "state": "RECORDED",
    "windows": [{"weekday": 1, "startMinute": 1140, "endMinute": 1200, "endDayOffset": 0}]
  },
  "changeReason": "周一改为 19:00 有空"
}
```

对应响应示意（UUID 由服务器生成）：

```json
{
  "profileId": "0e5d9405-f96f-4e8b-a0db-91ddb43eb805",
  "profileVersion": 5,
  "section": "COMMON",
  "sectionVersion": 3,
  "revisionId": "2fae4f23-bc78-4e85-98b6-b4a05fcfb6cf",
  "changed": true,
  "sourceTokens": [{"ownerModule": "profile", "scopeType": "CONDITIONS", "scopeKey": "COMMON", "version": 3}],
  "impactHint": "RELATED_DRAFTS_REQUIRE_RECHECK"
}
```

impactHint 是确定的协作提示，不声称已枚举受影响草案，也不包含计划已经调整的信息。完整草案影响列表由 workspace 调 planning 公开查询取得。

## 3. 公开 ProfileApi 与 DTO

方法属于 `com.evoloop.profile.api`，应用层实现；以下为设计签名，不表示源码已建立。

```text
getConditions(AccessContext actor, GoalCategory category, ConditionTime applicableAt)
  -> ConditionSnapshot
getBodyFacts(AccessContext actor, BodyFactSelector selector, Instant observedThrough)
  -> BodyFactSnapshotSet
getSourceTokens(AccessContext actor, ProfileScopeQuery query)
  -> SourceTokenSnapshot
```

`AccessContext` 仅接受服务端 ActorContext 或受限 ProcessingContext。确认/发布/AI 接纳调用发生于调用方已经取得用户栅栏的本地短事务，本域查询加入事务，不另开事务或锁 ai。普通本人读取先 `checkProcessing`，短暂最终一致允许；标注最新来源快照则在一次持栅栏事务采集所有源域 token。跨域调用无 HTTP 回环。

| DTO | 字段与语义 |
| --- | --- |
| ConditionTime | `CURRENT_FOR_PLANNING` 不带未来计划时间；`HISTORICAL_AT(instant)` 按 savedAt 追溯，当时未保存的分区 NOT_PROVIDED。历史内容不得当当前发布依据 |
| ConditionSnapshot | `profileId?、profileVersion、category、mode、readAt、sections[]、refs[]、scopeTokens[]`；sections 是 COMMON + 所选类别；每段 `sectionId?,version,revisionId?,savedAt?,knowledge,availability,typedModuleConditions,restrictions,privacyRedactedAt?`。FITNESS 可含 routineSleep 及其 componentRevisionId；LEARNING 不返回 routine字段/知识状态/组件ID且不加载作息组件。历史version对应引用修订的分区版本，另给currentVersion |
| SourceReference | `ownerModule=profile,objectType=CONDITION_SECTION/BODY_MEASUREMENT/DAILY_BODY_STATE,objectId,revisionId,version`；条件 version 为分区版本而非 PersonalProfile根版本；未提供分区无 ref，token 仍返回逻辑 0；作息组件 revisionId 由 COMMON修订固定引用，无需读取健康正文即可保留该引用 |
| BodyFactSelector | 二选一：`DateRange(fromDate,toDate)`；`FactRefs([{factType,factId,revisionId?,originalBusinessDate?}])`。明确 CURRENT / HISTORICAL_REVISION 解析模式；refs 请求若要验证集合完整性还须另传完整日期范围 |
| BodyFactSnapshotSet | `readAt,observedThrough?,measurements[],dailyStates[],missingOrRemovedRefs[],refs[],scopeTokens[]`；按 factId 去重。截止是实际观测截至，不隐瞒后来纠正/补记；新补记仍递增当日 token |
| BodyMeasurementSnapshot | `factId,version,revisionId,revisionNo,status,observedAt,businessDate,savedAt,values[],note?`；历史解析附 `currentVersion/currentStatus`。每值明确 metric/site/value/unit |
| DailyBodyStateSnapshot | 与测量的身份/时间字段相同；`fatigue,mental,discomfort,note?`；UNKNOWN 原样保留，不转 false/0 |
| ProfileScopeQuery | `conditionSections[]` 与 `dateRange?` / `bodyDates[]`；token 查询按请求范围用途核验，限制数目与 HTTP 一致 |
| SourceTokenSnapshot | `readAt,tokens[]`，每项 `ownerModule=profile,scopeType,scopeKey,version`；不存在范围仍返回 0，不能漏项 |

getConditions CURRENT 返回 COMMON + 类别的当前分区 token；HISTORICAL_AT 返回历史 refs，同时仍给当前 token 并明确 `isHistorical=true`，防止历史内容被误当最新审查依据。历史可信追溯使用明确 revisionId，而不是重新将实际时间推导为当时资料。

历史正文被隐私删节时 `privacyRedactedAt`/`unavailableComponents` 明确 HEALTH_COMPONENT_ERASED；不能把保留的可用时间投影当原始完整健康来源。个人根 version 为当前编辑版本；对象 ref.version 为所引用修订对应的对象版本（本域通常等于 revisionNo），历史当前版本单独输出，不能混用。

getBodyFacts 日期范围返回每个日期 token，包含无观测日；纠正跨日使两日 token 变化。按事实引用查询返回原/现日期 token，并标明并非完整集合查询。已隐私清理的旧修订不可返回；返回 SOURCE_UNAVAILABLE 供消费方按其删除策略清理派生来源，不能从事件载荷恢复正文。

学习投影只读 COMMON 可用时间 + LEARNING 分区。COMMON token 保守覆盖作息变化，可能多触发一次学习草案复核；来源正文不泄露健康字段。授权版本/epoch 由 identity 返回，不混装成 profile token。

## 4. 错误与恢复

统一错误 `{code,message,requestId,details}`。details 仅含本人字段位置、日期、当前版本或需要的用途，不含他人信息。

| 状态 / code | 触发 | 恢复 |
| --- | --- | --- |
| 401 UNAUTHENTICATED | 会话不存在/失效 | 恢复本人会话后查询已有结果 |
| 403 PROCESSING_DENIED / PURPOSE_REQUIRED / DATA_SCOPE_RESTRICTED | identity 账户、用途、请求范围限制 | 返回用途/范围原因；学习无关范围保持可用 |
| 404 PROFILE_FACT_NOT_FOUND / SOURCE_UNAVAILABLE | 本人范围无对象、引用已物理清理 | 刷新来源；不得从旧快照回写 |
| 409 VERSION_CONFLICT | expectedVersion 与当前根不匹配 | 返回 currentVersion，用户合并后新请求，不覆盖 |
| 409 IDEMPOTENCY_CONFLICT | 相同键不同规范化输入 | 修正请求键或恢复原输入 |
| 409 BODY_STATE_DAY_OCCUPIED | 创建/纠正目标日期已有另一当前状态 | 返回本人现有 factId/version；显式选择编辑该事实，不自动合并 |
| 409 FACT_REMOVED | 已普通删除事实再次纠正 | 展示已删，不恢复；重新记录新的观测 |
| 409 SOURCE_STALE | 消费者提交的 refs/token 已变化 | 重新采集，更新审查/结论；本域不擅自发布 |
| 422 INVALID_UNIT / INVALID_MEASUREMENT / EMPTY_MEASUREMENT | 单位/正数/指标部位/存储精度不合法 | 指明 values[index].field，无医学判定 |
| 422 DATE_TIME_MISMATCH / FUTURE_OBSERVATION | businessDate 与上海日期不一致或观测晚于当前 | 用户核对实际时间，保留未保存输入 |
| 422 EMPTY_BODY_STATE / INVALID_KNOWLEDGE_STATE | 全部未知或知识状态与内容冲突 | 补充/修正自述字段，不推算 |
| 422 FIELD_NOT_APPLICABLE / UNSELECTED_COMPONENT | 学习带健康字段、mask 不匹配、窗口非法 | 返回组件字段路径，保存正确分区 |

死锁/瞬态数据库失败由基础设施有限重试相同 requestId；业务版本冲突不自动覆盖。普通误记删除无恢复命令；重复相同删除请求重放原成功结果，新的删除请求对 REMOVED 返回 200 changed=false，不增加版本/token。

## 5. 核心流程时序

### 5.1 保存条件与未来计划复核

```mermaid
sequenceDiagram
    actor U as 用户
    participant H as ProfileHandler
    participant I as IdentityApi
    participant C as 公共幂等设施
    participant P as ProfileRepository
    participant E as 持久事件登记
    participant L as planning / review
    U->>H: PATCH 分区 + mask + expectedVersion + 幂等键
    H->>I: lockProcessingFence(适用用途/范围)
    I-->>H: 账户资格 / 授权版本 / deletionEpoch
    H->>C: 锁请求回执并校验摘要
    alt 已提交相同请求
      C-->>H: 返回仍有资格查看的原业务结果
    else 首次请求
      H->>P: 锁个人条件根并核对 version
      H->>P: 合成完整分区 / 追加修订 / 更新指针
      H->>P: 同事务递增 CONDITIONS 分区 token
      H->>E: 登记 ProfileConditionsChanged
      H->>C: 保存成功回执
      H-->>U: 提交后响应版本与复核提示
      E-->>L: 至少一次通知依据变更
      L->>P: 通过 ProfileApi 查当前 token
      Note over L: 标记相关草案/审查需复核，原生效计划保持
    end
```

若只作无变化保存，返回 changed=false，既不追加修订也不发变更事件。调用下游失败发生在提交之后，不回滚条件；最终发布通过 token 核验仍能识别资料变化。

### 5.2 补记/纠正身体观测

```mermaid
sequenceDiagram
    actor U as 用户
    participant H as BodyObservationHandler
    participant I as IdentityApi
    participant P as 本域仓储及日期槽
    participant E as 持久事件登记
    participant R as review
    participant L as planning
    U->>H: 保存过去观测或按 factId 纠正
    H->>I: lockProcessingFence(ACCOUNT_ACCESS + HEALTH_DATA)
    H->>H: 公共幂等 / 本人归属 / expectedVersion
    H->>P: 锁事实；日状态再按日期排序锁原/新槽
    alt 目标日期已有另一日状态
      P-->>H: BODY_STATE_DAY_OCCUPIED
      H-->>U: 409；事务无变化
    else 合法
      H->>P: 追加修订 / 更新当前投影及槽
      H->>P: 递增原/新 BODY_DAY token
      H->>E: BodyObservationChanged(引用与范围)
      H->>H: 保存幂等结果并提交
      H-->>U: 事实保存成功及来源引用
      E-->>R: 更新受影响日/周来源状态
      E-->>L: 身体证据变化提示
      L->>P: ProfileApi 直接读当前不适/限制证据
      Note over L: 限制评估不等待 AI，不修改历史基准
    end
```

身体事实不以某个计划为必填，因此本域不调用 planning.protectBaseline；那是有计划的 execution 事实保存协作。条件与身体事实为不同命令，客户端连做两项须显示各自真实保存结果，不能宣称二者天然原子提交。

### 5.3 普通误记删除与隐私清理

普通删除在相同事务协议中追加 REMOVE 修订、释放日状态槽、递增 BODY_DAY、登记变更、提交回执。隐私清理消费 DataRequestCreated 后先核验受限上下文，按请求范围分批物理清理正文及历史/持有的引用清单；每批先栅栏，提交清理进度和 token/必要事件，再在事务外处理导出产物，向 identity 返回真实阶段状态。旧任务因 epoch/范围与最新来源复核不能恢复已清理内容。

## 6. 领域事件与集成事件

内部纯 Java 事件：`ConditionSectionSaved`、`MeasurementRecorded/Corrected/Removed`、`DailyBodyStateRecorded/Corrected/Removed`；基础设施按同一事务映射到下列公开集成事件，不为同一次事实再发重复累计事件。

| 公开事件 / schemaVersion | 载荷（除共同信封） | 订阅者 / 行为 |
| --- | --- | --- |
| ProfileConditionsChanged / 1 | `profileId,sectionId,section,oldRevisionId?,newRevisionId?,changeKind,sourceTokens` | planning 使相关当前草案审查待复核；review 核验使用该条件的当前判断。清理时 newRevisionId 可空，不带条件正文 |
| BodyObservationChanged / 1 | `factType,factId,revisionId?,changeKind=CREATED/CORRECTED/REMOVED/PRIVACY_ERASED,oldBusinessDate?,newBusinessDate?,sourceTokens` | review 标记影响日及周来源；planning 更新证据提示，限制读当前快照。隐私清理不传播原身体数值/不适正文 |

共同信封完整字段：`eventId,eventType,schemaVersion,occurredAt,ownerModule=profile,userId,aggregateId,aggregateVersion,requestId,affectedScopes,payload`。普通删除 aggregateVersion 为新根版本；物理清理事件引用清理批次及最后已知版本，不能要求被删除根仍存在。载荷不含完整身体资料、学习资料或数值，消费者通过公开 API 受资格控制读取。

采用 ADR-002 的单一持久事件登记；不另建 profile outbox。消费至少一次，公共 `(consumer,event_id)` 去重与本域业务变化同事务。乱序不回退本地已见版本；一次事件重复不导致重复事实/重复统计。事件暂未消费仍通过范围 token 检查拒绝过期审查/确认/AI 接纳；恢复补偿通过当前 token/公开查询完成，不能重放正文复活删除事实。

profile 消费 `DataRequestCreated` 执行本域范围处理；授权/账户事件仅用于取消待处理工作或刷新缓存，最终读写资格以 identity 实时核验为准。profile 不自行存一份授权/账户状态。
