# identity：边界与统一语言

| 项目 | 内容 |
| --- | --- |
| 版本 / 日期 / 状态 | v1.1 / 2026-10-13 / 详细设计工作版 |

## 1. 职责及所有权

本域回答：当前操作者是否是本人；本次用途和范围是否允许处理；数据请求完成到哪一阶段。拥有微信及密码身份到内部 userId 的关联、账户生命周期、可撤销会话、用途说明及决定快照、账户级授权版本与隐私 epoch、数据请求范围及阶段回执、导出包元数据和注销进度凭据。首次登录不创建资料、目标或计划，也不自动授权健康、图片或 AI。

不拥有身体、条件、目标、计划、实际、结论、AI 任务或食物图片正文。数据请求通知所有持有者，各所有者判断事实、修订、快照、衍生内容及文件关联的处理闭包并回执。identity 汇总进度，不反向导入业务仓储逐域删表。

## 2. 统一语言

| 术语 / 类型 | 定义 | 区分与来源 |
| --- | --- | --- |
| UserAccount / 本人账户 | 稳定 userId、账户状态、version、authorizationVersion、deletionEpoch 的根 | 微信 openId 不是 userId；UC-COM-001/005 |
| WeChatIdentity / 微信关联 | 服务端兑换出的 appId + openId 与 userId 的关联 | 客户端 openId/userId 不可信；UC-COM-001 |
| PasswordIdentity / 密码身份 | 规范用户名、BCrypt 哈希、状态及版本与 userId 的关联 | 2026-10-13 用户确认的账号增量；用户名不是 userId；不伪造 WeChatIdentity |
| 管理员账号命令 | 服务器本机创建新密码账户或重置已有密码 | 受服务器管理权限保护，不是用户注册、用途同意或账户恢复 |
| UserSession / 会话 | 服务端随机凭据对应的可到期、撤销记录 | 登录与用途同意不同；UC-COM-001 |
| ActorContext | 服务端会话解析出的 userId、sessionId、最近核验时间 | HTTP 不接受客户端构造；BR-COM-001 |
| ProcessingPurpose / 用途 | 本域四个用途代码及适用能力 | 不自动扩大范围；UC-COM-002 |
| AuthorizationGrant / 授权 | 单个可选用途的当前决定及不可变历史 | 某用途同意不代表其他用途；BR-COM-002 |
| PurposeNotice / 用途说明 | 范围、处理方、期限/政策、影响能力及 noticeVersion 告知快照 | 说明更新不自动扩权；UC-COM-002 ALT-02 |
| authorizationVersion | 账户所有用途决定的单调全局版本，初始 0 | 不等于聚合 version、noticeVersion 或单用途 revisionNo |
| deletionEpoch | 撤回、指定删除、注销时递增的隐私栅栏计数 | 重新同意不回退；撤回也递增 |
| ResourceScope | 模块、数据类别、对象/日期与衍生范围描述 | 用数据语义表达，不用页面名 |
| ProcessingContext | 服务器签发的限用途、操作、范围 worker 上下文 | 无用户确认权，不是可自我续期的授权 |
| ProcessingFence / 栅栏 | 账户根行事务锁及锁内再次核验 | 一次 checkProcessing 通过不授予未来写入权 |
| DataRequest / 数据请求 | EXPORT、DELETE、CLOSE_ACCOUNT 及冻结范围/阶段矩阵 | 受理不等于完成，归档不等于删除 |
| ScopeSelection / 选择范围 | 用户选定模块、数据类别、日期/对象和图片范围 | 不默认全量；删除包括相关衍生副本 |
| RequestStage / 阶段 | 请求、所有者、阶段的一项真实工作 | 数据库、文件、供应商、备份独立回执 |
| StageReceipt / 回执 | 单调 receiptVersion、阶段结果和证据引用 | 重复相同内容幂等，同版本不同内容冲突 |
| ExportFragment / 片段 | 所有者导出的本人片段、版本清单和真实 snapshotAt | 组合快照不假称全域同一时刻 |
| ExportArtifact / 产物 | identity 导出包的对象引用、摘要、到期与状态 | 不是永久公开 URL，下载须核 epoch |
| RequestProgressCredential | 注销后只查询单个请求的随机凭据 | 不恢复会话或正文访问 |
| ResidualItem / 未完成项 | 供应商、备份或政策未落实等结构化残留 | 不能隐藏于“成功”；BR-COM-018 |

## 3. ProcessingPurpose 权威代码

| 代码 | 定义与资格 | 典型场景 |
| --- | --- | --- |
| `ACCOUNT_ACCESS` | 本人非敏感基础管理的账户资格；不保存可选 grant | 登录、人工学习计划/记录、用途管理；权利请求另有专用资格 |
| `HEALTH_DATA` | 告知范围内健康相关数据本地存储、读取与输入准备；当前 GRANTED | 身体、训练、睡眠、摄入、健身条件与计划 |
| `FOOD_IMAGE` | 用户选定食物图片上传、存储、读取/处理；GRANTED 且有具体选择证据 | 食物图片上传分析，不能后台扫描相册 |
| `AI_PROCESSING` | 向告知处理方发送本次最小输入及接纳候选；当前 GRANTED | 生成、审查、复盘、图片理解 |

学习文本 AI：ACCOUNT_ACCESS + AI_PROCESSING；健身文本 AI 另加 HEALTH_DATA；食物图片 AI 另加 FOOD_IMAGE。人工健身不要求 AI_PROCESSING，手动饮食不要求 FOOD_IMAGE，纯学习不要求 HEALTH_DATA。拒绝 AI 仍可手工闭环。健康用途撤回后普通健康读写受限，本人仍可管理授权、导出/删除已有内容和查看请求；这是 V1 保守资格设计，告知与保留政策按 TBD-003 评审。

ACCOUNT_ACCESS 不代替敏感授权。可选用途无 grant 时为 UNSET；UNSET、DENIED、WITHDRAWN 均不通过对应用途。供应商改变、目的扩大、期限改变需新 noticeVersion；旧同意只适用于旧说明，必要时 NOTICE_RECONSENT_REQUIRED。各领域直接引用 `identity.api.ProcessingPurpose`，不得自建枚举。

## 4. 最小 ProcessingContext

字段为 `contextId, contextKind, userId, ownerModule, operation, resourceScope, purposes, expectedAuthorizationVersion, expectedDeletionEpoch, taskId?, dataRequestId?, businessRequestId, issuedAt, expiresAt`。上下文经已有 ActorContext 或受信模块身份向 identity 签发；不能从 HTTP 字段解析为可信类型，不含微信原凭据或供应商秘密。

| contextKind | 资格与限制 |
| --- | --- |
| BACKGROUND_TASK | 指定任务范围；账户 ACTIVE、用途与双版本匹配；绝无用户确认权限 |
| DATA_REQUEST_WORKER | 只处理已受理请求冻结范围；删除/注销在 CLOSING/CLOSED 可清理残留，不得创建普通事实/计划/结论 |
| STAGE_REPORTER | 只回执获分配的本模块阶段；CLOSING/CLOSED 可报进度，无正文访问权 |
| BACKGROUND_MAINTENANCE | ACTIVE/CLOSING/CLOSED 可对本模块指定旧资源取消任务、拒绝结果、释放租约、记录无正文失败元数据或清理持有内容；不读/生成正文、不接纳、不确认 |

删除恢复可重新签发匹配当前 epoch 的专用上下文，不为旧普通 AI 任务更新 epoch。导出上下文要求请求 acceptedEpoch 等于当前 epoch，变化即失效。ResourceScope 包含 `ownerModules, dataClasses, businessDateRange?, objectRefs[], includeImages, includeDerived`，引用为 `ownerModule/objectType/objectId/revisionId?`。所有者按 userId 查询；引用不存在或非本人不授予访问。

时间点 UTC；businessDate 是 Asia/Shanghai 日期。空范围拒绝，未指定范围不默认全用户。活跃 DELETE/CLOSE_ACCOUNT 范围相交的普通读取、生成输入和写入受限，未相交范围可继续；EXPORT 不冻结一般写入。导出每域短栅栏固定 ID/修订选择清单，随后分批读取不可变修订，显式组合采集区间。全局 epoch 使旧 AI 与旧导出保守失效，完整版本最终核验在短事务栅栏内完成。

旧 BACKGROUND_TASK 被拒绝后，identity 可给服务器受信资源所有者重新签发匹配当前 epoch 的 BACKGROUND_MAINTENANCE，用于终结/清理。维护上下文不要求已撤回用途仍 GRANTED，不能把旧任务升级为新的可接纳任务，不能用于任意业务状态修改。具体操作白名单见 03。

## 5. 协作边界

| 协作方 | 核验用途/资格 | 数据请求义务 |
| --- | --- | --- |
| profile | 身体/健身条件和 RoutineSleepRevision 作息正文 HEALTH_DATA；availability/学习条件 ACCOUNT_ACCESS，按实际字段作用域核验 | 条件、观测、历史与范围版本；不复制健康正文到学习视图 |
| planning | 对应类别基础用途，AI 加 AI_PROCESSING | 目标、草案/发布修订、审查、引用快照 |
| execution | HEALTH_DATA/FOOD_IMAGE/AI 按实际输入并集；学习 ACCOUNT_ACCESS | 事实、修订、图片、草案、营养快照及汇总 |
| review | 对应输入用途并集 | 日周结论、确认、人工内容与来源副本 |
| ai | 实际任务用途及双版本 | 取消任务、输入/结果/尝试、供应商残留 |
| infrastructure | 受信模块专用工作资格 | 共享幂等、持久事件正文、临时产物、平台备份 |

七方包括 identity 自身；即便无选中正文，也须检查衍生持有。其他模块依赖 `identity::api`，identity 仅依赖 shared。bootstrap 注册受信模块身份与允许阶段。页面入口不改变权限、数据所有者或处理范围。

## 6. 密码身份与入口保护边界

一个账户可没有微信关联、没有密码身份；当前密码表约束每账户最多一个密码身份。两种身份可在模型上指向同一账户，但当前脚本仅新建密码账户，不提供绑定、解绑、用户名修改或跨身份账户合并。账户 CLOSING/CLOSED 和密码身份非 ACTIVE 均不能通过密码登录；管理员重置不能恢复账户状态。

独立 Basic Auth 账号仅控制测试站点入口。后端 ActorContext 始终来自业务会话，不从 Basic Auth 用户名或 `X-EvoLoop-Session` 字段直接构造。后者仅由可信本机网关转换为 Bearer 后交给既有会话解析。部署细节见[网关说明](<D:/project/pri/EvoLoop/infra/nginx/README.md>)。
