## 3. 不变量、并发与失败恢复测试设计

| 场景 | 必须证明 | 所属验证 |
| --- | --- | --- |
| 新微信关联并发登录 | 唯一约束只产生一有效关联/账户；冲突回滚不残留孤立账户；客户端 openId 无权 | 真实 MySQL 唯一/事务 |
| 微信兑换期间进程中断 | 有限缓存可信结果可恢复；结果无法验证明确 REAUTH_REQUIRED；不将超时标成功 | 端口故障注入 / 恢复 |
| 撤回与 AI 接纳竞争 | 同用户账户栅栏给出确定提交顺序：接纳先提交为撤回前行为，撤回先则旧结果拒绝 | MySQL 双事务并发 |
| AI 返回成功但撤回用途 | 普通 context 拒绝；BACKGROUND_MAINTENANCE 可终结/清理，但不能调用计划发布/用户确认 | 跨模块资格/操作白名单 |
| 删除与手工写入竞争 | 删除受理先提交则相交写受限；非相交写可继续；清理 worker 严格限定范围 | 栅栏/范围并发 |
| 导出与一般写入并发 | 固定 ID/不可变 revision 清单不变；导出不冻结新写，manifest 明示 snapshotAt/采集区间 | 导出集成 |
| 导出与隐私删除竞争 | epoch 变化使旧片段/包/网关票据不可新取；不补读被删历史或新版本 | 文件端口 / 资格集成 |
| 回执重复、乱序、伪造模块 | 同序号同内容幂等，摘要不同冲突，小序列忽略/拒绝，module 不匹配拒绝；成功不回退 | DataRequest 领域规则 |
| stage 无实际处理方 | 只有证明无持有时 SKIPPED；未实现/未知政策必须待处理，不以超时完成 | 阶段策略规则 |
| 供应商仅确认受理 | PENDING_EXTERNAL，不得 SUCCEEDED；重启后重新查询证明，不重复声称清理 | 外部清理恢复 |
| 同一请求系统重启 | 持久事件至少一次、消费去重与工作领取恢复；共用单一事件设施，无第二 outbox | Modulith 候选接入验证 |
| 隐私处理中共享设施 | 公共 receipt/事件/临时文件/备份副本纳入 infrastructure 回执 | 七方清理集成 |
| 注销后进度恢复 | 重新微信核验只能获得绑定请求的进度凭据；不再签发普通会话/下载权限 | 认证与契约 |
| 数据库子表插他人 parent | 复合 user_id FK 拒绝；所有可空 revision 去重有非空摘要；无 NULL 唯一漏洞 | V010 MySQL 约束 |
| 密钥轮换与私密日志 | 同 openId 新旧密钥仍对应一账户；日志/事件不存凭据、私人正文；过期加密缓存实际清理 | 安全运行配置与故障恢复 |

原设计规划的 domain 测试位于 `backend/src/test/java/com/evoloop/identity/domain/`；应用/持久化镜像 application/infrastructure；跨域验收在 tests/acceptance。以上是实施目标，没有以文档检查替代真实测试证据。
