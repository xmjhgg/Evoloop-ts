## 1. 类型、仓储及共同约束

以下 `UUID` 全称为 `CHAR(36) CHARACTER SET ascii COLLATE ascii_bin`；不是数据库原生 UUID 类型。所有时间点 `DATETIME(6)` 保存 UTC，日期 `DATE` 为上海业务归属日。所有 id、version、receipt 序号、epoch 非负，revisionNo 从 1；VARCHAR 枚举需 CHECK 约束。每表显式 user_id；预认证暂存表 user_id 可空是唯一身份尚未知的安全暂存例外，识别后回填，不能通过该表取得业务权限。

`UserAccountRepository` 加载账户和至多三个当前授权，历史按需；`SessionRepository` 按 token 摘要查询；`DataRequestRepository` 加载范围与阶段头，回执/产物分页查询。领域仓储不继承 JpaRepository，JPA 表模型仅本域可见。专用读投影不返回可编辑聚合。ProcessingContext 为服务器受控不可变类型，持久任务保存必要快照；不建立可被客户端修改的授权 context 表。

内部 FK 均 ON DELETE RESTRICT，隐私处理按显式顺序清理，不用级联掩盖阶段。每个子表用 `(user_id,parent_id)` FK 引用父表同名复合唯一键，防止跨用户拼接。本文逐表列出的 UQ 包含该键；跨域 objectId/revisionId/产物来源只保存引用，无跨域 FK/JPA 导航。表索引若含 user_id 的顺序同时支持本人过滤；正文/JSON 不做模糊日志搜索。

基础设计中的默认值、CHECK 和复合键为原工作版约定，不自动代表后续增量 DDL。V120 密码身份的字段和实际约束单列于第 8 节。

## 7. 事务、并发、导出与删除

| 场景 | 原子范围及锁顺序 |
| --- | --- |
| 密码登录 | 事务外规范用户名、读身份及 BCrypt 匹配→账户栅栏→锁密码身份并复核状态/哈希→签发既有会话；不写公共幂等回执 |
| 密码重置 | 账户栅栏→条件更新 ACTIVE 密码身份/版本→撤销全部 ACTIVE 会话→提交；不变更账户/授权版本或 epoch |
| 密码账户创建 | 单事务新建账户及密码身份；用户名/userId 唯一约束冲突回滚，无微信占位身份 |
| 已有账户登录 | 事务外微信兑换→账户栅栏→公共幂等→会话/登录提交；到期/撤销/账户再核验 |
| 新账户登录 | appId/openId lookup 唯一约束解决竞争→取得真实账户后栅栏；唯一冲突整笔回滚重查，不保留失败创建账户 |
| 改授权 | 栅栏→幂等→grant/新 revision→账户双版本→持久事件→提交 |
| 删除受理 | 栅栏→幂等→scope/stage 矩阵→epoch 递增→旧导出标失效/清理登记→事件 |
| 注销受理 | 栅栏→幂等→CLOSING/epoch→撤销会话→请求和进度凭据→事件；全部一次提交 |
| 处理/回执 | 先定位 userId→锁账户→请求→阶段→回执历史/产物引用→状态重算与事件 |

导出不冻结正常写入。各所有者在短栅栏事务冻结固定 objectId/revisionId 清单及 snapshotAt，事务释放后分批读不可变修订；源修订如果因隐私请求被清理，不补取新版本或已删正文，报告缺失并取消旧 epoch 导出。manifest 保留各域时间、版本与采集区间，组包过程在事务外；入库/下载前锁内再次核 epoch。epoch 变化后旧片段/包立即不可用并由持有者清理。范围门禁只针对活跃 DELETE/CLOSE_ACCOUNT，EXPORT 本身不限制普通业务写入。

普通误记删除与隐私删除不同：前者本域新删除修订，后者清理请求覆盖的正文、旧修订、引用快照、AI 输入/结果、临时片段/文件关联以及公共幂等/事件正文。实际文件操作事务外，小批次数据库清理分别持栅栏；先记录待清理对象与证明引用，避免删元数据后失去清理定位。

FK 不阻碍残留处理：账户根及最小请求/阶段元数据在清理跟踪期保留，使 CLOSING/CLOSED 的受限 worker 可继续回执。最终最小化顺序为密文/会话/授权正文/可识别说明→产物→回执敏感项→范围目标→政策允许的请求/账户墓碑。保留事项/期限尚 TBD，不宣称上述所有记录无限保留或瞬时抹除。基础设施负责公共 receipt/事件/备份，不由 identity 直接写其表。

数据库死锁/瞬态失败有限重试同 requestId；版本/范围/幂等摘要冲突不覆盖。租约失效防旧 worker 写入，供应商或文件系统无法保证 exactly-once，以可重试受控对象槽位和验证证明实现。V010 只为设计编号，DDL、加密、索引性能与真实 MySQL 锁/FK 行为必须在实现阶段验证。
