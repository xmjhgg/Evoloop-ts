## 1. 聚合划分

| 根 | 内部实体 / 值对象 | 一致性边界 | 来源 |
| --- | --- | --- | --- |
| UserAccount | WeChatIdentity、PasswordIdentity、AuthorizationGrant/Revision；状态、双版本 | 账户资格/授权决定与 epoch，同事务触发撤销会话 | BR-COM-001/002/003/018 |
| UserSession | 凭据摘要、到期、撤销理由 | 单会话变化，注销同事务批量撤销 | UC-COM-001/005 |
| DataRequest | ScopeSelection、ObjectRef、RequestStage、StageReceipt、ExportArtifact、ProgressCredential | 冻结范围/阶段、单调回执、聚合进度；外部文件操作无数据库长事务 | UC-COM-003～005；BR-COM-004/018 |

账户根同时是 ProcessingFence，不另建锁表。三个可选用途的小集合由账户协调；会话/请求列表不全量装入账户聚合。领域模型纯 Java，公开 DTO、HTTP 与 JPA 模型分别转换。

## 3. 账户、会话、授权状态

```mermaid
stateDiagram-v2
    [*] --> ACTIVE: 首次建立本人关联
    ACTIVE --> CLOSING: 确认注销，撤会话、递增 epoch
    CLOSING --> CLOSING: 残留待清理或阶段失败
    CLOSING --> CLOSED: 必要阶段完成及保留政策已落实
    CLOSED --> [*]
```

CLOSING 即时禁止普通访问、新任务与写入，不等事件消费；微信或密码重新登录、管理员密码重置均不恢复 ACTIVE。CLOSED 没有恢复操作。最小墓碑/微信 lookup 摘要是否保留及期限仍为 TBD-003；未决定不宣称最后清理完成。若最终允许再次注册，使用新 userId 并隔离旧数据，不能复活旧账户。

```mermaid
stateDiagram-v2
    [*] --> ACTIVE: 签发会话
    ACTIVE --> REVOKED: 退出、轮换、密码重置、注销
    ACTIVE --> EXPIRED: 到期
    REVOKED --> [*]
    EXPIRED --> [*]
```

解析会话检查 expiresAt、revokedAt 和账户资格，不依赖客户端删除 token。注销进度使用独立单请求凭据，不恢复普通会话。密码登录复用 `evoloop.identity.session-duration`（当前配置默认 PT12H），不单独延长会话；轮换和敏感操作的最近身份核验仍按既有规则。

```mermaid
stateDiagram-v2
    [*] --> UNSET
    UNSET --> GRANTED: 明确同意完整说明
    UNSET --> DENIED: 明确拒绝
    DENIED --> GRANTED: 主动同意
    GRANTED --> WITHDRAWN: 主动撤回
    WITHDRAWN --> GRANTED: 对当前说明重新同意
    GRANTED --> GRANTED: 接受新说明版本
```

非重复决定追加 AuthorizationRevision，递增 grant.version、account.version、authorizationVersion；WITHDRAWN 再递增 deletionEpoch。同一幂等请求不增加版本。撤回不删数据，重新同意不复用旧任务，旧 authorizationVersion/epoch 永久不匹配。

## 4. 请求与阶段状态

```mermaid
stateDiagram-v2
    [*] --> ACCEPTED: 冻结范围和阶段矩阵
    ACCEPTED --> PROCESSING: 领取处理
    PROCESSING --> WAITING_EXTERNAL: 外部或政策待完成
    PROCESSING --> PARTIAL_FAILURE: 部分阶段可重试失败
    WAITING_EXTERNAL --> PROCESSING: 后续实际进度
    PARTIAL_FAILURE --> PROCESSING: 重试失败阶段
    PROCESSING --> AVAILABLE: 导出组包完成
    PROCESSING --> COMPLETED: 删除或注销全部必要阶段完成
    PROCESSING --> FAILED: 不可继续
    AVAILABLE --> EXPIRED: 产物实际到期
    AVAILABLE --> INVALIDATED: epoch 变化
    ACCEPTED --> INVALIDATED: 导出 epoch 变化
    PROCESSING --> INVALIDATED: 导出 epoch 变化
```

阶段状态：PENDING、RUNNING、SUCCEEDED、SKIPPED、FAILED_RETRYABLE、FAILED_FINAL、PENDING_EXTERNAL、PENDING_POLICY。可重试失败/等待状态重返 RUNNING 需 attemptNo 增加；成功不被旧回执回退。SKIPPED 必须证明无数据/无该类处理方并说明，不能表示未实现。receiptVersion 是每请求/所有者/阶段的单调序列，不等于 DataRequest.version。

DELETE/CLOSE_ACCOUNT 固定七方：identity、profile、planning、execution、review、ai、infrastructure。各方对 MODULE_DATABASE、OBJECT_STORAGE、PROCESSOR、BACKUP 分别回执。无相关持有由该方报 SKIPPED；未核实仍 PENDING_EXTERNAL/PENDING_POLICY。注销另有 identity 的 ACCOUNT_ACCESS（受理事务撤销会话）和 ACCOUNT_FINALIZATION（其他阶段完成后按已批准政策清理/最小化关联）。

EXPORT：七方分别有 EXPORT_SNAPSHOT、EXPORT_OBJECTS，identity 另有 EXPORT_PACKAGE。各域在短栅栏固定 objectId/revisionId 清单与 snapshotAt 后释放锁，分批读取不可变修订，普通写入不冻结。片段 manifest 记录真实 snapshotAt、采集区间、对象修订、引用和缺失；无数据返回空范围。格式与期限已落实且组包成功后 AVAILABLE。采用各域真实时间和版本的组合快照，不假称全域同一瞬间；无法提供的引用显式 missingItems。

同用户不相交删除可并存，相交的未完成删除返回 DATA_REQUEST_SCOPE_CONFLICT。注销可关联已在处理的删除请求及真实证明，不靠关联推定阶段完成。导出与活动删除相交时禁止发起；既有导出在 epoch 改变后失效。处理中不能扩大冻结范围，扩大需新确认/请求。

## 5. 栅栏与最终核验

所有短写事务账户根 SELECT FOR UPDATE 后锁公共幂等、本域根及事件登记。生成输入、AI 接纳、确认/发布最终检查在栅栏内；checkProcessing 不持有跨调用锁。不能持锁等待微信/供应商/文件网络操作。

核验顺序：可信上下文/本人 → 账户与会话或专用工作资格 → 用途/noticeVersion → authorizationVersion → deletionEpoch → 活跃删除范围 → 操作/对象范围。后台永无用户确认权。全局授权版本变化会使无关用途的旧任务保守失效，这是 V1 取舍；重新任务须重取来源，不改旧任务版本绕过核验。

撤回、删除、注销同事务递增 epoch 并持久登记事件。事件或物理清理虽可稍后执行，旧 worker 已不能写回。外部请求已发出只能尽力取消；返回先核验再关联，被拒绝的孤立文件按残留阶段清理。

## 6. 核心不变量

1. userId 来自服务端会话，所有者始终按本人范围查对象。
2. 删除覆盖相关正文、修订、快照、衍生和文件关联；保留例外需明示政策与真实阶段。
3. 删除使汇总/结论由所有者重算或失效，已确认未来计划不自动变更。
4. 文件实际验证后才成功；供应商仅受理仍待处理；备份未经验证不得成功。
5. 回执只存脱敏证据引用和残留，不能包含被删正文或秘密。
6. 导出包、进度凭据、共享事件与幂等副本进入隐私范围；最低进度元数据期限按 TBD-003。

## 7. 密码账号不变量与并发

1. 用户名先 trim，再转小写，仅允许 3～32 位 ASCII 字母、数字或下划线；数据库对规范用户名全局唯一，对 userId 唯一。用户名仅是认证查询键，业务归属始终使用 userId。
2. 创建/重置脚本要求密码 16～72 个 UTF-8 字节，保存 BCrypt cost=12 的带盐哈希；登录仅验证非空及不超过 72 字节，不修改已存密码策略。明文、哈希和会话凭据不进入普通日志、事件或用户导出。
3. 未知用户使用 dummy BCrypt 哈希执行匹配；未知用户、错误密码、密码身份非 ACTIVE 或账户非 ACTIVE 均返回 401 LOGIN_FAILED，不暴露账户是否存在。这不承诺所有失败路径耗时完全相同。
4. BCrypt 匹配在事务外；成功后 READ COMMITTED 短事务先锁账户，再锁密码身份，重新核验状态和哈希未变，随后签发既有 UserSession。校验期间密码被重置则不能用旧哈希签发会话。
5. 重置使用相同账户→密码身份顺序，递增密码身份 version，并同事务撤销该账户全部 ACTIVE 会话（包括其他登录方式签发的会话），理由 PASSWORD_RESET。重置不改变 account.version、authorizationVersion、deletionEpoch 或用途决定。
6. 创建账号同事务插入 ACTIVE 账户和密码身份，初始三个版本为 0，不插微信身份、资料、目标或授权。重复创建报错，唯一约束阻止重复身份；脚本无业务幂等回执，不宣称重复执行自动成功。
7. 重置脚本的操作前状态检查及事务内条件更新拒绝写入非 ACTIVE 身份/账户，不提供激活功能。与注销竞争的数据库并发场景仍待专门测试；脚本当前没有根据更新行数单独报告竞争结果。
8. 密码登录不签发 recentVerificationProof，也没有密码再次核验/注销进度恢复接口；只有密码身份的账户不能把登录成功当作已满足现有微信敏感操作核验。
