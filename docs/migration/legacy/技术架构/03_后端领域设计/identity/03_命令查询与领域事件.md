## 1. HTTP 共同规则

前缀 `/api/v1/identity`；时间点带 Z，业务日期为上海 DATE。普通请求从 Bearer 随机会话凭据恢复 ActorContext；禁止客户端 userId/ownerModule 赋权。除下述密码登录及本机管理员命令外，业务写入带 `Idempotency-Key`，服务端映射 commandRequestId，与 DataRequest 的 dataRequestId 分开。编辑带 expectedVersion，后台携带双版本和受限上下文。普通写幂等由公共 `sys_command_receipt` 维护；重放相同输入返回原提交结果，摘要不同 409 IDEMPOTENCY_CONFLICT。

## 2. HTTP 用例契约

| 方法 / 路径 | 输入 | 输出与权限 | 主要失败 |
| --- | --- | --- | --- |
| POST `/sessions/password` | username、password；无需业务会话，不接受客户端 userId | 201 复用 LoginResult：userId、sessionId、sessionCredential、expiresAt、accountVersion、authorizationVersion、deletionEpoch；用途不自动授权 | 401 LOGIN_FAILED；网关限速 429 |
| POST `/sessions/wechat` | wxCode、clientRequestId、returnContext（受控入口代码） | 201 userId、sessionId、sessionCredential、expiresAt、账户版本/双版本；首次空资料正常 | 422 INVALID_LOGIN_CREDENTIAL；403 ACCOUNT_CLOSING/CLOSED；503 LOGIN_PROVIDER_UNAVAILABLE；409 请求冲突 |
| POST `/identity-verifications/wechat` | 新 wxCode、verificationPurpose=CLOSE_ACCOUNT/RECOVER_REQUEST_PROGRESS；恢复时 dataRequestId | 200 限期 recentVerificationProof；恢复情形只重新签发该注销请求进度凭据，不能建业务会话 | 422 INVALID_LOGIN_CREDENTIAL；404 本人关联/请求不匹配；503 兑换不可用 |
| GET `/me` | 当前会话 | 200 userId、sessionId、status、accountVersion、authorizationVersion、deletionEpoch、allowedEntryCodes；不查询业务正文 | 401 SESSION_EXPIRED/REVOKED；403 ACCOUNT_RESTRICTED |
| DELETE `/sessions/current` | expectedVersion（会话） | 200 REVOKED；幂等退出，不撤回用途或删除数据 | 409 VERSION_CONFLICT；凭据已撤销的同请求可按有限安全重放 |
| GET `/authorizations` | 当前会话 | 200 三个可选用途当前状态/版本、说明、受影响能力；ACCOUNT_ACCESS 作为基础资格单列 | 401/403 |
| PUT `/authorizations/{purpose}` | decision=GRANTED/DENIED/WITHDRAWN、noticeVersion、expectedVersion（账户）、explicitAction=true | 200 当前决定/notice、accountVersion、authorizationVersion、deletionEpoch；只有真实本人可同意 | 409 VERSION_CONFLICT/NOTICE_CHANGED；422 INVALID_PURPOSE/NOTICE_INCOMPLETE/EXPLICIT_ACTION_REQUIRED |
| POST `/data-requests/preview` | type、scopeSelections；导出图片选择/删除衍生包含 | 200 normalizedScope、scopeDigest、confirmationTextVersion、影响类别/未知项；只描述策略闭包，不伪称逐域已查影响数量 | 422 EMPTY_SCOPE/INVALID_SCOPE；403 受限身份 |
| POST `/data-requests` | type=EXPORT/DELETE、scopeSelections、scopeDigest、confirmationTextVersion、explicitConfirm=true、expectedVersion（账户） | 202 dataRequestId、status、version、scope、stages、双版本；DELETE 同事务递增 epoch | 409 SCOPE_CHANGED/DATA_REQUEST_SCOPE_CONFLICT；422 明确确认或范围不满足 |
| POST `/account-closure` | expectedVersion、confirmationTextVersion、explicitConfirm=true、recentVerificationProof | 202 dataRequestId、status=CLOSING、progressCredential、progressCredentialExpiresAt；会话即时撤销 | 403 REAUTH_REQUIRED；409 VERSION_CONFLICT；422 CONFIRMATION_REQUIRED |
| GET `/data-requests` | type/status、cursor、limit | 200 本人请求概要、nextCursor，不含正文/供应商秘密 | 401/403 |
| GET `/data-requests/{id}` | 当前会话；注销后改用受限进度端点 | 200 冻结范围、真实阶段/残留、版本、artifact 概要 | 404 REQUEST_NOT_FOUND |
| GET `/data-request-progress/{id}` | `Request-Progress-Credential`，不接受其作为 Bearer 会话 | 200 该单请求状态与脱敏残留；不返回对象正文或下载入口 | 401 PROGRESS_CREDENTIAL_EXPIRED；404 范围不匹配 |
| POST `/data-requests/{id}/retry` | expectedVersion、stageRefs[]（失败/等待阶段）；注销后须重新微信核验的绑定请求 recentVerificationProof | 202 原请求、当前版本及重试计划；只续办该请求清理，不扩大范围/重做成功阶段/恢复会话 | 409 STAGE_NOT_RETRYABLE/VERSION_CONFLICT；403 REAUTH_REQUIRED |
| POST `/data-requests/{id}/artifacts/{artifactId}/download` | 当前会话；不使用进度凭据 | 200 一次下载票据/受控应用网关 URL、expiresAt、digest、missingItems；最终核 epoch，不直发可绕过核验的对象存储 URL | 409 EXPORT_INVALIDATED；410 EXPORT_EXPIRED；403 DATA_REQUEST_IN_PROGRESS |

purpose 必须来自 01 的三个可选代码，ACCOUNT_ACCESS 不能 PUT 同意。preview 输出按已批准策略列关联类别，并标 `impactResolution=OWNER_PENDING`；精确跨域闭包由所有者在处理时报告。发现超出用户确认的独立数据需要删除时不擅自扩大，返回 RESCOPE_REQUIRED 并保留未完成阶段。CLOSE_ACCOUNT 始终全用户范围，说明所有模块、图片、导出与第三方/备份阶段。

身份验证 proof 由微信重新兑换或已有可信服务端核验产生，不接受客户端时间自报。具体时效、渠道参数 TBD；它验证操作者，不授予数据用途。注销响应丢失后旧会话不能读业务；相同注销请求可凭同一最近核验 proof 取回有限期加密保存的同一 progressCredential，或再次核验原微信关联后只重新签发该请求进度凭据。该恢复入口不能使账户恢复 ACTIVE。

### 2.3 错误结构

```json
{
  "code": "PROCESSING_EPOCH_STALE",
  "message": "数据处理状态已变化，旧任务不能继续写入",
  "requestId": "44000000-0000-4000-8000-000000000001",
  "details": {"expectedDeletionEpoch": 2, "currentDeletionEpoch": 3}
}
```

普通能力拒绝为 403 PURPOSE_NOT_GRANTED / ACCOUNT_RESTRICTED / RESOURCE_DELETING；版本变化为 409 AUTHORIZATION_STALE / PROCESSING_EPOCH_STALE / VERSION_CONFLICT；过期上下文 403 PROCESSING_CONTEXT_EXPIRED。对非本人对象统一 404，避免泄漏他人状态。内部回执错误不暴露完整私人范围。

## 3. IdentityApi 公开契约

公开包只返回不可变 DTO，不返回聚合、JPA、供应商响应或认证秘密。

| 方法 | 输入 | 输出 / 事务要求 |
| --- | --- | --- |
| `checkProcessing` | ActorContext 或 ProcessingContext；PurposeSet、ResourceScope、operation；expectedAuthorizationVersion/expectedDeletionEpoch（后台必填，人工适用时） | ProcessingDecision：userId、accountStatus、authorizationVersion、deletionEpoch、allowedPurposes、allowedOperations、拒绝代码；普通只读，不持锁 |
| `lockProcessingFence` | 同上；调用者已开启 READ COMMITTED 短事务 | FencePermit：相同资格版本、contextKind、允许操作和事务绑定标识；账户 SELECT FOR UPDATE 到调用者提交；MANDATORY，不用 REQUIRES_NEW |
| `createProcessingContext` | 有效 actor + 受信请求模块；ownerModule、operation、scope、purposes、businessRequestId、taskId? | 当前双版本与用途快照的 BACKGROUND_TASK；持栅栏签发，输入快照与持久任务同事务提交；模块不可任意选择其他 owner |
| `createDataRequestContext` | TrustedModuleContext、dataRequestId、获分配 stage、operation | DATA_REQUEST_WORKER/STAGE_REPORTER；冻结范围；删除可在 CLOSING/CLOSED，导出仍需 acceptedEpoch 匹配 |
| `createMaintenanceContext` | TrustedModuleContext、ownedResourceRef、maintenanceOperation | BACKGROUND_MAINTENANCE；只任务状态维护/清理；按当前 epoch 签发，无同意/正文接纳权 |
| `reportDataRequestStage` | STAGE_REPORTER 或合适 DATA_REQUEST_WORKER；dataRequestId、module、stage、receiptVersion、attemptNo、status、artifactDescriptors、snapshotAt?、sourceManifestRef?、residualItems、evidenceRef?、contentDigest | StageReportResult：accepted/duplicate、stage 状态、requestVersion/状态、未完成项；账户→请求→阶段短事务，回执历史与状态/事件同事务 |
| `getDataRequest` | 本人 actor 或绑定请求的进度资格 | 完整真实进度；不授予跨域正文访问 |

TrustedModuleContext 由 bootstrap 对模块/worker 绑定服务器能力，不是 HTTP 可传的角色字符串。签发不得接受消费者要求提高权限；操作、purpose、scope 必须是已有用户选择/受理请求范围的子集。taskId 可在分配 UUID 后、创建任务前签发；跨任务重用 context 拒绝。具体上下文有效期按接入配置，不把文档示例期限视为生产规则。

### 3.1 特权不是用途扩张

DATA_REQUEST_WORKER 只允许 EXPORT_OWNED_SCOPE、PURGE_OWNED_SCOPE、VERIFY_EXTERNAL_CLEANUP；导出/删除权利操作不要求已经撤回的 HEALTH_DATA 或 AI_PROCESSING 再次同意。它不能从原数据新生成 AI 结论。STAGE_REPORTER 只 REPORT_STAGE。

BACKGROUND_MAINTENANCE 仅 `CANCEL_TASK / REJECT_RESULT / RELEASE_LEASE / RECORD_FAILURE_METADATA / PURGE_HELD_CONTENT`。ACTIVE、CLOSING、CLOSED 可使用；不要求已撤回用途仍 GRANTED，但必须可信 owner、本人归属、当前 epoch、指定旧资源及账户栅栏。不读取/生成正文、不接纳结果、不确认用户动作。旧普通任务被拒绝后重新签发维护 context，可以终结任务及清理持有结果；不能升级旧 BACKGROUND_TASK。

### 3.2 AI 任务委派子操作

AI 协作使用 `AI_CANDIDATE_PROCESSING` 封闭能力组，详见[跨域协议](../01_领域协作契约与设计约定.md)。ProcessingContext.ownerModule 保留 origin 业务域；任务资源属于 ai，不将两者混为同一所有权。预分配 taskId 后按来源范围签发；checkProcessing/lockProcessingFence 同时核验服务器 TrustedModuleContext 和具体子操作，origin 仅可创建/读取自己候选/保存业务候选/报告接纳，固定 ai executor 仅可领取/执行/保存候选/完成失败任务，不能写 origin 的业务对象、报告业务接纳或人工确认。租约续期不更新旧双版本；撤回后维护资格另按当前 epoch 签给 ai，仅处理其任务状态/清理，不升级旧普通任务。

### 3.3 回执语义

唯一 `(dataRequestId,module,stage,receiptVersion)`。同版本同摘要返回 duplicate；同版本不同摘要 RECEIPT_CONFLICT；小于已接纳序列 RECEIPT_STALE。大于当前序列不要求逐个齐全，但验证合法转换、attemptNo 与完成证据；SUCCEEDED/SKIPPED 不接受旧失败回退。不同模块不能替另一模块回执。PENDING_EXTERNAL 含未完成项；SKIPPED 必须 reasonCode 和说明；SUCCEEDED 的必需证据类型按阶段约定，不以日志一条“成功”代替文件/供应商验证。

删除/注销恢复重新签发当前 epoch context；回执本身无需读取私人正文。导出旧 epoch 回执只能用于报告清理残留，不能把请求恢复 AVAILABLE。

ArtifactDescriptor 为 `artifactId, ownerModule, slotKey, controlledStorageKey, formatCode, digest, byteSize, snapshotAt, captureStartedAt, captureEndedAt, expiresAt, producedEpoch`；受信所有者只能登记其用户/请求/模块对象命名空间下的产物，identity 在回执事务登记元数据，不接受客户端任意文件键。组包只通过存储端口读这些受控片段，不反向查询模块仓储。manifest 至少含固定对象/修订选择清单、引用、缺失与真实时间区间。

## 4. 登录与授权时序

```mermaid
sequenceDiagram
    actor U as 用户
    participant H as Identity HTTP
    participant W as 微信端口
    participant A as Identity 应用服务
    participant DB as MySQL
    U->>H: wxCode + Idempotency-Key
    H->>A: 查预登录请求，领取短租约
    A->>DB: 预登录幂等摘要/状态，提交
    A->>W: 兑换凭据（无业务事务）
    W-->>A: 验证后的 appId/openId
    A->>DB: 关联查找；新账户以唯一键防重
    A->>DB: 锁账户栅栏，核验 ACTIVE
    A->>DB: 保存会话 + 公共幂等结果，提交
    A-->>U: 本人会话；敏感用途仍 UNSET
    U->>H: 明确同意用途、noticeVersion、expectedVersion
    H->>A: ChangeAuthorization
    A->>DB: 栅栏→幂等→授权修订/账户版本
    A->>DB: 持久登记 AuthorizationChanged，提交
    A-->>U: 用途决定及双版本
```

预登录暂存仅防重复微信兑换；交换结果不得当 AI 输入。新关联竞争唯一键失败时整笔回滚，再按唯一关联获取账户锁，不先锁失败创建的幽灵账户。兑换结果提交前进程崩溃或微信 code 已消耗且结果未持久化时返回 LOGIN_REAUTH_REQUIRED，要求新 code，不能假称登录成功；同请求已提交时取原限期加密响应。

```mermaid
sequenceDiagram

    participant I as Identity
```

```mermaid
    E-->>O: 至少一次事件（模块去重）
    O->>I: 创建受限请求上下文
    O->>DB: 栅栏内小批次清理本域正文/历史/快照
    O->>I: reportStage(MODULE_DATABASE, SUCCEEDED)
    O->>F: 事务外删文件/请求第三方清理

    I->>DB: 栅栏→请求→阶段，回执追加及进度重算
```

导出使用同样所有者回执路径：各域短栅栏固定 ID/修订清单与 snapshotAt 后分批读取不可变修订，不冻结普通写入，manifest 保留采集区间。收集片段后 identity 在事务外组包，锁内核 epoch 后关联产物和 AVAILABLE；期间 epoch 变化则清理临时包并 INVALIDATED。下载票据由应用网关在每次取文件前核验；不直发对象存储预签名链接绕过撤回/删除核验。已实际交付给用户的副本无法收回，此状态不等同系统仍在保存或允许旧任务回写。

## 7. 事件及恢复

共用信封 `eventId,eventType,schemaVersion,occurredAt,ownerModule,userId,aggregateId,aggregateVersion,requestId,affectedScopes,payload`；schemaVersion=1。requestId 是命令幂等 ID，payload 另含 dataRequestId，避免同名歧义。

| 集成事件 | 最小载荷 | 订阅者与作用 |
| --- | --- | --- |
| AuthorizationChanged | purpose、decision、noticeVersion、authorizationVersion、deletionEpoch | 各业务域/ai：旧处理失效；不删除原事实或自动改计划 |
| AccountStatusChanged | status、authorizationVersion、deletionEpoch、dataRequestId? | 各域拒绝普通访问/接纳，清理仍用专用资格 |
| DataRequestCreated | dataRequestId、type、scopeSelections/受控范围引用、acceptedEpoch、requiredStageMatrixVersion | 六域+infrastructure：自行扩展本域持有闭包、执行/回执 |
| DataRequestProgressChanged | dataRequestId、requestStatus、stageRef、stageStatus、receiptVersion、remainingCount | identity 查询通知/运维；不据此推定其他阶段完成 |
| ExportArtifactInvalidated | dataRequestId、artifactRefs、deletionEpoch、reason | 持有导出片段/包的所有者清理受控产物 |

纯领域事件在本域转换后登记集成事件；使用唯一持久事件设施，不另建 outbox。消费 `sys_event_consumption` 同事务去重，乱序按账户双版本/请求版本忽略回退；关键核验仍读 identity 当前状态，不依赖事件及时到达。轮询扫描未完成请求/未完成阶段可恢复遗漏工作，不能凭扫描超时补成功。外部调用失败有限重试并回执真实状态；清理无法验证保持待处理。

## 7. 密码登录与本机管理员命令（已实现增量）

实现入口为 `PasswordSessionController` → `PasswordSessionService` → `IdentityRepository.passwordIdentity(username, lock)`。后者是内部认证读取，返回 userId、passwordHash、status，不进入跨域 IdentityApi、普通 HTTP DTO 或 AI 输入。HTTP 的实际结构以[OpenAPI](<D:/project/pri/EvoLoop/contracts/openapi/evoloop-v1.yaml>)为准。

密码登录不要求 Idempotency-Key，不使用 sys_command_receipt 缓存可重放登录响应；每次成功都签发一个独立会话。网络失败后重试可能产生多个会话，退出只撤销当前会话，密码重置撤销账户全部有效会话。与原微信兑换幂等流程分别实现，不套用微信的一次性 code/兑换暂存表。

```mermaid
sequenceDiagram
    actor U as 用户
    participant H as PasswordSession HTTP
    participant A as PasswordSessionService
    participant DB as MySQL
    U->>H: username + password
    H->>A: 规范用户名，校验输入
    A->>DB: 非锁定读取密码身份
    A->>A: 事务外 BCrypt 匹配（未知用户用 dummy hash）
    alt 匹配且密码身份 ACTIVE
        A->>DB: READ COMMITTED，先锁账户，再锁密码身份
        A->>A: 再核 ACTIVE 和哈希未变
        A->>DB: 保存既有会话摘要及到期时间，提交
        A-->>U: 201 LoginResult
    else 认证或锁内复核失败
        A-->>U: 401 LOGIN_FAILED，不签发会话
    end
```

| 管理命令 | 输入与资格 | 原子结果与失败 |
| --- | --- | --- |
| 创建密码账号 | 服务器管理员运行 [provision-password-account.py](<D:/project/pri/EvoLoop/scripts/provision-password-account.py>)；username，交互密码或受控 stdin JSON | 新 userId、ACTIVE 账户和密码身份；重复用户名失败并要求显式 --reset；不自动绑定既有微信账户 |
| 重置密码 | 同脚本显式 --reset；既有密码身份和账户须 ACTIVE | 更新 BCrypt 哈希及身份 version，同时撤销全部 ACTIVE 会话；未知或非 ACTIVE 拒绝；不恢复账户，不改变授权 |

脚本通过服务器本机 MySQL 管理连接执行事务，密码不接受命令行参数，不建立公网管理 API，不登记公共业务幂等结果，也未新增账号创建/重置领域事件。重置和登录共用账户→身份锁顺序；失败信息不输出密码或 SQL 正文。并发状态竞争的验证限制见 02/05。

公网部署的 Nginx 对密码端点按来源 IP 限制 5 次/分钟、burst=5，超限 429；限速属于网关而非 PasswordSessionService。页面、资源、接口先验证独立 Basic Auth；普通请求将 X-EvoLoop-Session 转换为后端 Authorization: Bearer，密码登录端点清空该头。后端仅本机监听，不能以公网直连绕过网关限速。客户端将业务凭据保存在当前标签页 sessionStorage，过期返回登录，切换账号重新加载并清理旧页面状态；不是服务端会话授权的替代。

本次没有开放注册、找回密码、身份绑定、用户名修改或账号管理页面；密码登录能力不补充原微信敏感操作核验。

## 8. 2026-10-15 本地账户同步栅栏

`/api/v1/sync/bootstrap` 使用既有账户处理锁建立本地模式切换点，不更改账号、会话或用途授权模型。`sys_sync_account` 属于基础设施；`IdentityRepository.localMode` 仅查询该模式。`TransactionalCommandExecutor` 拒绝已切换账户的普通领域旧写入，身份命令和查询继续可用；`lockBackgroundFence` 同样阻止旧后台接纳写入。同步入口直接校验同所有者行、引用、结构与基础版本，不重复执行业务保存或发布事实事件。

同步每次读取/写入仍检查当前用途、授权版本和删除代次。撤回或删除后旧设备被阻止；显式重新初始化下载当前云端副本，旧待同步操作保留为本地分支，不能自动重放。隐私处理中的基础设施清理覆盖同步回执、日志、版本备份，离线设备及外部导出文件不能声称已被远程彻底清理。iOS / 微信移动入口采用业务 Bearer 会话；旧 H5 的 Basic Auth 网关继续保留。具体限制见[实施记录](<D:/project/pri/EvoLoop/docs/技术架构/13_双端本地优先实现与验证_20261015.md>)。
