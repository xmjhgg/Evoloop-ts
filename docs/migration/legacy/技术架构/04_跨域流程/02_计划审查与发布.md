# 计划审查与未来范围发布

版本 v1.0，2026-10-11，详细设计工作版。领域所有者为[planning](../03_后端领域设计/planning/README.md)，共同协议见[协作约定](../03_后端领域设计/01_领域协作契约与设计约定.md)。

## 1. 审查输入与异步边界

手工、AI 生成与复盘调整进入同一个目标/周工作草案。审查绑定草案完整版本、目标/条件修订、当前限制规则、来源范围 token、授权版本与 epoch。修改动作、时段、数量、目标或相关条件后旧审查与旧处理状态失效。普通建议可保留，阻断项必须解决；审查失败或不可用不发布未审查草案。

RULES 渠道由 planning 的确定性、版本化策略完成适用审查，覆盖不足为 INFORMATION_REQUIRED；AI 渠道增加已授权语义审查，以下时序描述该异步分支。拒绝 AI 时可选择 RULES 重新审查，不能自动将 AI 失败算作通过，也不能用渠道切换绕过禁止项。规则计算参数与审批配置待落实时不宣称可发布。

## 2. 发布必须核验的项目

| 核验 | 冲突行为 |
| --- | --- |
| 草案/目标/条件和最新审查指纹匹配 | 409 SOURCE_STALE / VERSION_CONFLICT，重新审查 |
| 阻断项、信息不足项及适用健身规则已处理 | 422，不以结论已确认或用户接受风险绕过 |
| selectedItemIds 属于本人目标/周并明确确认 | 不扩展到未选择日期或其他目标 |
| 真实时间未到开始边界，无已开始/已有事实保护 | 409 BASELINE_PROTECTED，用户明确缩小范围后重新提交；不静默跳过 |
| 复盘调整的依据仍最新已确认 | 调用 planning.api.AdjustmentBasisVerifier 的 review 实现，验证底层范围 token；失效拒绝 |
| 跨目标时段/饮食/睡眠基准冲突处理明确 | 展示冲突并要求选择，不自动移动别的目标 |

发布锁账户栅栏、幂等、Goal、WeekPlan、稳定项目保护行；与 execution 保存争用同一保护行且同用户栅栏串行。partial publication 保存不可变项目修订及发布 manifest，当前指针仅切换所选可发布项目，完整周适用组合保留其他日期旧修订。根 version 与修订号分别使用。

## 3. 健身与目标生命周期

健身总目标计算、餐次分配一致性、风险规则由 planning 版本化策略负责。来源模型和营养成分换算不能代替发布规则。生产计算参数、阈值和营养来源待明确前标记未完成配置，不能借原型上限作为生产健康阈值。

暂停/归档只改变指定目标未开始范围，不删历史、不影响其他目标。恢复进入待规划，用最新条件重新审查并确认未来安排；历史执行引用原目标状态与计划修订。身体新增不适限制当前关联活动提示，不直接改写原计划修订。

## 4. 失败与待实现验证

旧模型返回可保留受控过期状态，不覆盖新草案；任务调用成功与审查业务接纳独立。发布事务任一失败不切换任何选中指针；事件失败提交后重试。重复确认返回同一发布 ID。

对应 UC-COM-010-AC-01～06、UC-COM-015-AC-01～03，及 planning 追溯中的健身审查与状态 AC。重点验证：动作改动后旧审查拒绝；已开始事实与发布竞争；部分发布其余日期不变；当天已有摄入总量保护；周日夜睡眠跨周；来源 verifier 无编译循环与运行时递归。
