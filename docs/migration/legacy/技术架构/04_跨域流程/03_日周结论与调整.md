# 共享日结论、目标周复盘与调整依据

版本 v1.0，2026-10-11，详细设计工作版。判断所有者为[review](../03_后端领域设计/review/README.md)，草案与发布所有者为[planning](../03_后端领域设计/planning/README.md)。

## 1. 来源与同一结论身份

每用户/日期只有一个 DailyConclusion，包含目标分段与日总览；今日与复盘查询同一 ID/当前修订/确认状态。每用户/目标/周只有一个 GoalWeeklyReview。结论只引用事实，不能新建一份摄入、身体或睡眠事实。

来源包括计划执行时目标/适用修订、execution 事实、profile 身体观测、人工输入、截至时间及范围 token。已有对象 refs 加上范围 token 可检测后来新增事实、移出日期或删除。无计划只显示数量，未登记与零值分别表达；各单位独立统计，未来未到执行时点不进分母。

## 2. 确认与失效

保存人工补充不自动确认；确认日/周判断不登记全部完成，不发布计划；周确认不代确认每日。AI 失败保留事实和人工判断，人工路径保存明确来源、覆盖、未知与截止，不伪装成模型生成。

事实/人工来源变化使最新确认失效；旧历史确认保留其当时认可的范围。读取标为“最新已确认”、接纳、确认和提出调整前必须在用户栅栏内核验当前来源；异步标记仅为加速。原 confirmed_at 存在不能单独证明最新性。

周结论引用每日结论状态/修订以及底层事实；七天不齐可生成有限判断，必须显示实际覆盖。日重新确认等影响引用状态的变化也改变日结论 token，关联周判断需复核。

## 3. 未来调整与回环

review 提供候选 `oldValue/newValue/reason/affectedDate` 和最新已确认 basisRefs；planning 持有唯一目标/周工作入口，保留其他安排并显式解决同项目/字段冲突。来源通过接口倒置核验，不新增 planning→review 编译依赖。proposal 接口和最终发布均核验依据。

跨周候选按影响日期计算周一：周日调整周一进入同一个下周 WeekPlan；已有草案/生效内容合并，不另建第二份周一安排。已开始睡眠/训练不可追溯修改，用户缩小范围后走重新审查与计划确认。

原结论、草案保存与计划发布是独立结果。来源修正不自动改已确认未来计划；普通手工规划可独立进行，不要求先确认复盘。
