# 跨域流程与事务设计目录

版本v1.0，2026-10-11，详细设计工作版。本目录存放超出单个聚合/上下文的应用协作流程；业务规则仍由各领域所有者维护，统一归属遵循[整体业务领域设计](../03_后端领域设计/00_整体业务领域设计.md)，接口及锁协议见[领域协作约定](../03_后端领域设计/01_领域协作契约与设计约定.md)。

| 流程 | 发起与协作 | 一致性与结果 |
| --- | --- | --- |
| 真实训练/学习/睡眠保存 | execution → planning公开锁定命令 → 实际仓储 → 持久事件 | 同一MySQL事务保护适用基准与事实；提交后异步更新review，事实成功不等待AI |
| 实际食用确认 | execution食物草案 → 核对个人份量 → planning锁定适用饮食基准 → MealRecord | 只有确认吃下部分才入账，草案不计数；一事实多目标引用，日小计不复制累计 |
| 计划审查与确认 | planning → profile/identity版本核验 → ai任务；结果回来planning处理 → 明确发布 | 改动使旧审查失效；确认锁受影响项目，只有可调整范围切换指针 |
| 日/周结论生成与确认 | review → planning/execution/profile快照 → ai；review接纳与人工确认 | 同日日结论及目标分段共享，源变化使旧确认过期；读取/确认核验最新来源 |
| 按结论调整未来 | review核验最新已确认来源 → planning合并草案 → 审查发布 | 候选携带来源版本；确认前通过planning.api的来源核验端口调用review实现，核对结论及底层依据，保持无实现包循环；不追溯发布 |
| 资料或目标改变 | profile/planning持久变化 → 消费者标记相关草案/审查依据失效 | 已发布计划不自动变更，历史仍用当时版本 |
| 身体状态与关联健身限制 | profile保存日级身体状态；execution保存训练感受 → planning公开规则评估/限制查询 → review/workspace引用 | 身体与训练事实由原域唯一保存；任务读取、执行入口及发布核验最新适用来源和限制，不只依赖异步标记，不等待AI成功；原计划修订与限制分别表达 |
| 数据请求/撤回授权 | identity记录请求与用途版本 → 公开事件通知各域 → 各域处理并按identity契约回执 | 多阶段任务记录真实状态、失败和重试；identity不反向导入数据所有者；返回/写入核验授权与对象状态，不恢复删除内容 |

单体中优先使用公开接口的本地调用。需要原子保护的跨域步骤允许共享一个Spring/MySQL事务；后台分析用可靠事件最终一致，不在数据库事务中调用AI。

| 详细流程 | 关键内容 |
| --- | --- |
| [执行事实保存](01_执行事实保存.md) | 基准保护与事实同事务、摄入总量保护、睡眠跨周、修正与失败恢复 |
| [计划审查与发布](02_计划审查与发布.md) | 来源指纹、最新审查、明确选中范围、部分发布和保护冲突 |
| [日周结论与调整](03_日周结论与调整.md) | 共享身份、范围版本、独立确认、调整依据与接口倒置 |
| [授权及数据请求](04_授权及数据请求.md) | 删除epoch、各持有者清理、真实阶段、外部待处理和受限进度 |

各流程列明时序、输入版本、幂等及失败恢复；原始 UC-AC 的逐项映射由领域 05 文档维护。上述设计还需后续源码与数据库集成验证。
