# 执行事实保存与计划基准保护

版本 v1.0，2026-10-11，详细设计工作版。统一契约见[协作约定](../03_后端领域设计/01_领域协作契约与设计约定.md)，所有者细节见[execution](../03_后端领域设计/execution/README.md)、[planning](../03_后端领域设计/planning/README.md)。

## 1. 职责与输入

execution 接收真实事实；planning 唯一决定适用计划修订及保护范围；profile 保存身体观测；review 在提交后更新共享日结论。客户端提交 requestId、expectedVersion（纠正时）、businessDate、真实时间/内容/单位、可选目标及计划修订引用。服务端从会话取得本人，不能按输入 userId 授权。

```mermaid
sequenceDiagram
    participant C as 客户端
    participant E as execution
    participant I as identity
    participant P as planning
    participant D as MySQL同一本地事务
    participant R as review消费者
    C->>E: 保存事实/确认个人摄入
    E->>D: 开始READ COMMITTED事务
    E->>I: lockProcessingFence(本人,用途,范围)
    I->>D: 锁账户行并重新检查权限/epoch
    E->>D: 检查幂等键与请求摘要
    E->>P: protectBaseline(时间,类型,候选修订)
    P->>D: 按序锁目标/周/稳定项目或日饮食槽
    P-->>E: 不可变基准引用与保护范围
    E->>D: 保存事实修订/多目标引用/范围token
    E->>D: 同事务保存结果与可靠事件登记
    E->>D: COMMIT
    E-->>C: 已保存factId/version，结论待更新
    D-->>R: 提交后至少一次交付事实变更
    R->>R: 去重并标记来源变化，刷新共享日结论
```

## 2. 原子性与保护规则

execution 开启事务，planning 的 protectBaseline 必须参与已有事务；任何归属/版本/字段/写入失败共同回滚。按账户栅栏→幂等→Goal→WeekPlan→项目保护→事实的顺序，多项目按 ID 排序。记录无计划时引用 NULL/空集合；不补造过去计划。

| 类型 | 保护与日期口径 |
| --- | --- |
| 训练/学习 | 保护执行时对应目标及项目修订；部分/明确未执行与未登记分开，计划组数不变成实际组数 |
| 睡眠 | 完整事实按起床日定位；START 可用已发生 beginAt、未知 endAt 和暂定预计起床日，不算完整睡眠；finish 使用真实起床日。开始时间在前一夜，周日夜至周一晨归下周；不能以“周一仍未来”追溯发布 |
| 摄入 | 必须本人核对个人实际份量，分析草案不入账；锁用户/日期总量保护槽并保护已开始餐次。同日已有自主摄入也禁止事后加当日新总目标，未开始餐次仅在保留总量与已开始部分的约束下调整 |
| 身体观测 | 直接走 profile 公开命令，不在 execution 再建另一份身体测量事实；单次训练感受仍归 execution |

风险限制不得阻止如实记录已发生事实；planning 使用 profile 事实与 execution 提供的 FitnessEvidenceReader 对后续活动评估。限制判定不等待 AI，读证据端口不再次调用 planning。

## 3. 修正、删除与失败恢复

纠正同 factId 生成新修订，保留原始适用基准；真实归属日变化递增旧日与新日的范围 token。已登记的保护不因普通误记删除而解除；历史目标不重新计算成更容易达标。共享饮食/睡眠正文只有一份，多目标基准有冲突先选择，汇总按 factId 去重。

摄入纠正移日还需在同事务建立新日的总量保护，原保护保持；sleep 预计日与真实起床日变化保留开始引用。原基准日期不匹配用 baselineDateMismatch 明确展示，review 不把原引用套作新日应执行目标或计算虚假达标率。

事件失败不回滚已提交事实；review 查询与确认同步核验范围 token，即使事件未消费也识别旧确认。响应丢失用同 requestId 查/重试原结果；同键不同输入 409，业务冲突不静默覆盖，数据库瞬态失败有限重试。

隐私删除按 identity 请求清理正文、历史、图片关联与派生快照，旧 AI 不能恢复；普通误记删除与隐私删除采用不同语义。对象存储清理在事务外，未完成阶段保持真实状态。
