# 用途授权、导出删除与注销协作

版本 v1.0，2026-10-11，详细设计工作版。请求和阶段所有者为[identity](../03_后端领域设计/identity/README.md)，各域负责自己的正文、历史与派生副本。共同用途与栅栏见[协作约定](../03_后端领域设计/01_领域协作契约与设计约定.md)。

## 1. 资格变化先于异步清理

授权撤回、删除和注销在用户栅栏内递增 authorizationVersion（授权变化时）/deletionEpoch，并记录明确范围；范围内普通写入与旧任务接纳即刻受限。正在外部供应商执行的请求只能尽力取消，返回不能重新恢复内容。重新授权创建新上下文，旧 epoch 不恢复资格。

```mermaid
sequenceDiagram
    participant C as 用户
    participant I as identity
    participant D as MySQL
    participant O as 六域及infrastructure
    participant X as 对象存储/供应商/备份处理
    C->>I: 确认删除范围或注销
    I->>D: 锁用户栅栏，幂等保存范围/epoch/请求
    I->>D: 同事务登记DataRequestCreated
    I-->>C: 202 requestId和真实处理状态
    D-->>O: 至少一次通知各持有者
    O->>I: 申请受限DATA_REQUEST_WORKER上下文
    O->>D: 分批短事务锁栅栏清理正文/历史/派生物
    O->>X: 事务外清理文件/处理方数据
    X-->>O: 完成证明或待处理/失败
    O->>I: reportDataRequestStage(阶段版本/结果)
    I->>I: 只在必要阶段全部成功或确无数据时完成
    C->>I: 查看进度（注销后受限进度凭据）
    I-->>C: 实际完成/未完成范围与可恢复阶段
```

## 2. 范围、阶段与真实回执

请求通知 identity/profile/planning/execution/review/ai 及 infrastructure；未拥有选中正文也要检查派生快照、任务输入/结果和事件载荷。阶段按 MODULE_DATABASE、OBJECT_STORAGE、PROCESSOR、BACKUP 跟踪；确无数据/无处理方可 SKIPPED 并说明，未知政策或第三方无证明保持 PENDING_POLICY/PENDING_EXTERNAL，不能以超时或“已软删”宣称完成。

| 请求 | 所有者行为 |
| --- | --- |
| 导出 | 各域提供真实 snapshotAt、范围和修订清单，组合快照注明采集区间；不宣称跨域同一瞬间。导出包含范围内历史及未知/估算来源。下载再次检查账户/用途/epoch |
| 指定删除 | 清理所选正文、历史、衍生快照及外部关联；只删照片时是否保留已确认人工摄入按已确认范围决定。汇总重算，关联结论失效，未来计划不自动变化 |
| 注销 | 撤销普通会话与处理资格，账户进入 CLOSING；受限清理/进度凭据继续工作。必要阶段完成后 CLOSED，不把归档目标当注销 |
| 撤回可选授权 | 限制对应处理，保留适用手工/学习功能；已发出外部调用如实跟踪。旧导出文件因 epoch 改变不得无条件下载 |

基础设施处理公共幂等敏感响应、消费记录、持久事件载荷、临时导出；各域同时处理自己的引用，不因其为“历史”免除范围内删除。已删除后的防重摘要或最小请求回执是否保留、多久保留由明确保留策略决定，文档不编造期限。

## 3. 幂等、重试及权限

回执按 requestId/module/stage 和单调 receiptVersion 幂等，迟到回执不能把成功回退或以旧快照覆盖当前结果。清理批次可重入，外部产物记录稳定引用；失败阶段可恢复重试，不重复重建导出或请求。

DATA_REQUEST_WORKER 限已受理范围，STAGE_REPORTER 只报进度；在 CLOSING/CLOSED 仍能处理该请求，不取得一般业务权限。身份凭据和进度凭据分开；对外状态不暴露供应商密钥、其他用户路径或完整私人事实。
