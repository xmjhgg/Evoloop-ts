# ADR-002：事实与计划锁定原子提交，分析通过可靠异步完成

| 项目 | 内容 |
| --- | --- |
| 日期 / 状态 | 2026-10-10 / 建议采用，第一版设计 |
| 对应规则 | BR-COM-003/004/009/011/012/014/017；BR-FIT-003/004/008/010/015 |

真实执行保存由execution应用用例开启事务，通过planning公开命令核验并锁定适用计划项目，再写事实、版本、幂等结果和事件登记，使用同一MySQL事务。计划确认争用相同稳定项目锁并核对最新状态，防止实际已提交后被改写基准。

日结论/周复盘和AI任务在提交后处理。事件持久登记与业务同事务，提交后至少一次消费，消费者幂等；AI任务自身保存状态、重试与租约。采用Spring Modulith JDBC事件登记作为候选实现，初始化时验证迁移、序列化、重试和重启恢复，不重复维护并行Outbox。

异步事件未消费期间，旧结论不能被当作最新已确认：查询及确认须比较计划、事实、资料和人工内容的最新引用版本，给出待更新/过期状态。旧AI返回在业务所有者接纳前再次核验；任务调用成功和业务已接纳分开记录。

不在数据库事务里等待AI或外部文件服务。导出/删除/注销按阶段记录真实结果，外部清理未完成就保持处理中/部分失败，允许重试，不能宣称所有阶段已经完成。

代价是需要持久任务、版本引用、锁顺序和恢复测试。得到的约束是实际保存独立于AI成功，历史基准受保护，原有人工确认流程保持明确。
