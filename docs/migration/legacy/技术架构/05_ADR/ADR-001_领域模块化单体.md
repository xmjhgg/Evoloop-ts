# ADR-001：首版采用领域模块化单体

| 项目 | 内容 |
| --- | --- |
| 日期 / 状态 | 2026-10-10 / 建议采用，第一版设计 |
| 背景 | React客户端、Java Spring、MySQL已由用户指定；目标、计划、实际和结论存在频繁的版本与事务核验 |

首版一个Spring Boot应用、一个MySQL业务库。按identity、profile、planning、execution、review、ai六个上下文组织代码，workspace仅组合页面查询，shared仅基础类型。各模块对外公开契约，领域模型和仓储封闭在内部，用结构检查执行边界。

该方案让小团队先实现完整闭环，并保留清晰的数据归属与后续拆分点。代价是各模块共享部署和故障影响范围，需要通过依赖检查、独立模块测试、AI任务隔离及指标保持可维护性。

没有按前端四个tab划分后端服务，也没有为健身/学习各复制账户、计划、结论流程。健身/学习专属模型在核心上下文内扩展。

后续出现独立团队、明显的容量瓶颈或差异化发布需求时，先评估AI Worker独立部署，再考虑业务服务拆分。拆分须追加ADR、重新定义跨库事务/事件契约与恢复策略。
