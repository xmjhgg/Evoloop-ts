# ADR-003：短事务用户处理栅栏与来源范围版本

| 项目 | 内容 |
| --- | --- |
| 日期 / 状态 | 2026-10-11 / 详细设计建议，待评审与真实 MySQL 验证 |
| 背景 | 计划发布、事实新增/修正、授权撤回、结论确认和 AI 接纳都要求“核验的依据仍最新”；仅靠异步失效标记或已有事实 ID 无法覆盖新增和删除 |
| 依据 | [整体领域边界](../03_后端领域设计/00_整体业务领域设计.md)、[统一协作契约](../03_后端领域设计/01_领域协作契约与设计约定.md)、[ADR-002](ADR-002_事务与异步一致性.md) |

V1 在 READ COMMITTED 短事务内先通过 identity 公开接口锁定本人账户根行，作为处理栅栏；所有影响业务依据、授权及删除状态的短写遵约。确认、接纳和需要准确最新性标记的读取在持栅栏期间采集/校验来源。外部调用和长时间任务执行释放数据库锁，通过持久任务继续。

同用户短写串行，避免“先验证结论、后有新事实插入、再发布旧依据”的窗口；不同用户不共享栅栏。它仍配合稳定项目保护锁，不以账户行代替领域保护状态。锁顺序与后台场景遵循统一契约，不能先锁任务再锁账户。

各领域维护自己的 scope token。来源集合同时记录对象修订 refs 与范围版本 scopeTokens；在相同事务内新增、纠正、删除或改变确认状态时递增相关范围版本。不存在范围逻辑版本为 0，首个新事实建立为 1，因此空范围的结论也能检测后来新增。

授权版本及 deletionEpoch 另行核验。删除后需要继续跟踪的请求阶段由受限上下文处理，不获得普通业务权限；范围版本不保存事实正文，也不替代隐私清理。

代价是同一用户的高并发短写和准确查询会竞争账户行；需要缩短事务、批量公开读取并监控等待时间。首版个人目标管理的访问规模适合先验证此保守方案。若吞吐证据要求拆分，可改为按用途/目标/日期的栅栏或事务性版本 CAS，但必须证明跨范围新增、撤回、删除和来源核验仍安全，另加 ADR。

进入实现前验证：两连接并发事实与计划发布、补记与结论确认、授权撤回与 AI 接纳；重启/重复事件不回退 token；不存在范围第一次插入使旧结论过期；数据库瞬态失败可重试而业务冲突不覆盖。当前文档检查不能代替这些集成测试。
