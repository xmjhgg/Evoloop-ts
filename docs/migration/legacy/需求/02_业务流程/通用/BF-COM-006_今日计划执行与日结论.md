## 1. 业务目标与触发

用户先看今日，按计划执行后反馈，程序输出今日执行结论并在同页呈现。

## 2. 前置条件与边界

可有多个目标，也可无计划自主记录。首次进入优先展开健身，学习折叠摘要可展开；无健身则展开首个可用目标，分类或展开不会复制今日或复盘对象。 所有数据限本人；业务状态、日期与版本按公共规则。四个 tab 是同一闭环的视图，不创建四套重复对象。

## 3. 主业务流程

| 步骤 | 执行方 | 动作与结果 | 关联用例/规则 |
| --- | --- | --- | --- |
| S01 | 系统/用户 | 默认展开健身；展开目标内左列今日计划、右列今日执行，同项目成对排列 | UC-COM-011、UC-FIT-008 |
| S02 | 用户 | 登记真实训练饮食睡眠或学习结果 | UC-FIT-009、UC-FIT-010、UC-FIT-011、UC-FIT-012、UC-FIT-013、UC-FIT-014、UC-LRN-002 |
| S03 | 系统/AI | 事实先保存，右列更新；自动生成更新同日日结论，将该目标分段显示在左右对照区下方 | UC-COM-012、UC-FIT-017 |
| S04 | 用户 | 在对照区下方今日复盘结论中补充纠正并确认明确范围 | UC-COM-013、UC-FIT-018 |
| S05 | 系统 | 复盘读取同日日结论与确认状态 | UC-COM-013 |
| S06 | 用户 | 如需改变未来，主动提出调整草案 | UC-COM-015、UC-FIT-019 |

## 4. 替代与异常流程

| 分支 | 条件 | 处理与结果 |
| --- | --- | --- |
| ALT-01 | 未登记/待执行/休息/暂停 | 分别展示，不能等同失败 |
| ALT-02 | 饮食照片只分析未确认 | 不计摄入、不触发新的事实结论 |
| ALT-03 | AI 失败或旧返回 | 实际仍保存，显示待生成/过期，可人工确认有限结论 |
| ALT-04 | 结论确认后继续登记 | 旧确认保留历史，最新日结论与派生周报告需更新 |
| ALT-05 | 切换类别/展开目标/收起卡片 | 同一时刻最多一目标展开；只改显示，不登记实际或改确认状态；无匹配目标显示空状态 |
| ALT-06 | 只有学习或使用窄屏 | 学习直接默认展开可反馈；窄屏保留左计划/右执行，结论在下方可纵向阅读，无横向溢出 |

保存失败/不明时先核实结果再重试，不虚假报成功；AI 可退出等待，失败保留事实、旧计划和草案，旧依据返回不能覆盖新版本。拒绝可选授权保留与之无关的人工能力。

## 5. 输入、输出与状态

输入：当前适用计划与实际记录。输出：分目标日结论和日总览。事实保存成功独立于生成成功；日结论确认不改计划。
