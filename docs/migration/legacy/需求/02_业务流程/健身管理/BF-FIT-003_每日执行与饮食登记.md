## 1. 业务目标与触发

从今日健身主区域查看安排并反馈真实执行，日结论在同页更新。

## 2. 前置条件与边界

BF-COM-006 的健身扩展；无计划允许记录，食物分析先为草案。 所有数据限本人；业务状态、日期与版本按公共规则。四个 tab 是同一闭环的视图，不创建四套重复对象。

## 3. 主业务流程

| 步骤 | 执行方 | 动作与结果 | 关联用例/规则 |
| --- | --- | --- | --- |
| S01 | 用户/系统 | 今日默认展开健身；左计划/右执行按训练、饮食、昨夜睡眠成对展示，训练左列含当日动作组数与数量单位 | UC-COM-011、UC-FIT-008 |
| S02 | 用户 | 从右列反馈训练状态、实际时长与感受，或登记昨夜睡眠与身体状态；实际动作组次可选，不从计划自动填写 | UC-FIT-009、UC-FIT-010、UC-FIT-011 |
| S03 | 用户/AI | 选择拍照分析或手工填写食物草案 | UC-FIT-012、UC-FIT-014 |
| S04 | 用户/系统 | 核对个人实际吃下份量并确认入账 | UC-FIT-013 |
| S05 | 系统/AI | 更新右列实际和覆盖，触发对照区下方健身今日复盘结论；引用同一归属日日结论 | UC-COM-012、UC-FIT-017 |

## 4. 替代与异常流程

| 分支 | 条件 | 处理与结果 |
| --- | --- | --- |
| ALT-01 | 共享菜/剩菜/多照片 | 按个人份量核对，同餐多图不重复 |
| ALT-02 | 营养未知/无目标 | 未知不零，无目标只显示小计与完整性 |
| ALT-03 | 记录失败/AI 超时 | 记录与分析状态分开；成功事实不回滚 |
| ALT-04 | 未来任务或今晚睡眠 | 不当今日已发生事实 |

保存失败/不明时先核实结果再重试，不虚假报成功；AI 可退出等待，失败保留事实、旧计划和草案，旧依据返回不能覆盖新版本。拒绝可选授权保留与之无关的人工能力。

## 5. 输入、输出与状态

实际训练/睡眠/状态直接保存事实；饮食仅确认实际食用后入账。输出归属日汇总和待确认日结论；计划不自动改变。
