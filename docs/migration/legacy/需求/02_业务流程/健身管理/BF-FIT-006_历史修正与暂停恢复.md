## 1. 业务目标与触发

在复盘查看纠正历史，在计划安排管理健身目标暂停与恢复。

## 2. 前置条件与边界

历史事实与执行时目标均保留可追溯版本，归档不是删除请求。 所有数据限本人；业务状态、日期与版本按公共规则。四个 tab 是同一闭环的视图，不创建四套重复对象。

## 3. 主业务流程

| 步骤 | 执行方 | 动作与结果 | 关联用例/规则 |

| S01 | 用户 | 按日周查看计划实际与结论历史 | UC-FIT-022 |
| S02 | 用户/系统 | 补记修正或删除误记，重算受影响依据 | UC-FIT-015、UC-FIT-016、UC-FIT-023 |

## 4. 替代与异常流程

| 分支 | 条件 | 处理与结果 |
| --- | --- | --- |
| ALT-01 | 历史修正 | 旧结论及调整草案需更新，已确认未来计划不自动改 |
| ALT-02 | 暂停期自主执行 | 保留事实，不作普通缺勤 |
| ALT-03 | 恢复未确认草案 | 显示待规划，不直接复用旧过期计划 |
| ALT-04 | 只暂停健身 | 学习目标不受影响 |

保存失败/不明时先核实结果再重试，不虚假报成功；AI 可退出等待，失败保留事实、旧计划和草案，旧依据返回不能覆盖新版本。拒绝可选授权保留与之无关的人工能力。

## 5. 输入、输出与状态

事实变更→对应日周汇总与结论失效；状态暂停→待规划→重新确认生效。历史计划基准不追溯改写。
