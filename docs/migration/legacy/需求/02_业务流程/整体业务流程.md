## 1. 主闭环

产品先进入今日，默认全部类别并优先展开健身，学习以折叠摘要参与同一个闭环；无健身则展开首个可用目标。四个底部入口固定为：今日、计划安排、复盘、我的。

```mermaid
flowchart TD
    A[打开产品与本人会话] --> T[今日: 默认健身展开 / 左计划右执行 / 下方日结论]
    A --> M[我的: 身体/作息/可用时间/模块基础]
    M --> G[计划安排: 分类大目标]
    G --> W[目标下本周与下周]
    W --> D[逐日手工或AI草案: 动作/组数/数量单位/休息]
    D --> C[审查并确认未来计划]
    C --> T
    T --> E[执行后保存真实反馈]
    E --> R[自动更新日结论: 分目标+总览]
    R --> U[今日补充并确认日结论]
    U --> V[复盘: 历史日结论与计划实际]
    V --> P[结合每日结论生成并确认周复盘]
    U --> J[选择是否提出未来调整]
    P --> J
    J --> D
```

## 2. 页面职责与入口

| 页面 | 首屏及主操作 | 业务结果与关联流程 |
| --- | --- | --- |
| 今日 | 默认健身展开，其他目标折叠可切换；展开卡内左计划/右执行，成对展示项目，下方该目标今日复盘结论；无健身仍可使用 | 事实先保存、自动更新结论、人工确认；BF-COM-006、BF-FIT-003/004、BF-LRN-001 |
| 计划安排 | 先列大目标/类别，再按目标展示周计划；本周默认展开，下周同时可见；每日训练动作/组数摘要与详细字段，可在周/日编辑中独立增删修改 | 目标与日安排草案→审查→确认；BF-COM-004/005、BF-FIT-001/002 |
| 复盘 | 按目标/日/周回看每日结论及计划实际，周复盘与未来差异 | 确认判断后主动提出调整；BF-COM-007、BF-FIT-004/005/006 |
| 我的 | 身体测量、常规作息、时间/器材/学习基础、授权与账户 | 资料版本与规划依据，不管理大目标实体；BF-COM-002/003 |

## 3. 用户使用路径

### 首次使用

登录后先展示今日空状态。用户可直接手工记录；也可去计划安排建立健身/学习大目标，按需要在我的补充条件，再安排该目标本周剩余日期和下周。草案审查后用户确认，今日显示生效安排。缺少个性化条件只限制相应建议，不强迫所有用户先填健身档案。

### 每日使用

默认查看健身展开卡，按需切换学习；左计划/右执行→执行→从右列反馈真实状态与量。训练/睡眠/学习事实保存后即成立；饮食需核对个人实际食用才入账。程序自动更新当日日结论，在展开卡左右对照下方呈现目标分段，用户补充原因并明确确认范围。复盘读取同一结论；一天内继续记录会使旧确认失效，提示重核，不把早先判断当作全天最终结论。

### 每周使用

计划安排随时可维护下一周，不必等待复盘。训练日明确每天练哪些动作、每动作几组、每组数量与单位、组间休息；每天独立编辑并保存，休息日不强制力量动作。动作变更也须重新审查，确认才发布未来版本。用户在复盘选大目标/周，查看每天结论状态、每日计划和实际，再生成/补充/确认周判断。周中开始或提前复盘明确覆盖和截至时间，允许有限依据，不自动认定缺失日失败。

### 依据复盘调整

从最新已确认日/周结论选择明日、剩余周或下一周→展示原/新/理由/日期→合并到同目标同周工作草案→编辑/审查→确认未来版本。确认结论与确认计划是两个动作。周日明日和下周周一是同一对象，其他日期与其他目标保持。已开始、已有实际的目标不追溯修改。

### 历史与状态

从复盘补记/纠正事实，更新归属日与周结论并使旧确认失效；已确认的未来计划不会自动变化。在计划安排暂停/恢复/归档某目标，仅作用于选定未来范围。我的改资料后提示重新规划，不能静默改当前计划。

## 4. 模块边界与复用

- 通用：本人权限、资料、分类目标、周每日安排、计划审查确认、今日总览、日结论、目标周复盘、未来差异与状态协议。
- 健身：增肌/减脂方向、训练、食物分析与实际摄入、睡眠、身体反馈、健康限制。原编号保留，通过通用流程扩展专属字段。
- 学习：主题、基础与资源、逐日内容/时段/数量、实际成果，参与同一日周复盘。首版不扩展课程平台、自动评卷或成绩预测。
- 工作/财务、设备同步、跨模块自动调度延后。原型的固定日期、历史样例与模拟AI不构成生产需求的事实/计算方式。

## 5. 可核对的闭环例子

用户有减脂目标和阅读目标；本周六训练45分钟、阅读30分钟。执行反馈训练30分钟、阅读20分钟，今日保留两个原目标与部分执行，输出有限覆盖日结论。用户确认“加班导致时间不足”，周复盘结合每日结论确认下周时间限制。提出下周训练45改30分钟的草案，确认结论不会立即改计划；审查并确认未来计划后下周内容变化，今天45分钟基准仍保留。之后补记今日一餐，只更新今日与本周结论，不改已经确认的下周安排。
