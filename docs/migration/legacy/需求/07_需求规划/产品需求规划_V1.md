## 1. 产品定位

EvoLoop 是以“目标 → 周/每日计划 → 实际反馈 → 日/周结论 → 未来调整”为核心的 AI 自我管理工具。用户先看今日，各模块围绕分类大目标组织，健身是主要模块之一。首版完整保留健身训练、饮食、睡眠闭环，同时纳入轻量学习目标与执行。

首版解决：把大目标变成每周每天可执行安排；在同一今日页对照计划与实际并取得日结论；通过每日结论和周复盘决定未来变化。我的登记真实身体、作息与可用条件，辅助 AI 规划。

AI提供草案和分析，用户确认判断与计划。效果通过安排可执行、反馈真实、结论有依据和变化可确认体现，不承诺统一身体改善或学习分数。

## 2. 长期模块规划与首版边界

| 模块 | V1范围 | 后续范围 |
| --- | --- | --- |
| 通用 | 本人会话/授权、个人资料、分类目标、手工/AI辅助周每日草案、审查确认、今日计划实际、日结论、目标周复盘、未来差异、历史与状态 | 跨模块自动排程等另行评审 |
| 健身 | 主要模块；方向增肌/减脂，训练、日饮食目标、拍照估算与个人份量确认、睡眠、身体状态、日周复盘和调整 | 深度设备/专业服务另行评审 |
| 学习 | 轻量模块；自定义目标/主题、基础与资源、逐日内容/时段/数量/成果、实际反馈、复用日周结论与未来调整；今日显示紧凑 | 课程平台、自动评卷、成绩预测不属首版 |

## 3. 首版用户与分类目标

### 3.1 用户与个人条件

同一“个人用户”角色管理本人多个分类目标，健身/学习不是权限角色。个人身体、常规作息、可用时间与模块条件在我的维护，资料可分步填写；只学习不要求身高体重等。

首版健身个性化建议仍优先面向18～64岁的普通成年人，支持新手和已有训练经验者；这是健身服务范围，不作为创建学习目标的限制。

健身个性化建议沿用原普通成年用户范围及相关限制：未成年人、孕产期、需要疾病管理/康复处方等不进入默认个性化训练饮食生成，保留适用手工记录与专业指导提示。该限制只影响相应健身能力。具体规则与适用边界上线前审核。

### 3.2 目标设计

| 目标内容 | 规则 |
| --- | --- |
| 通用大目标 | 名称、健身/学习类别、描述/衡量方式、开始与可选结束日期、稳定身份、版本和状态 |
| 健身专属 | 方向仍增肌/减脂；目标体重可选；睡眠恢复是计划内容，不要求额外习惯目标 |
| 学习专属 | 自定义主题、期望成果、可选期限；基础与资源引用我的条件；不复用营养/训练必填 |
| 下属计划 | 每个目标有本周/下周等周计划，周下详细每日内容；各日可不同 |

大目标在计划安排管理，个人资料在我的管理。目标修改形成版本；已有计划不得直接把类别换成另一模块，需另建目标。暂停/归档保留历史，恢复重新规划未来。目标或资料修改均不自动替换生效安排，不回写历史目标与实际。

## 4. 核心流程

```mermaid
flowchart TD
    A[本人会话: 首先进入今日] --> M[我的: 身体/作息/可用条件]
    M --> G[计划安排: 健身/学习大目标]
    G --> W[目标下本周/下周与每日动作明细草案]
    W --> C[手工/AI编辑: 审查后确认]
    C --> T[今日: 默认健身展开 / 左计划右执行 / 下方结论]
    T --> E[执行反馈先保存真实事实]
    E --> D[程序自动更新今日日结论]
    D --> U[用户在今日补充并确认]
    U --> R[复盘: 日历史/目标周结论]
    R --> P[确认周判断并选择未来调整]
    U --> P
    P --> W
```

### 4.1 第一次使用

登录后显示今日空状态，可自主记录，或去计划安排建立分类大目标。根据规划需要在我的补充条件，再手工或AI辅助安排目标下本周剩余日期及下周每日内容。审查最新草案、明确确认未来范围后，今日读取生效安排；不强制先健身或先生成AI整周方案。

### 4.2 每日使用

首次进入今日默认全部类别并优先展开健身，其他目标折叠摘要；无健身则展开首个可用目标。展开卡内左列今日计划、右列今日执行，同项目成对排列，下方今日复盘结论。按需切换目标查看计划，执行后从右列反馈训练/学习状态与实际量，昨夜睡眠按真实时间登记，饮食照片估算需核对个人实际份量后确认入账。程序在事实保存后自动更新日结论，刷新右列实际与卡片下方的目标结论分段；分目标结论和当日总览仍属于同一归属日日结论。用户补充原因并确认；复盘读取同一结论和状态。当天继续登记或修正会使最新确认失效，保留旧版历史并提示重核。

### 4.3 每周与调整

计划安排默认展示每个目标本周与下周，可随时详细规划下周，不依赖先完成周复盘。复盘按目标/周结合日结论、计划与底层事实，明确每天确认状态、截止、覆盖和缺失，用户补充并确认周判断。

根据最新已确认日/周结论选择明日、剩余周或下周→查看原/新/理由/影响日期→合并同目标/周草案→编辑审查→确认未来版本。确认复盘不发布计划。周日明日与下周周一用同一对象，已开始/有实际目标不追溯改变。没做周复盘仍可有限依据独立安排下周。

## 6. 我的资料与个性化输入（F-01、F-18）

个人资料在我的分步填写；大目标在计划安排。下表为健身专属必要信息，不作为学习或进入今日的必填。学习只维护主题、基础、资源与可用时间；共同时间和作息引用本人版本。

| 信息组 | 首次使用的必要信息 | 可选信息 |
| --- | --- | --- |
| 目标引用 | 读取计划安排中当前健身方向（增肌/减脂） | 目标描述、体重或期限在目标入口维护，不在我的重复创建 |
| 适用范围 | 年龄段；是否存在需专业指导的健康或伤病限制，可选“不确定” | 用户主动补充的限制说明 |
| 训练条件 | 当前经验、常见活动、可训练日期、每天时长、场地和器材 | 动作偏好、已有训练习惯 |
| 饮食条件 | 饮食禁忌或过敏情况（可选“无已知”或“不确定”）、就餐方式 | 预算、口味、食材偏好 |
| 作息 | 通常入睡与起床时间、工作日作息限制 | 近期睡眠感受、特殊班次 |
| 饮食目标计算 | 请求 AI 生成数值目标时，补充所选估算方法必要的年龄、身高、当前体重、活动水平等参数，并说明用途 | 围度、历史趋势等；适用的生理参数仅在计算需要且用户同意时收集 |

“不确定”不能被解释成“没有风险”；涉及个性化建议必要信息不足时，说明缺少什么，提供一般习惯建议或仅记录模式。用户拒绝可选信息，不影响与该信息无关的功能。

计算所需参数缺失时，明确缺失项，允许用户补充或手动填写自己的每日饮食目标后进行适用的审查；不凭照片、微信资料或姓名猜测身体参数，也不填入伪精确的个人目标。未设置数值目标时仍能拍照和手动记录，只展示摄入估算，不计算目标差额。原始档案变更后提示是否重新规划，不自动重写当前计划。

## 7. 周计划、自定义编辑与每日饮食目标（F-02、F-03、F-15）

### 7.1 周计划内容

每份周计划归属一个大目标与周。一份周计划包含周期、制定依据、周重点、逐日安排、备选方案、限制、版本与确认时间。计划安排先展示大目标，本周默认展开且下周可见，手工可逐日安排，AI可辅助生成；下表展开健身专属内容，学习内容按自身单位复用周每日协议。

| 维度 | 每日安排的最小内容 | 记录粒度 |
| --- | --- | --- |
| 训练 | 训练或休息；每日独立动作名称、组数、每组数量及次/秒/分钟单位、组间休息秒；时间、地点/器材、时长、强度描述及替代方案 | 状态、实际时长、感受；实际逐动作组次及负重自愿填写，不从计划自动登记 |
| 饮食 | 当日热量、蛋白质、碳水、脂肪目标；主要餐次分配及食物建议 | 照片或手动食物明细；实际食用份量；用户确认后的摄入估算 |
| 睡眠 | 目标入睡与起床时间、睡前习惯、与训练恢复的配合 | 实际入睡/起床、主观质量和次日疲劳 |

训练安排必须明确休息和恢复，不能把每天都训练作为默认要求。饮食建议优先适应用户实际条件，例如食堂、外卖或自炊。运动安排采用逐步建立习惯的原则；WHO 指南支持从少量活动开始并逐步增加，参考 [WHO 2020 指南](https://iris.who.int/bitstream/handle/10665/336656/9789240015128-eng.pdf?sequence=1)。

### 7.1.1 每日训练动作明细

周列表显示各日期的训练/休息与动作组数摘要；展开某日显示动作名称、组数、每组数量/单位、组间休息，并汇总动作数与总组数、时间和地点。不同日期使用各自组合，不以整周同一自由文字替代。力量或按组动作明确练几组及每组练多少，计时动作用秒/分钟，连续活动可按持续时长安排，休息日不强制力量动作。

动作名去除空白后非空；力量训练至少一项动作；组数及次数为正整数，计时数量为正数；单位必选为次/秒/分钟；按组动作休息秒数非负，0表示连续。非法值定位到日期/动作/字段，保留输入，不能保存成有效待审查草案或确认；修正后重新校验审查。这些是字段完整性规则，原型例子和输入上限不作为生产训练强度或健康阈值。

未开始日切换为休息后不再要求力量动作；切换为力量后须补齐有效动作，及时展示对应字段。未来草案完整保存每个日期的列表与字段，审查确认只替换可调整范围；已开始/已有实际的动作基准、历史目标和执行保持。旧计划的自由文字保留，不猜未知组数；未来编辑或生成时补齐明细。

### 7.2 修改与审查

用户可在周编辑或单日编辑中增删某日动作、修改动作名称/组数/每组数量与单位/组间休息，并修改日期、时间地点、时长、每日热量及营养素目标、餐次分配、饮食选择、睡眠安排，以及用文字描述调整意图。两入口读写同一工作草案，每天动作独立；只修改指定字段，保留其他日期与未涉及内容。AI 文字修改先转换成可查看的草案差异。

审查逐项展示“问题 → 原因 → 建议 → 影响日期”，先检查每日动作必填、数量单位和休息日适配，再检查时间冲突、器材可用性、饮食限制、每日饮食目标与餐次分配的一致性、恢复安排、目标冲突和已知风险。原始 AI 草案也必须审查，不能仅审查用户改动。

| 审查结果 | 用户处理方式 | 是否可确认 |
| --- | --- | --- |
| 无需调整 | 查看后确认 | 可以 |
| 普通优化建议 | 采纳；自定义修改；或明确选择保留原方案 | 处理普通建议后可以 |
| 必须解决的问题 | 修正不可执行冲突或产品禁止的风险内容 | 解决前不能确认 |
| 信息不足 | 补充必要信息，或改为可支持的一般建议/记录模式 | 个性化部分满足条件后可以 |

用户再次修改草案、目标或相关档案后，旧审查与其意见处理状态失效，须审查最新内容；动作名称、组数、数量、单位、休息和增删动作均属于内容变更。保存后再进入可读回完整逐日字段。确认页按日期展示动作原/新值、生效日期和变更摘要；确认的是明确版本，不能在确认后后台追加内容。

### 7.3 每日饮食目标（F-15，P0）

每个计划日具有独立饮食目标，训练日与休息日可采用不同安排，也允许保持相同目标；不强制采用复杂的饮食周期策略。

| 内容 | 首版要求 |
| --- | --- |
| 热量 | 每日目标值及合理参考范围，统一以 kcal（千卡）展示 |
| 营养素 | 蛋白质、碳水化合物、脂肪的每日目标，以 g 展示；允许给出参考范围 |
| 餐次 | 早餐、午餐、晚餐及可选加餐的目标分配、份量建议与食物替换 |
| 依据 | 主目标、身体参数、活动与训练安排、所采用的估算方法及不确定性 |
| 用户修改 | 可调整总量、营养素和餐次；更改后重新审查，确认明确的生效日期 |

AI 基于可核对的估算方法和规则生成饮食草案，解释其如何服务增肌或减脂。计算方法、参数适用范围和允许的调整边界在上线前审核，不在本需求文档直接规定所有人通用的摄入量。

餐次热量分配需与每日目标一致；营养素与总热量存在明显不一致时，提示核对并说明依据。调整总量后同步提出餐次更新草案，不能静默改写用户已确认的安排。

当日已有饮食摄入记录时，保留当日总量目标作为复盘基准；可调整未开始餐次的安排，新总量目标从次日或其他未来日期生效。

今日页分别展示“每日目标”“已记录摄入（估算）”“与目标的差额”。记录不完整时标注“尚有餐次未登记”，不能把已记录值称为全天实际摄入，也不能仅据此判定热量不足。

## 8. 执行记录与拍照饮食分析（F-04、F-05、F-13）

### 8.1 今日页

首次进入默认全部类别，优先展开首个健身卡片，学习和其他目标显示折叠摘要；无健身则展开首个可用目标。点击另一目标展开并收起原目标，点击已展开卡可收起；切换类别后优先展开筛选内健身，否则首个可用目标，无匹配则显示空状态。展开/筛选只改变显示，不改变计划、事实与结论版本。

展开卡内按同一项目展示左列“今日计划”和右列“今日执行”，下方展示该目标“今日复盘结论”及补充、确认入口。健身训练左列列出当日生效动作及组数×每组数量单位、时间地点，可进入计划日详情查看组间休息等完整字段；右列显示真实状态、实际时长、感受和反馈入口；饮食左列目标/宏量/餐次，右列确认摄入、差额、覆盖及拍照/手动记录；睡眠对照昨夜适用计划与起床日实际，今晚归属明日目标另行标明，不用于今日完成判断。学习展开后采用同样布局，保留自己的内容/单位和成果。

窄屏仍保留计划在左、执行在右，长内容换行并纵向阅读，下方结论可读，无页面横向溢出。待确认调整单独标草案，不混入当前安排；计划细化不强制实际逐动作组次登记，也不由计划推定完成。

建议操作路径：打开小程序 → 查看安排 → 快捷登记；饮食可拍照后核对食物与实际食用份量，确认保存。常规记录以约一分钟完成为体验目标，识别等待、复杂食物与详细记录另行观察，不为满足时长省略必要确认。

### 8.2 记录内容

| 类别 | 最小记录 | 自愿补充 |
| --- | --- | --- |
| 训练 | 项目执行状态；执行时的实际时长或数量；主观感受 | 重量、组数、次数；未按计划的原因 |
| 饮食 | 日期/餐次、食物明细、实际食用份量；有可靠依据时记录热量与营养素估算；明确未知项 | 食物照片、额外进食、饮料、烹饪方式、饥饿感和备注 |
| 睡眠 | 入睡时间、起床时间、主观质量 | 夜醒情况、午睡、当日疲劳 |
| 身体状态 | 可选疲劳、精神状态和不适反馈 | 可选体重、围度及测量时间 |
| 学习 | 实际状态、已执行内容及适用时长/数量；未登记单独保留 | 笔记、成果和困难；不由时长推算掌握率 |

输入校验仅保证日期、单位、格式和前后逻辑合理；超出常见范围时请用户核对，不能直接修改用户填写的值。睡眠时长计算需允许跨午夜，不按两个钟表时间直接相减。

### 8.3 执行状态

训练项目区分：已完成、部分完成、明确未执行、未登记。未来任务另显示“待执行”。饮食记录另区分分析草案、待确认与已确认；目标比较以已确认的实际食用记录为依据。

- “未登记”表示信息缺失，不认定失败，也不推断实际完成。
- 部分完成保留实际数量或描述，不强行换算成统一分数。
- 休息日展示“计划休息”，不算缺勤；额外训练单独记录，不抹去原安排。
- 饮食和睡眠以真实记录及与目标的比较为主，不强迫用户把所有现实情况归入简单对错。
- 允许补记、修正和删除误记；保留更新时间，相关复盘提示记录已变化。
- 无生效计划时仍可手动记录，展示“暂无计划”，之后生成计划不追溯替这些记录补目标。

### 8.4 拍照分析食物热量（F-13，P0）

主流程：**拍照或选图 → AI 识别食物与估算份量 → 展示热量结果 → 用户修正 → 确认实际食用 → 保存并汇总**。

1. 选择日期和餐次，拍摄或从相册选择食物照片；同一餐可补充多张照片。
2. AI 输出各食物名称、估算可食份量、每项与整餐热量、可估算的营养素、主要假设，以及需要核对的地方。
3. 结果明确标为估算；份量、烹饪油和酱料等不确定时给出参考范围或待补充项，不能伪造经过校准的准确率。
4. 用户可增删食物，修改识别名称、重量/份数、烹饪方式，补充饮料和配料；修改相关输入后重新计算对应明细。
5. 确认自己实际吃了多少，可填写克数或整份的比例；整盘食物、多人共享菜和剩菜不能默认全部算作个人摄入。餐前照片可先存草案，实际食用后再确认。
6. 用户确认后，将实际食用部分写入饮食记录并更新今日摄入；AI 结果不自动变成已发生的饮食事实。

同一餐的不同角度照片用于补充识别，结果需合并核对，不能按照片张数重复累计。上传重复照片或重复点击保存时提示核对，并确保同一记录只入账一次；同一照片在不同餐次再次使用时不能直接判定为重复进食。

支持外卖、食堂、家常菜、混合菜、零食和饮料。对模糊、遮挡、非食物或无法判断份量的照片，允许补拍、文字补充或手动输入，失败时保留已填写内容。识别不到营养数值的食物仍可保存文字记录，热量标为未知，不当作零。

照片分析与营养估算需要份量和成分依据；研究数据也包含成分重量及营养标注，参考 [Nutrition5k 官方数据说明](https://github.com/google-research-datasets/Nutrition5k)。因此首版采用“估算 + 用户核对”的产品流程，不承诺仅凭单张照片得到精确摄入。

营养结果记录来源与适用份量，可来自已接入的食物成分数据、用户填写的包装标签、人工输入或明确标注的 AI 估算。可参考 [USDA FoodData Central 官方接口说明](https://fdc.nal.usda.gov/api-guide/)评估数据来源；实际选型需验证中文食物覆盖和使用条件。不能把模型生成值标记成数据库实测值，也不把未知营养素补为零。

### 8.5 摄入汇总与修正

- 每日摄入按归属日期，累计已确认记录的实际食用份量与对应数值；分析中、待确认、删除和重复记录不参与累计。
- 热量统一以 kcal、营养素以 g 汇总；包装标签为 kJ 或每 100 g 等口径时，先换算单位和食用份量再保存。
- 有估算范围时保留明细范围，汇总显示参考范围及缺失情况；不将范围称为统计置信区间。
- 负差额以“已记录摄入超出目标”表达，不截断为零；正差额以“与目标还差”表达，同时显示记录覆盖情况。差额只用于对照，不自动要求用户补吃、节食或额外运动。
- 修改份量、食用比例或营养数据后，更新同一记录的版本并重算日/周统计；相关复盘标记需更新，不再新增一条重复摄入。
- 无饮食目标时保留拍照与手动记录，显示摄入估算与完整性，不虚构目标或差额。

## 9. 今日日结论与未来调整（F-06）

### 9.1 自动生成与人工确认

保存真实执行反馈成功后，程序自动对照归属日适用目标和实际，更新日结论，在今日展开卡左右对照下方显示该目标分段。结论包含分目标对照和当日总览，同一归属日对象在今日/复盘共享，不为每张卡新建一份结论：事实摘要、具体进展、计划/实际差异、记录覆盖与未知、可能原因及需确认判断、保持或改变未来的建议。

训练/学习部分、明确未执行和缺失各自表达；未记录动作组次时不由计划或总时长推定各动作完成；饮食只使用确认实际摄入，营养估算标来源/范围，不从漏记断定全天不足；睡眠只评价已经发生的昨夜，身体风险继承既有边界。学习以实际内容、量与成果对照，投入时间不冒充掌握率。

用户在今日补充原因、纠正AI判断、告知现实限制，可只保存补充，核对最新内容后再确认日结论。复盘读写同一归属日对象。确认包含覆盖和截至时间，不代表全天任务全部完成。再记录/补改/删除事实或改变补充时旧确认失效，相关周复盘/调整草案提示更新。

AI失败不回滚已保存事实；展示事实摘要与待生成，允许重试或确认明确标注来源的人工结论。旧输入任务返回不得覆盖新事实/新确认；信息不足可有限复盘，不编造经历或确定原因。

### 9.2 未来调整

依据最新已确认结论主动选择明日、剩余周或下一周，展示原/新/理由/日期，合并同目标同周工作草案。没有充分理由允许保持；不同来源候选逐项选择或自定义，保留其他安排。

健身不因单次体重、一餐估算或漏餐大幅增减摄入或惩罚性运动。当天已有摄入保留总目标基准，新总量从未来生效。已开始/已有事实目标不追溯改变。保存补充、确认结论、保存调整草案、审查并确认计划分别处理；只有最后的计划确认改变未来生效安排。

## 10. 对照每日结论的周复盘与下周安排（F-07、F-08）

复盘按目标/周展示大目标、周重点、每日计划与日结论列表，每日标已确认、待确认、需更新或未生成。周分析同时核对底层事实及执行时目标版本，避免把日结论的原因推测重复当事实。

健身包含训练/恢复、饮食目标与摄入及不确定性、已发生睡眠、身体观察和计划变化；学习包含内容、实际量、成果与障碍。跨目标总览不强加同一总分。允许提前和有限记录复盘，标截至时间/覆盖/缺失，不要求七天都完整或确认。

用户可填写最有效/最难执行的安排、下周可用时间与重点，保存反馈不等于确认。确认周结论不代确认每日，也不发布下周计划。之后主动提出下周草案，标采纳结论的变化，继续编辑审查确认。

计划安排可随时独立安排下周，没有周复盘也可明确有限依据规划。历史日事实或结论变动使周确认/候选需更新，已确认未来计划不自动重写。

### 10.1 统计口径

| 指标 | 首版展示规则 |
| --- | --- |
| 训练执行 | 已完成/应执行项目，同时列部分、明确未执行、未登记；只纳入截止前生效任务，排除休息及暂停范围 |
| 记录覆盖 | 分维度已登记/应登记，已到登记时点漏记进入分母，未来排除；无计划只显示数量 |
| 训练量 | 实际时长/组次分别可核对，不合强度总分 |
| 饮食 | 按每日当时目标与确认摄入对照，范围/未知/漏餐明确，未知不零，小计不冒充全天 |
| 睡眠 | 有效记录参与时长，显示有效天数，按起床日和相应目标对照 |
| 体重/围度 | 有测量才展示数量、时间与单位，短期变化不等于确定成效 |
| 学习 | 同单位目标与实际、成果描述、未登记及投入量分别展示，不推算成绩或掌握率 |
| 日结论依据 | 各日结论状态、版本与覆盖；未确认的判断标明，周确认不改变每日状态 |

真实跨页事实只统计一次。周中起步、暂停或漏记明确覆盖，不通过改计划降低历史分母。

## 11. 日期、生效范围与版本规则

### 11.1 时间规则

V1 使用北京时间（Asia/Shanghai），一周为周一至周日。页面显示计划周期和记录归属日期。跨时区自适应后续评估。

睡眠统一按**起床日期**归档：周二晚到周三早晨的睡眠属于周三。日期 D 的睡眠目标对应 D−1 晚到 D 早晨；今日页分别展示“昨夜睡眠记录”与“今晚目标（归属明日）”。日复盘使用已经发生的昨夜睡眠，不评价尚未发生的今晚睡眠。

周日夜间睡眠归属下周一。第一次生成计划时，已经发生或开始的睡眠时段只允许记录，不追溯新增目标。周统计与引用的计划目标遵循相同归属口径。

周日的次日调整进入下周草案的周一，不能另外发布第二份周一安排：

- 尚无下周计划或草案时，生成下周草案并把周一调整合并。
- 已有下周草案时，保留其他日期安排，展示合并差异并重新审查。
- 下周计划已经确认、暂无草案时，以该生效版本创建调整草案，仅修改必要的周一项目；确认后形成新版本。
- 归属周一的睡眠等项目已经开始时，不追溯调整其目标。

### 11.2 生效与历史

1. 每个用户、目标、日期、计划项目只有一个当前生效安排，每目标/周一个当前工作草案；同一身体/睡眠/饮食事实跨目标按引用复用，不重复累计。
2. 第一次确认的周计划保留为周初基准；后续调整产生可追踪的版本。
3. 执行记录关联当时适用的计划版本。复盘主要对照执行时的目标，并单独展示与周初基准的变化。
4. 已发生、已开始或已有实际记录的项目不追溯修改目标；允许纠正实际记录，允许调整尚未开始的其他项目。
5. 全天执行状态已经登记后，不能通过删改计划降低历史应执行任务数。
6. 暂停计划从用户选择的当前或未来时间生效，仅作用于尚未开始的项目；暂停期可记录，但不新增应执行任务。恢复时重新规划剩余日期。
7. 草案保存后退出再进入可继续处理；关闭页面不代表确认。
8. 饮食目标与摄入记录均可追踪版本；当日入账后不通过降低或提高目标改写历史表现。尚未开始餐次可在保留当日目标的前提下调整安排，未来日期的目标按草案流程确认。

### 11.3 关键状态

| 对象 | 状态与流转 |
| --- | --- |
| 计划草案 | 编辑中 → 审查中 → 可确认/需修改/信息不足 → 已确认；改动后重新审查 |
| 生效版本 | 当前生效 → 被新版本替代 → 历史可查；按日期保留各项目生效范围 |
| AI 任务 | 生成中 → 成功/失败/超时；成功但依据已变化时标记过期 |
| 日/周结论 | 待生成/生成中 → 待确认 → 用户明确确认；人工补充可先保存；引用或内容变化后需更新，原确认保留历史 |
| 食物分析 | 分析中 → 待核对/需补充/分析失败 → 用户确认摄入；修改依据后重算，未确认不入账 |

审查完成不自动生效。返回内容的依据已变化时，必须更新依据后重新生成/审查；用户不能把过期结果直接覆盖到新草案。重复确认只生成一次版本。

## 12. AI 能力与质量要求

### 12.1 AI 的职责

| 场景 | AI 需要提供 | 用户决定 |
| --- | --- | --- |
| 目标建议 | 目标拆解、冲突和缺失信息提示 | 选择主目标和投入条件 |
| 周计划 | 可执行草案、安排理由和替代方案 | 修改与确认 |
| 每日饮食目标 | 基于档案的热量与营养素草案、餐次分配和估算依据 | 编辑、审查后确认 |
| 食物照片分析 | 食物、份量、热量/营养素估算、未知项和修正提示 | 核对食物、份量与实际食用情况，确认入账 |
| 计划审查 | 具体问题、严重程度和可采纳建议 | 处理普通建议；修正必须解决项 |
| 日复盘 | 对照记录、待确认判断和次日变化建议 | 补充事实、确认结论与调整 |
| 周复盘 | 周变化、执行障碍和下周重点建议 | 确定下周重点并确认计划 |

对话限定在当前目标、计划、食物分析或复盘情境中。AI 可以生成待确认的食物分析结果，不能直接写入实际执行、替用户确认计划或摄入，或把自己推测的事情当作用户经历。

### 12.2 输出约束

- 计划必须具有清晰日期、项目、单位和可记录字段，不能只返回一篇建议文章。
- 日期、汇总、版本冲突、必填项和产品禁止内容由明确规则检查，不能全部依赖 AI 的自我审查。
- 食物份量、单位换算、整餐/每日累计与目标分配由可核对的计算处理；保留数据来源和估算状态，不能依赖 AI 自由叙述决定账面总量。
- AI 引用的依据区分“用户填写”“执行记录”“一般建议”；因果推测要说明不确定性。
- 计划和审查只基于本次允许使用的数据；不虚构专业资格、测量结果或确定的身体改善承诺。
- 记录 AI 任务类型、输入版本、输出版本及所用模型/提示规则版本，便于排查效果变化；用户页面用易懂语言展示依据。
- 上线前由人工审核训练与饮食的基本规则，并用新手、时间不足、器材受限、记录不足、目标冲突和风险反馈等样例检查输出质量。
- 食物照片用有已知份量、配料或标签的样例检查名称、份量、热量及未知项处理；覆盖混合菜、油酱料、饮料、共享菜和重复照片。真实食物误差按类别记录，不直接套用研究数据集准确率作为产品承诺。

### 12.3 失败与恢复

AI 生成失败、超时或内容格式不合格时，展示可重试状态，保留原生效计划、草案与人工记录。用户可继续查看和登记；新的未审查草案不能因此直接生效。

照片上传或分析失败时，保留图片草案与文字输入，允许重试、替换图片或手动记录；未经确认的估算不入账。营养数据服务不可用时标记受影响的数值为未知或明确的 AI 估算，不能无提示地替换来源。

生成等待期间可退出页面，返回后查看结果。网络中断时明确哪些内容尚未保存；不展示虚假的保存成功。AI 返回时校验档案、草案和记录版本，旧结果不能覆盖新内容。

调用设置可调整额度与防重复策略；额度不足时明确告知，并保留已获得的结果和基础功能。模型、供应商和成本预算在技术方案阶段确定。

## 13. 健康边界与数据保护（F-09、F-10）

### 13.1 健康边界

产品提供增肌/减脂的日常健身与饮食规划。V1 产品规则禁止极端节食、脱水减重、带伤强行训练、用药或疾病诊疗建议；用户确认不能绕过这些限制。

用户报告明显不适或新增伤病限制时，停止继续提出增加强度的建议，提示暂停相关活动并寻求专业评估；今日页对关联的既有任务展示暂停提示，AI 失败时也不能继续引导用户照旧完成这些训练。暂停不删除原计划与实际记录，不能把暂停当天当作普通“意志不足”。不确定能否提供个性化建议时，保留记录并限制相应生成流程。

普通偏好与优化建议由用户选择。审查用“发现的问题/建议”表达，不能把“未发现问题”宣传为医学安全保证。

### 13.2 数据与授权

项目将健身档案与相关记录按敏感等级保护。医疗健康信息依法属于敏感个人信息，处理时落实单独同意及必要性告知；收集范围遵循最小必要原则。依据 [《个人信息保护法》第 6、28～30 条](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)。

- 收集前说明用途、范围、保存期限和授权方式；拒绝可选信息不影响无关功能。
- 仅发送本次任务所需内容给 AI，不发送微信身份标识等无关数据；服务商确定后核对其保存、训练使用及处理关系，涉及跨境时另行落实要求。以上属于上线前待核实事项，不能默认“脱敏即免除义务”。
- 用户可查阅、更正、复制/导出记录，申请删除和注销；提供便捷撤回入口。参考 [《个人信息保护法》第 15、44～47 条](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)。
- 撤回 AI 数据使用授权后停止新的相关调用，保留可独立提供的记录与查阅功能；涉及删除请求时明确范围和结果。
- 用户之间严格隔离；日志避免保存完整健康档案、身份凭据和无关原文。
- 照片仅在用户拍摄或选择后上传，不能访问整本相册；仅发送本次分析所需图片，移除不必要的位置等元数据。说明图片的处理与保存用途，撤回/删除流程覆盖原图、缩略图及关联分析结果。
- 保存与删除期限、备份清理策略、供应商信息在内测前具体化并写入隐私说明，不以无限保留作为默认政策。

### 13.3 提醒

P0 使用小程序内的待办提示。微信消息提醒列为 P1：一次性订阅需要用户触发并授权，按可用授权发送；拒绝授权不影响核心功能。参考 [腾讯云官方小程序订阅消息说明](https://cloud.tencent.com/document/product/1301/103770)。

是否具备长期订阅资格、可用消息模板及项目实际服务类目，需按小程序主体核对。产品不承诺打开提醒开关后即可无限每日推送，提醒内容也不暴露具体健康记录。

底部入口固定：**今日、计划安排、复盘、我的**。目标和个人资料分开；今日是产品首页，健身主要、学习紧凑。

| 页面 | 展示顺序与主要内容 | 关键操作 |
| --- | --- | --- |
| 今日 | 默认健身展开、其他目标折叠可切换；左今日计划/右今日执行成对排列，下方该目标今日复盘结论 | 展开/收起/筛选目标、右列真实反馈、拍照/手工摄入确认、下方补充并确认同日日结论 |
| 计划安排 | 分类大目标在上；目标下本周默认展开与下周安排；周重点、每日动作及组数摘要、动作/数量单位/休息详情，区分草案/生效 | 创建编辑目标、逐日动作增删与字段编辑、保存读回、手工/AI辅助安排、查看差异、校验重审确认、暂停/恢复/归档 |

按钮明确区分保存执行反馈、保存补充、确认日/周结论、保存草案、审查、确认计划。无目标、无周安排、有待处理草案或缺失记录各有下一步。风险提示靠近相关健身项目，不用无差别全屏提醒打断学习操作。

| A-31 | 今日默认展开与左右对照 | 首页先今日，默认健身展开、学习折叠可切换；同目标左计划/右执行，结论在下方；切换不改对象/状态，320/390像素窄屏仍可读且无横向溢出 |
| A-32 | 大目标下展示本周与下周 | 计划安排先目标/类别，每目标本周默认展开且下周可见，周下有每日详情 |
| A-33 | 逐日手工安排 | 本周/下周各日可有不同内容/时段/量及训练动作组合，某日编辑不覆盖其他日；保存草案和确认计划分开，不依赖AI生成成功来编辑 |
| A-34 | 我的条件与生效计划独立 | 身体、作息、时间和模块基础可保存，测量事实跨页复用；改资料不自动改当前计划，相关草案需复核 |
| A-35 | 反馈后日结论同步与失效 | 真实反馈成功后程序自动更新归属日日结论；今日/复盘同对象；新事实或补充变化使旧确认及周依据需更新 |
| A-36 | 周复盘结合每日结论 | 按目标对照周计划、每日结论与事实，日状态和截止/覆盖明确；周确认不代确认每天 |
| A-37 | 按确认结论调整未来 | 原/新/理由/日期可核对，形成未来差异草案，复审并明确确认才生效，已开始/有实际基准不变 |
| A-38 | 轻量学习参与闭环 | 学习目标可用，逐日内容/实际量/成果进日周结论；有健身时今日折叠摘要可展开，仅学习时默认展开左右对照与下方结论；无健身必填，不推算掌握率 |
| A-39 | 多目标事实与时间冲突 | 共享事实只统计一次，重叠时间有提示须处理，单一事实冲突目标基准须选择；不静默重排其他目标 |
| A-40 | 无健身档案与目标状态 | 无目标/计划可记录，只学习可用；暂停归档只影响指定目标未来，历史保留，恢复先规划确认 |
| A-41 | 日结论生成失败或旧返回 | 实际保存不回滚，明确待生成/过期并可重试或确认来源明确的人工结论，不编造或覆盖新依据 |
| A-42 | 同目标同周多来源草案 | 日/周复盘与手工改动合并同一工作草案，冲突逐项选值/自定义，保留其余项目，确认一次唯一生效 |
| A-43 | 每日训练安排细化 | 周列表/单日详情显示当日动作、组数、每组数量单位与休息，汇总动作数/总组数；力量日有明细，计时动作保留单位，休息日不强制动作；今日左列读取相同当日适用版本 |
| A-44 | 每日动作独立编辑与保存 | 周/日编辑同一草案，可新增删除动作并独立修改各日字段；保存再进入、审查确认后各日明细完整保留；训练/休息切换不覆盖其他日或历史基准 |
| A-45 | 动作字段校验与重新审查 | 空动作名、非法组数/数量/单位/休息或力量日无动作阻止有效保存/确认；修改任一动作字段或增删动作使旧审查及处理状态失效，修正并重审最新版本才可发布 |

## 17. 首版效果评估

先验证自用体验，再扩大内测。首次试用建议覆盖至少两个完整周，以观察一次完整的周复盘与下周调整；这属于试用安排建议，不代表健康效果验证。

| 要验证的问题 | 观察方式 |
| --- | --- |
| 能否获得可执行计划 | 首次草案到确认的成功率；用户修改原因；时间和器材冲突数量 |
| 是否愿意持续记录 | 有效记录天数；各维度缺失情况；常规记录耗时 |
| 复盘是否改变行动 | 人工纠正频次；调整采纳原因；次日能否执行被采纳的安排 |
| 是否形成周闭环 | 完成周复盘并确认下周计划的比例；退出或卡住的环节 |
| AI 是否可靠 | 无依据判断、伪造记录、过期覆盖、风险建议及失败恢复情况 |
| 拍照记录是否有帮助 | 食物与份量纠正率、识别到确认耗时、分菜品热量估算误差、失败后能否继续登记 |
| 饮食目标是否可对照 | 目标与餐次一致性、摄入汇总正确性、漏记/未知项是否影响复盘判断 |
| 是否适合长期使用 | 用户对计划难度、记录负担和建议帮助程度的反馈 |

初期不预设未经验证的减重承诺、留存率或转化率。根据内测建立基线，再制定迭代目标。
