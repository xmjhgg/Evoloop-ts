## 2. 各类文档的职责

| 文档 | 唯一维护内容 | 与其他文档的关系 |
| --- | --- | --- |
| 产品规划 | 定位、版本范围、功能优先级、产品级验收 | 保留现有 F-*、A-* 编号；详细需求引用它 |
| 角色正文 | 角色目标、责任、权限、主要流程 | 关联 BF，不复制全部功能用例 |
| 业务流程正文 | 从触发到业务结果的全过程及分工 | 每一步关联 UC，跨模块可引用通用用例 |
| 功能用例正文 | 一项可观察的用户目标如何完成、输入输出、分支和验收 | 一个用例一份正文，被多个流程复用 |
| 公共规则 | 跨用例共同使用的规则与口径 | 用例引用 BR；只写本用例特有补充 |
| 清单与追溯矩阵 | 编号、名称、关系、文档状态和正文链接 | 不复制详细流程；没有正文明确标“待建立” |
| 迭代与变更记录 | 本轮范围、变化原因、受影响项及处理结果 | 记录变化，当前正文保存完整有效需求 |
| 基线快照 | 某次确认范围的不可变需求集合 | 后续修改当前正文，不回写旧快照 |

文件按模块和业务主题归档，角色与流程通过清单关联。同一角色可跨模块，同一用例可出现在多个流程中，避免为每个角色复制相同用例。

## 3. 编号规则

| 类型 | 格式 | 示例 |
| --- | --- | --- |
| 业务角色 | ROLE-三位序号 | ROLE-001 |
| 协作参与方 | PART-三位序号 | PART-001（AI 协作能力） |
| 业务流程 | BF-模块-三位序号 | BF-FIT-003 |
| 功能用例 | UC-模块-三位序号 | UC-FIT-012 |
| 公共规则 | BR-模块-三位序号 | BR-FIT-004 |
| 用例验收条目 | 用例编号-AC-两位序号 | UC-FIT-012-AC-01 |
| 需求变更 | CHG-日期-三位序号 | CHG-20261010-001 |

模块编码：COM 为通用，FIT 为健身，LRN 为学习（本轮首次登记）。工作/个人财务在首次建立正文时登记新模块编码。

编号分配后不因名称、目录、排序或版本变化而更换，也不回收停用编号。新增用例使用下一个可用编号；拆分用例保留原编号的历史及替代关系。F-* 和 A-* 继续表示产品规划层的功能与验收，不能重编号成 UC 或 AC。

## 4. 文件与状态

正文文件名为“编号_业务名称.md”；全项目只维护一份角色清单、一份流程清单和一份用例清单。相对链接用于项目内导航，模板占位项在正文中须替换或明确标记“不适用/待决策”。

文档状态统一为：待编写、草稿、待评审、已评审、已废止。验收、开发状态在迭代中单独记录；本轮正文全部是草稿。

角色、流程、用例和变更正文必有稳定编号、版本、状态、日期、来源、责任人和变更记录。规范、清单及需求导航以文件名称识别，保留版本、日期、来源和变更记录；项目 README 只承担导航。需求负责人可以先标为“待指定”，不能虚构已经评审或通过验收。
