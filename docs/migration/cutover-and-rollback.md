# 按账户迁移、切换与回退

## 1. 迁移前提

独立新目录、Java 账号/同步容器库、测试库、端口与灰度入口；不与旧 Java 共用业务表写入。冻结本地结构、命令、载荷与备份版本矩阵，完成客户端业务等价、故障恢复、真实存储及必要设备验收后，才进入数据迁移。

## 2. 顺序与证据

1. 清点账户/身份映射、全部旧表和增量、历史修订/基准/确认/来源、图片、设备未同步意图与批次、在途 AI/权利请求；建立加密备份、字段与附件摘要。
2. 对目标账户阻断旧业务写入及在途任务，固定一致导出截至点；其他账户继续旧路径。不能新旧写入并行后自动拼接。
3. 在客户端临时库转换/导入，保留稳定 ID、字段精度、历史指针、原基准、组件与确认范围。生成缺失/拒绝清单，无法证明等价则停止。
4. 旧设备待同步数据经旧兼容通道或显式转换器保留原事务/意图导入；不能丢弃队列，也不能默认将旧 JS 方法名作为新命令版本。
5. 新 Java identity 按明确映射迁移账户/哈希，旧会话兼容经验证或要求重新登录；不按同名用户合并。新云端只初始化账号/AI/同步容器。
6. 经客户端验证的完整快照建立唯一新同步根，记录旧来源摘要、截止点、payload 版本、附件范围和 baseSequence；未同步操作另存，不能冒充同步基线。
7. 临时库核对后原子切换，验证离线保存、重启、同步与新设备下载恢复，之后该账户旧入口只读/升级提示。灰度不覆盖原站其他用户。

每阶段记录：源/目标数量与规范摘要、拒绝/缺失项、引用闭包、历史基准与确认抽样、队列依赖、附件清单、代表性查询、版本/设备、操作者与回退点。字段/历史/队列任一不通过均不得切库。

## 3. 回退条件

无新写入时可恢复旧截至状态。有新本地/云端同步写入后，先保全全部分支和未同步意图，使用经过验证的客户端导出/旧导入流程回退，或在新工程向前恢复；禁止旧快照覆盖切换后数据。

回退演练必须包含丢回执、断写、部分历史、旧版本客户端、错误密码与照片恢复。旧 `/evoloop/` 的访问保护、base path、资源、SPA fallback、原接口与新灰度入口隔离需另有外部验证。本轮不修改服务器或原站配置。
