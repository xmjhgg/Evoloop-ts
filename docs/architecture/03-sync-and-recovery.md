# 数据批次同步、冲突与恢复

目标协议设计，尚未生成 Schema、OpenAPI 或 Java DTO；[契约分工](../engineering/contracts-and-versions.md)。

## 1. 信封与账户版本

| 对象 | 必备字段/含义 |
| --- | --- |
| SyncBatch | protocolVersion、batchId、deviceId、expectedHeadVersion、payloadSchemaVersion、changes、payloadDigest |
| Change | 受控逻辑表、主键、before/after 或显式 tombstone，不含 SQL/可执行代码 |
| SyncReceipt | batchId、inputDigest、STORED/CONFLICT/REJECTED、serverSequence 或 currentHeadVersion、错误码 |
| PullEnvelope | 连续 serverSequence、batchId、规范不可变载荷、摘要、结构版本 |
| SnapshotManifest | snapshotId、baseSequence、payloadSchemaVersion、分块摘要、账户、数据/附件范围、完整状态 |
| CapabilityManifest | 支持的身份/AI/同步协议、payload 版本及大小/分块约束；不公布服务器业务引擎版本 |

headVersion 是账户级递增版本，每个成功批次加 1，等于 serverSequence。即使不同业务对象也可能冲突，这是首期的明确取舍。BIGINT/序号用规范十进制字符串；payloadDigest 的规范化规则必须由跨 TS/Java 黄金样本证明，不能依赖对象字段遍历或各语言默认 JSON 序列化。

## 2. Java 保存事务

认证/访问资格 → 输入大小/结构/归属/摘要检查 → 锁账户同步头 → 查询 `(accountId,batchId)` 幂等记录 → 比较 expectedHeadVersion → 保存完整载荷/回执/新 headVersion → 提交。相同批次与摘要返回原结果，不再增加版本；同编号不同输入拒绝。冲突/拒绝不推进 head；记录幂等终态后重试仍返回该批次结果，重新对账使用新 batchId。

账户由会话确定；载荷里的 user_id 必须与其一致，不能据客户端指定账号路由。允许表名、字段、主键形状、精度、所有者和版本是协议约束。服务器不查询业务图、不重算营养、不核验确认资格、不做领域引用闭包或命令执行。

## 3. 客户端队列与对账

每设备同账户串行上传，一次仅一个未决批次。批次定版后编号、版本、规范字节和摘要不变；丢回执重传原批次。commandId 与 batchId 独立，允许重放后生成新批次并关联原意图。

先保存云端基线和原本地分支，在临时视图按连续 sequence 拉取/验摘要/导入，再按本地依赖顺序用共享核心重放待处理意图。无语义冲突才基于新 headVersion 建新批次；来源、版本或确认失效时停止自动重放，显示差异和“采用云端 / 编辑后重提 / 显式重新应用”。发布和确认不能在重放中悄悄重新授予。

ACK 只证明该批次已存，不能清空全部队列。ACK 与拉取乱序、自己的回流按 batchId 核对，保留原批次直至连续版本覆盖且依赖完整。序号缺口、摘要失败、缺引用或不支持的载荷停止发布新视图，保留当前库/队列/证据，补齐快照/增量后再切换。

导入器在客户端验证结构、唯一键、引用闭包、修订与业务不变量。无效云端载荷返回可恢复错误，不传播为正确事实。已知永久格式拒绝、会话过期、升级要求、访问资格改变不无限自动重试；仅瞬时网络错误退避。

## 4. 快照、附件与恢复

快照临时上传 → 校验每块摘要与完整清单 → 当前 baseSequence 核对 → 原子发布完整标记。未完成快照不可用于恢复。增量基线只由已追平且无待同步操作的客户端生成，服务器不以领域引擎证明快照正确。账户唯一初始同步根只能建立一次，不能上传新根绕过版本竞争。

云端保留可恢复的完整基线及其后增量，具体保留/配额策略待批准。基础设施备份不是业务备份模块。附件缺失要明示，“结构化数据已同步”不等于照片已备份。

本地加密备份含业务、基线、意图、队列、冲突分支、版本与附件清单；恢复先保全现有未同步内容。旧库/命令/载荷/备份在临时库转换，核验后原子切换，失败不删原库。备份含未同步操作时不能充当云端已同步基线。

小程序近 90 天是默认保留目标，还须保留当前/未来安排、全部未同步数据及引用闭包。清理已同步历史前证明可恢复且不是唯一副本；空间不足停止新写并提供处理入口。iOS 保存完整结构化历史，H5 配额/驱逐按适配与恢复测试处理。
