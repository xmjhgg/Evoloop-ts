# 草案审查与计划发布

1. planning 基于当前目标/条件建立或编辑同周唯一工作草案，生成不可变逐日项目修订及完整 manifest。
2. 本地核验结构、数据充分性、时段/共享基准冲突、保护与批准限制；规则覆盖不足返回明确缺失，不把“无报错”当可发布。
3. 若用户选 AI 渠道，客户端冻结最小输入、完整动作/来源/规则/授权/保护指纹，提交本地关联，再向 Java ai 请求。服务端不从同步表重建计划。
4. AI 返回后本地短事务重新核验草案/来源，匹配才接纳审查候选。用户采纳意见改变内容则新草案重新审查；旧审查不继续授权。
5. 用户明确选择未来可调整项目与版本，planning 在同事务最终核验最新来源/保护/规则与审查，再发布选定项目。未选项目与已开始/已有实际保持原修订。

AI 失败不自动切换渠道通过；显式 RULES 重审仍保留禁止项与批准策略约束。未批准健身政策/参数无法由手动勾选绕过。成功本地提交后才生成同步变化，Java sync 只保存容器。

验证：编辑任一动作使旧审查失效；首次摄入冻结当日总量；睡眠真实开始保护跨周；发布/事实竞争只能出现符合保护的完整结果；重放发布失效必须重新展示并确认。
