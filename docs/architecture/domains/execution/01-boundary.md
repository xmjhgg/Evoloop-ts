# execution：边界与统一语言

在客户端唯一保存训练、睡眠、学习与个人摄入事实及修正历史，拥有食物分析草案、照片业务关联、个人份量与营养来源/换算。不保存第二份条件、计划或结论；身体测量/日状态归 profile，训练后感受归本域。

有计划的事实通过 planning 公开能力取得当时适用处方并保护原基准；无计划可自主记录，baseline 为明确无，不虚构目标。review 按公开事实快照、覆盖与范围 token 读取。workspace 多目标引用同事实，总览按 factId 去重。

食物识别、AI 候选、手工草案与已确认个人摄入分开。接纳候选不入账，个人份量核对与确认后才成为 MealRecord。营养来源端口在客户端声明；首期不新建 Java 营养来源服务，未接入来源如实不可用，手工输入仍可用。
