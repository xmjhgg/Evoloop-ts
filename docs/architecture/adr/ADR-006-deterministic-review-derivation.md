# ADR-006 确定性复盘派生与版本

日期：2026-10-20。状态：代码和本地测试已实现；数据库端到端、原生设备及性能另验。

事实保存与日结论显示之间原先只有来源失效，没有自动摘要。当前由 review 的公开 deriveReviews 用例消费本地事务已经递增的来源 key。local-runtime 只记录这些 key 并调用用例，不实现训练、营养或复盘计算。

先失效旧来源，再生成/替换受影响的日组件，随后失效并刷新已有依赖周组件。摘要是纯确定性计算，不请求网络或 AI；事实、原基准、token、日周新组件、旧确认失效、原意图和变化批次一起可靠提交。提交失败全部回滚；幂等重试不重复派生。不存在“事实已提交但派生请求只留在内存”的窗口。

替换组件不修改人工条目，不把旧人工最终判断或 AI 判断重新授予确认。未涉及的组件继续复用，例如学习变化保留健康范围确认。日/周新确认、AI 接纳、调整合并和计划发布仍是各自的显式操作。

当前指标版本为 review-metrics-v2，写入冻结输入并参与摘要。来源验证同时检查数据 refs/token 和指标版本；旧统计输入可以保留和查看，不能被当作新版的最新有效确认，也不能接纳旧 AI 返回。组件冻结输入必须通过自身摘要校验。

训练/学习按计划结束时点计入应登记；没有时段的当前日项目不提前认定漏记，过日再计入。已经明确登记的实际保留。睡眠按起床日和完成状态，不把进行中睡眠作为完整时长。周指标分日显示餐次覆盖，不将跨日三餐的并集合称全周完整摄入；个人共享事实总览去重，同单位身体变化仅是描述。

本次选择同事务即时派生，未增加独立后台队列。新事实通常涉及旧/新日期和它们的既有周；旧统计格式或公共条件变化可能涉及更多已有组件。大历史、设备 P95、容量和运行时间尚未压测，不能凭本地测试宣称达到设备指标。若后续拆为异步派生，必须先持久化请求并提供幂等恢复，来源和确认校验不得依赖调度是否及时完成。

同步拉取或恢复不会静默改写原队列/分支；来源读取门禁立即生效，必要摘要由显式刷新或后续本地命令生成。全新的手机页面接线、真实供应商、iOS 签名和真机不在本决策的验证证据内。
