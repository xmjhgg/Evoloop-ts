# ADR-004：首版本地聚合文档和原子状态封装

状态：2026-10-17 实现基线；适用于当前本地核心/云服务，不批准旧库切换。

旧工程 95 张关系业务表仍是迁移阅读基线。新核心通过各领域的公开能力和有类型实体访问仓储，不复制旧 Java 的行操作 Service。当前 `documents-v1` 使用 12 个受控逻辑集合：profile 条件/观测，planning 目标/周/保护/AI 候选，execution 事实/食物草案，review 文档/调整，以及来源 token 和不可变历史。

每行固定为 accountId、id、version、revisionId、data；data 是规范 JSON 字符串，领域内部仍有独立运行时 Schema、规则和类型。修改实体时将完整旧内容追加到 system.revision；业务 ID 稳定，原基准保存完整不可变处方。复制边界仅导出外层形状、集合白名单和版本，不向 Java 发布业务判断。

SQLite 当前将一个账户的完整一致状态封装在 local_state 行，使用同连接事务、代际比较和强持久化；IndexedDB 使用共同对象存储的一次严格 readwrite 事务；文件日志先写不可变段，再原子切换提交标记。状态包含业务、历史、token、命令成功结果、原意图及变化登记；网络批次在上传前定版并可靠保存。新事实不等待网络。

选择完整状态封装以先验证跨存储一致性、故障原子性和冲突保全。它会增加序列化、复制、历史和存储成本；不据此宣称大历史量性能或 P95 目标达成。后续可在同一仓储端口下引入分行 SQLite/增量日志，但必须提供状态格式升级、旧队列、失败恢复和跨适配等价证据，禁止直接重置本地库。

首版快照客户端目前发布一个受限分块；过大时明确失败。服务器支持受限多块清单，客户端尚不支持多块恢复。保留全部历史，不做未经恢复证明的自动裁剪。旧 rows-v1、旧方法名队列和旧备份只做拒绝/保全测试，尚无 95 表生产转换器；它们不能作为本版本的直接输入。

同步无领域语义拒绝。格式/摘要/所有者等协议前置检查失败返回 HTTP 错误，不建立回执；形状合法、版本竞争产生的 CONFLICT 回执永久绑定原批次。STORED 仅证明存储。客户端对未知版本停止导入，对引用/日期/单位/原基准错误拒绝发布新视图。

为了不让学习保护误使健康组件失效，通用 PLAN_DAY 之外增加按种类的 PLAN_DAY:date:kind token；草案编辑不递增这些 token。日/周根与人工 token 继续分离。

条件当前按分区核对 expectedVersion，跨分区依赖由来源 refs/tokens 捕获，不使用旧关系模型的全 profile 根行。日结论还增加 DAILY:date:slot 版本，让周组件只依赖相关日组件。全局 token 仍用于概览。规划和复盘冻结输入同时保留对象修订引用及集合 token。

批次按完整本地命令分组，受 2000 条变化/8 MiB 限额约束；单个命令超限明确停止同步且保留本地意图。无数据变化的成功操作保存 LOCAL_ONLY 本地回执，不制造空批次。快照能力握手返回当前完整基线位置，新设备先恢复该基线；已有本地待处理内容则保存分支并进入显式对账。
