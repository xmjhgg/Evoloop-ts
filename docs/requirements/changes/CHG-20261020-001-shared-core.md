## 2. 没有被本次编码替代的产品决策

“待批准”是产品规则尚未确认，不是额外的代码授权，也不指外部机构审批。来源仍为 requirements/README.md 第 4 节与 UC-FIT-007 的 TBD-001。

- 个性化营养：选用什么计算方法、适用人群、必需参数、系数、精度/容差、参数证据与方法版本。本次只实现标签单位换算和手工分配算术，不用经验系数生成个人目标。
- 健身限制：哪些具体证据和内容对应允许、提示、信息不足或阻断，手工计划与自动建议分别覆盖什么规则。当前发布阻断保留，不把“手工输入结构合法”当作健康规则已经覆盖。
- 宏量与热量的“明显矛盾”容差没有确认，本次不自行写入经验阈值。真实 AI 与照片识别质量也不由本地单元测试替代。

这些决策与当前计算版本、实际接入和真机验收分开记录。本次不宣称全部 44 UC/140 AC 或全部原字段已经完成。

## 3. 交付与追溯

新增命令为 execution.food-draft.save-label、review.adjustment.dismiss；实际摄入/事实命令增加可选 baselineMode=AUTO/SELECTED/UNPLANNED。旧命令不含新字段仍可解析；与新语义不一致的重放继续停止并保留分支，不静默升级预期版本。

营养 provenance 和餐次分配为业务文档的可选扩展；复制外层不变，Java 不加载或执行这些业务。统计快照使用 review-metrics-v2；旧快照保留，但不能继续授权新版确认或 AI 接纳。
