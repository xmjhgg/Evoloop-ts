## 2. 本轮范围取舍

| 能力 | 新工程要求 | 追溯与限制 |
| --- | --- | --- |
| 目标、草案、审查、发布、事实、日周结论与调整 | 全部本地执行；iOS/微信/H5 共用 TS 核心 | 原 UC/BR/AC 的业务语义保留，网络前提改为初始化后离线可用 |
| 注册登录 | 首期用户名/密码注册和登录；当前不迁移旧微信身份 | 新增项目专用 UC-NEXT-001/002；不改旧 UC-COM-001 的身份 |
| 用途说明与授权 | 本地按数据用途限制，AI/同步执行必要服务端访问检查 | UC-COM-002 保留必要部分；完整跨处理者授权编排暂缓，不能宣称原全部 AC 已满足 |
| 数据导出 | 本地密码加密备份与选定导出；含队列和附件范围 | UC-COM-003 执行位置改变；跨云端/处理者总包编排暂缓 |
| 删除指定数据 | 领域内删除/来源失效保持；完整跨副本权利请求流程暂缓 | UC-COM-004 的全链路清理 AC 未交付；同步 tombstone 不等于历史批次/快照/外部副本已清除 |
| 注销账户 | 首期仅必要账户停用、会话撤销、同步访问限制及明确清理范围 | UC-COM-005 的完整注销/外部清理流程暂缓；停用不显示为已彻底注销 |
| AI | 在线请求，客户端冻结输入并接纳候选；失败保留事实和草案 | 无 AI 时手工闭环仍可用；不能自动切换 mock 或自动发布 |
| 同步与恢复 | 新增数据批次、快照、客户端冲突、升级、备份恢复 | 新增项目专用 UC-NEXT-003/004/005，不视为健康设备自动同步 |

## 3. 新增用例与验收定义

UC-NEXT 编号只用于本次架构增量，不占用旧 UC-COM/FIT/LRN。账号、数据批次、冲突及备份已具备核心实现；设备交互、旧版本转换及完整 AC 验收状态按实现映射单独记录。

| 用例 | 用户目标 | 验收标准 |
| --- | --- | --- |
| UC-NEXT-001 用户名密码注册 | 建立可登录账户 | AC-01 规范用户名唯一，重复/并发提交只产生一个账户；AC-02 失败不留可登录半账户且无业务数据；AC-03 返回安全错误，密码/哈希不泄露 |
| UC-NEXT-002 密码登录与账户切换 | 恢复当前账户并隔离设备数据 | AC-01 有效会话且可撤销；AC-02 切换停止旧同步并隔离库/附件，旧未同步记录保留；AC-03 会话过期保留本地已保存内容，上传/AI 显示需登录 |
| UC-NEXT-003 同步本地数据 | 将可靠保存的数据异步传到云端 | AC-01 离线可靠提交先成功；AC-02 丢回执重传只推进一次 head；AC-03 跨账号/同编号不同摘要拒绝；AC-04 连续拉取、自己的回流、断写/缺口不丢队列 |
| UC-NEXT-004 处理多设备冲突 | 对账后选择如何保留操作 | AC-01 保留原分支/意图；AC-02 新基线重放不静默升级预期版本；AC-03 发布/确认失效重新展示差异；AC-04 冲突重提新 batchId，原批次保留记录 |
| UC-NEXT-005 当前版本加密备份与恢复 | 导出/恢复当前版本完整设备状态 | AC-01 含业务/基线/队列/分支/版本及附件；AC-02 错误密码/损坏/空间失败不覆盖现库；AC-03 当前格式恢复和重启可用，旧格式明确拒绝；AC-04 未同步内容不冒充同步基线 |

## 4. 待批准事项

健身政策/计算参数、营养来源、模型及照片评测、数据保留/清理期限沿用原待决状态。协议版本、同步限额、设备解锁和新账户同步根的当前实现见版本矩阵与 ADR-005。不得填入假定阈值或用本地开关替代批准。
